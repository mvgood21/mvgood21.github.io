애드센스 가치가 별로 없는 콘텐츠·복제 거절 대응

애드센스 '가치가 별로 없는 콘텐츠' 거절은 사이트 전체를 본 판정이었습니다. 우리 사이트에서 걸린 것은 베낀 문장보다 거의 검색되지 않는 글 101편이었습니다.

작성 Stephen · 웹사이트와 검색 · 읽는 시간 13분 · 최종 업데이트 2026년 11월 28일

11월 13일, 애드센스가 이 사이트를 "주의 필요"로 돌려보냈습니다. 사유는 "가치가 별로 없는 콘텐츠"와 "복제된 콘텐츠가 있는 화면에 Google 게재 광고" 두 개였습니다. 남의 글을 옮겨 온 적은 없었습니다. 거절 당일의 사이트를 다시 재 보니 노트 84편 중 71편은 다른 노트와 겹치는 5단어 묶음이 5% 아래였고, 같은 틀로 낸 노트 101편 중 10월 31일~11월 25일에 검색 노출을 10회 이상 받은 글은 8편뿐이었습니다.

이 글은 진행 중 기록입니다. 11월 28일 현재 검토 요청은 다시 넣지 않았고 승인도 받지 않았습니다. 검토 요청을 누를 조건과 다시 잴 날짜(12월 6일)는 뒤에 적었습니다.

거절 사유가 가리키는 정책 두 줄

두 사유는 Google 게시자 정책의 "인벤토리 가치" 항목에서 나왔습니다. 하나는 게시자 콘텐츠가 없거나 가치가 별로 없는 콘텐츠를 사용한 화면이고, 다른 하나는 논평이나 선별, 그 밖의 부가 가치 없이 다른 곳의 콘텐츠를 삽입하거나 복사한 복제된 콘텐츠입니다. 복제 정책의 예시에는 남의 글을 옮기거나 살짝 고친 것 말고도 "직접 검토 및 재구성 없이 자동 생성된 콘텐츠"가 들어 있습니다.

복제는 사이트 밖만 따지지 않습니다. 애드센스 콘텐츠와 사용자 경험 안내는 같은 내용이 사이트의 여러 페이지에 되풀이되지 않는지도 확인하라고 하고, 비슷한 주제의 다른 사이트와 비교해 실질적인 가치와 독창성이 있는지 물으라고 합니다. 몇 편을 더 써야 하는지, 글자 수나 비율 같은 기준은 공개돼 있지 않습니다. 아래 표의 "리뷰어가 보는 것"은 이 문서들과 우리 기록으로 읽은 것이지, Google이 밝힌 심사 절차가 아닙니다.

우리 기록: 5주 동안 101편

이 사이트는 Android 앱 소개와, 그 앱을 AI 코딩 에이전트와 만들며 남긴 개발 노트(AX 노트)로 되어 있습니다. 노트는 10월 18일부터 거의 매일 나갔고, 10월 하순부터는 대부분 AI 에이전트가 예약 작업으로 썼습니다. 11월 8일까지 발행한 날은 모두 정확히 3편이었습니다(git 기록). 애드센스는 github.io 주소로는 진행할 수 없어서 10월 31일 sugarmount21.com으로 옮겨 신청했습니다.

거절과 검색 하락이 같은 주에 왔습니다. 색인된 URL은 11월 20일 284쪽 중 235쪽에서 11월 28일 178쪽 중 14쪽(7.9%)이 됐습니다. 분모가 300에서 178로 준 것은 11월 24일 noindex로 사이트맵에서 뺀 쪽 때문이고, 색인은 그 전인 11월 22~23일에 이미 219쪽에서 119쪽으로 떨어져 있었습니다. 애드센스 심사와 검색 순위는 다른 시스템이라 같은 판정이라고 증명할 수는 없고, 같은 주에 같은 방향으로 판단했다는 것까지만 말할 수 있습니다.

베낀 문장은 없었고, 찾는 사람이 없었습니다

처음 가설은 반복 문구였습니다. 모든 쪽에 같은 메뉴, 푸터, 문의 상자, AI 초안 고지가 붙어 있으니 그게 복제로 보였을 수 있다고 생각했습니다. 거절 당일 저녁의 사이트(커밋 91d1ad1)를 꺼내 쪽마다 보이는 글자를 블록으로 자르고, 한국어 159쪽 중 3쪽 이상에 똑같이 나오는 블록의 비율을 쟀습니다.

노트의 반복분은 대부분 메뉴, 푸터, 관련 글 목록이었습니다. 노트 84편 전체로 넓혀도 다른 노트와 겹치는 5단어 묶음이 5%를 넘은 것은 13편이었고, 그중 11편이 같은 연재끼리였습니다(최대 9.7%). 베낀 것과 다름없는 쪽은 개인정보처리방침이었습니다. 이미지 앱 세 개의 방침은 앱 이름 정도만 달라서 글자의 90% 이상이 다른 방침과 같았습니다.

노트가 짧다는 두 번째 가설도 틀렸습니다. 노트 84편의 고유 글자(다른 쪽에 반복되지 않는 글자) 중앙값은 7,145자였고 1,500자 아래인 노트는 없었습니다. 고유 글자가 1,500자 아래이거나 절반 이상이 반복인 쪽은 159쪽 중 38쪽이었는데, 노트는 한 편도 없었고 대부분 연재 목록(13쪽, 고유 글자 중앙값 313자)과 주제·쪽 번호 목록이었습니다.

Search Console API로 10월 31일~11월 25일 노트별 웹 노출(한국어·영어 쪽 합산)을 모으자 다른 문제가 보였습니다.

101편이 합해 289회 노출된 기간에 앱 소개 쪽은 624회였습니다. 사람들은 "증명사진 용량 줄이기", "갤럭시 PNG JPG 변환" 같은 사진 문제로 들어왔는데, 사이트의 대부분은 에이전트로 앱을 만든 작업기였습니다. 거슬러 올라가면 자동 발행이 하루 3편을 채우려고 검색 수요를 확인하지 않고 주제를 골랐고, 모든 글이 표지 하나와 글자 카드 그림 두 개의 같은 틀이었습니다. 에이전트는 정해진 편수를 채웠고, 검색 수요를 확인하는 단계는 11월 24일 전까지 발행 절차에 없었습니다.

글을 더 쓰는 것은 답이 아니었습니다

거절 뒤 흔한 조언은 좋은 글을 몇 편 더 쓰고 다시 신청하라는 것입니다. 같은 사유로 거절된 한 사람은 3~5편을 더 쓰고 재신청하라는 안내를 받았다고 적었고, 프로그램 강좌 20편이 안 되는 블로그로 승인받았다는 후기도 있습니다. 둘 다 개인 경험담이지만, 편수보다 주제가 모였는지를 본다는 쪽이 우리 기록과 맞습니다.

우리는 속도만 줄이고 계속 냈습니다. 11월 14일부터 23일까지 17편을 더 냈지만 색인과 노출은 돌아오지 않았습니다. 코어 업데이트와 겹쳐 새 글의 영향만 따로 가를 수는 없습니다. 다만 Google 검색 센터의 유용한 콘텐츠 자가 점검 질문에는 검색에서 잘될지도 모른다는 기대로 여러 주제의 콘텐츠를 많이 만들고 있는지, 광범위한 자동화로 만들고 있는지를 묻는 항목이 있고, 스팸 정책은 대량 생성 콘텐츠 남용이 어떻게 만들었든 적용된다고 적고 있습니다. 그 질문에 우리 사이트는 둘 다 "예"였습니다. 사유가 "가치 없음"이면 검색어를 확인하지 않은 글은 더 내지 않습니다.

버린 방법은 둘입니다. 노트 삭제는 Google 코어 업데이트 안내가 고칠 수 없을 때의 마지막 수단으로 두고 있어 고르지 않았습니다. 11월 22일에 세운 노출 0회 노트 일괄 noindex 안은, 그때 노출 0회였던 30편 중 27편이 11월 10일 이후 글이라 수요가 없는 건지 집계가 덜 된 건지 가를 수 없어 취소했습니다.

이 글과 비슷한 문제를 겪고 있다면 메일로 상황을 알려 주세요. 읽고 답하겠습니다. 메일로 문의하기

11월 24~28일에 바꾼 것

Google이 색인을 유지했거나 실제 검색어가 들어온 노트 35편만 색인 대상으로 남기고, 66편은 지우지 않고 noindex(검색에 올리지 말라는 표시)로 돌렸습니다. 링크는 그대로라 쪽은 계속 열립니다. AX 노트 첫 화면은 최신 글 목록 대신 앱을 만들며 막힌 문제 다섯 묶음으로 시작합니다.

광고 코드도 같은 기준으로 좁혔습니다. 광고 설정을 검토용(data/ads.json의 mode "review")으로 두면, 빌드는 색인 대상이고 본문이 한국어 1,500자(영어 쪽은 600단어) 이상인 노트의 머리에만 애드센스 로더 태그(광고를 불러오는 스크립트)를 넣고 광고 단위는 넣지 않습니다. 목록, 앱 소개, 방침 쪽에는 없습니다. 로더가 붙은 쪽은 201쪽에서 70쪽(35편의 한국어·영어 쪽)이 됐습니다.

사람들이 찾는 쪽에는 도구를 붙였습니다. 11월 24~25일 증명사진 용량, PNG를 JPG로, 사진 100KB 이하, 셀카 좌우 반전 안내에 파일을 서버로 보내지 않고 브라우저에서 처리하는 도구를 붙였고, 11월 28일 HEIC를 JPG로 바꾸는 도구까지 다섯 곳이 됐습니다. 가장 많이 노출된 쪽은 갤럭시에서 증명사진 용량 줄이는 법으로 10월 31일부터 151회였습니다. 발행은 12월 6일까지 0편, 그 뒤 주 2편이 상한입니다.

11월 28일에는 연재 목록 13쪽도 noindex로 돌렸습니다. 그중 11쪽은 고유 글자가 1,500자 아래였습니다.

내 사이트를 재는 순서

검토 요청 전에 네 가지를 숫자로 적어 두면 고친 뒤와 비교할 수 있습니다. 사이트 밖 복제는 표의 셋째 줄처럼 문장 검색으로 따로 봅니다.

  1. 색인 비율: Search Console에서 색인 생성 > 페이지를 열고, 그래프 위 목록에서 "제출된 모든 페이지"를 고릅니다. 색인됨 쪽 수를 사이트맵 URL 수로 나눕니다. 우리 숫자(11월 28일 178쪽 중 14쪽)는 URL 검사 API로 사이트맵 URL을 하나씩 잰 값이라 보고서 화면과 하루이틀 어긋나기도 합니다. "크롤링됨 - 현재 색인이 생성되지 않음"은 Google이 읽었지만 색인에 남기지 않은 상태입니다. 도움말은 흔한 상태라고 하지만, 사이트 대부분이 이 상태라면 우리는 애드센스와 같은 방향의 신호로 봅니다. 이 상태의 쪽을 하나씩 확인하는 순서는 크롤링됨 - 현재 색인이 생성되지 않음 해결 전 확인에 따로 적었습니다.

  2. 노출 받은 쪽 수: 실적 > 검색결과에서 기간을 28일로 두고 페이지 탭을 엽니다. 노출이 1회 이상인 행 수를 사이트맵 URL 수와 비교합니다. 우리는 10월 31일~11월 11일에 121쪽이 노출을 받았고, 11월 12~25일에는 45쪽이었습니다.

  3. 반복 비율과 얇은 쪽: 아래 스크립트를 repeat.py로 저장하고 python repeat.py <빌드 폴더>로 돌립니다. 첫 열은 3쪽 이상에 똑같이 나오는 글자 비율, 둘째 열은 그 쪽에만 있는 글자 수입니다. 비율 50% 초과나 고유 글자 1,500자 미만인 쪽을 셉니다(1,500자는 우리 기준이지 Google 기준이 아닙니다). 위 표는 한국어 쪽만, 본문 기준으로 잰 값이라 이 스크립트 결과와 조금 다릅니다.

    import sys, glob, collections
from html.parser import HTMLParser
class Blocks(HTMLParser):
    def __init__(s): super().__init__(); s.out, s.buf, s.skip = [], [], 0
    def cut(s):
        t = " ".join("".join(s.buf).split()); s.buf = []
        if t: s.out.append(t)
    def handle_starttag(s, tag, a): s.skip += tag in ("script", "style"); s.cut()
    def handle_endtag(s, tag): s.skip -= tag in ("script", "style"); s.cut()
    def handle_data(s, d):
        if not s.skip: s.buf.append(d)
pages = {}
for f in glob.glob(sys.argv[1] + "/**/*.html", recursive=True):
    p = Blocks(); p.feed(open(f, encoding="utf-8").read()); p.cut(); pages[f] = p.out
seen = collections.Counter(b for bl in pages.values() for b in set(bl))
for f, bl in sorted(pages.items()):
    total = sum(map(len, bl)) or 1
    rep = sum(len(b) for b in bl if seen[b] >= 3)
    print(f"{rep / total:4.0%} repeated {total - rep:6} own  {f}")

  4. 발행 속도: 정적 사이트라면 git 기록에서 새 글 파일이 처음 추가된 커밋 날짜를 세고, CMS라면 글 목록을 날짜순으로 봅니다. 하루 편수가 늘 같거나 몇 주 만에 수십 편이 쌓였다면 표의 마지막 줄에 해당합니다.

검토 요청을 아직 누르지 않는 이유

우리가 정한 조건은 넷입니다. 사이트맵 URL 중 색인 비율 70% 이상, 새 도메인의 주간 웹 노출 200회 이상, 수요가 확인된 이미지 쪽 다섯 곳에 도구, 연재 목록 13쪽 정리입니다. 앞의 둘은 거절 전 수준(11월 11~20일 색인 69~83%, 11월 1~7일 노출 486회)보다 낮게 잡은 우리 기준입니다. 도구와 연재 목록은 11월 28일에 끝났습니다. 남은 둘은 같은 날 색인 비율 7.9%, 주간 노출 22회(11월 19~25일)입니다. 넷을 채우기 전에는 누르지 않고, 12월 6일에 같은 방법으로 다시 잽니다.

바꾼 것이 맞았는지 밖에서 확인할 숫자는 색인과 노출뿐인데 둘 다 거절 때보다 낮습니다. 애드센스 사이트 상태 안내는 검토가 보통 며칠이지만 2~4주 걸리기도 하고 사이트를 지웠다 다시 넣으면 더 늦어질 수 있다고 하며, 코어 업데이트 안내는 개선이 반영되는 데 몇 달이 걸릴 수 있다고 합니다. 고친 직후에 누르면 리뷰어는 바뀌는 중인 사이트를 보게 됩니다.

거절 사유가 계정이나 사이트 소유 확인처럼 콘텐츠와 무관하거나, 위 네 가지를 재 보니 문제 쪽이 몇 개뿐이고 이미 고쳤다면 기다릴 이유가 적다고 봅니다.

다시 한다면 바꿀 것과 남은 일

다시 한다면 자기 도메인부터 정하고 신청하겠습니다(github.io로 설정한 10월 23일부터 다시 신청한 10월 31일까지 8일이 지나갔습니다). 편수를 목표로 두지 않고 검색어가 확인된 주제만 쓰고, 개인정보처리방침과 목록 쪽은 처음부터 noindex로 두겠습니다. 도구도 노트보다 먼저 앱 소개 쪽에 붙였어야 했습니다.

남은 일은 12월 6일 측정입니다. 조건을 채우면 검토를 요청하고, 결과는 승인이든 거절이든 이 글에 날짜를 붙여 덧붙입니다.
