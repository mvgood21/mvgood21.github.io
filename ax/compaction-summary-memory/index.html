13일짜리 세션의 자동 압축 9번과, 압축마다 다시 실린 메모리 색인 한 줄

요약 9개에 예산을 정한 이유는 없었고, 10월 17일 착오는 압축마다 다시 실린 메모리 색인의 오래된 "각 2,000원" 줄이 유력한 출처였습니다.

작성 SugarMount · 에이전트와 일하는 법 · 읽는 시간 13분 · 최종 업데이트 2026년 11월 3일

13일 이어진 마케팅 세션에서 자동 압축이 9번 일어났고, 에이전트는 매번 1만 자 정도의 요약 한 장과 최근에 읽은 파일 2~5개, 메모리 색인(MEMORY.md)을 들고 다음 구간을 시작했습니다. 2026년 10월 9일부터 21일까지 게임 두 개의 광고와 홍보를 맡긴 Claude Code 세션입니다. 요약 9개 모두 사용자 메시지 목록은 있었지만, 광고를 runbook 값 대신 2,000원으로 정한 이유는 하나도 없었습니다.

근거는 Claude Code 세션 기록(jsonl) 5개, 메모리 파일 14개와 색인, 광고 runbook과 계획 문서입니다. 숫자는 2026-11-02에 세션 기록에서 다시 세었고, 시각은 한국 시간입니다. 광고 계정·캠페인 식별값은 쓰지 않습니다.

자동 압축 9번

세션 기록에서 "This session is being continued from a previous conversation"으로 시작하는 메시지는 9개였고, 압축 경계 기록(compact_boundary)도 9개였습니다. 9개 모두 trigger가 auto였고, 사용자가 /compact를 친 적은 없습니다. 압축 뒤에 남은 토큰은 압축 전의 2.6%~8.2%였습니다. 10월 17일 하루에만 3번 일어났습니다.

요약 9개에는 모두 "All user messages", "Pending Tasks", "Current Work", "Optional Next Step" 절이 있었습니다. 광고 이야기가 처음 나온 10월 11일 뒤의 요약 8개 중 예산 금액이나 켜짐·꺼짐 상태가 들어간 것은 5개였습니다. "runbook"이라는 단어는 9개 모두에 한 번도 나오지 않았고, 캠페인을 언어별로 나눈 이유도 없었습니다.

요약 말고도 압축 직후에 다시 실린 것이 두 가지 있었습니다. 하나는 최근에 읽은 파일로, 압축마다 2~5개가 붙었습니다. 광고 메모리 본문이 그중에 끼어 있던 것은 3번과 5번 뒤뿐입니다. 다른 하나는 메모리 색인입니다. 색인은 세션 첫 턴과 압축 9번 각각의 다음 사용자 턴에 한 번씩, 모두 10번 instructions로 다시 실렸습니다.

비교하려고 다른 세션 두 개도 세어 봤습니다. 앱 개발 세션과 게임 개발 세션은 둘 다 사용자가 /compact를 직접 5번씩 쳤고, 이어받기도 5번씩이었습니다. 수동 압축 직전 토큰은 253,498~832,659, 요약은 9,317~20,634자였고, 10개 모두 같은 4개 절로 짜여 있었습니다. 10번 모두 /compact 뒤에 지시문을 붙이지 않았습니다.

자기 세션에서 같은 것을 세려면 세션 기록 파일에 아래 세 줄을 돌리면 됩니다. 세션 기록은 ~/.claude/projects/<작업 폴더 이름>/ 아래에 세션마다 jsonl 하나로 있습니다.

grep -c '"subtype":"compact_boundary"' <세션>.jsonl   # 압축 횟수
grep -c '"isCompactSummary":true' <세션>.jsonl        # 이어받은 요약 수
grep -c '"type":"AutoMem"' <세션>.jsonl               # 메모리 색인이 실린 횟수

이 세션에서는 9, 9, 10이 나왔습니다.

25,000원은 압축 없던 세션에서

백로그에 이 글감을 올릴 때 적은 가설은 "요약 뒤 에이전트가 runbook 값으로 돌아가 운영자에게 질책받았다"였습니다. 세션 기록을 보면 그 일은 10월 8일 밤에 있었습니다. 21시 56분에 운영자는 Chrome에서 광고 캠페인을 만드는 세션 두 개를 동시에 열었습니다. 하나는 화살표 매듭풀기, 하나는 한판블록이었고, 두 세션 모두 압축이 0번이었습니다.

  • 21:57 운영자가 화살표 세션에 지시: "일 예산 2,000원, 목표 CPI 없음, 전 세계". 같은 분에 한판블록 세션은 지시문에 적힌 runbook을 읽음
  • 22:07 한판블록 세션의 질문: "tCPI 1,400원과 일 25,000원은 미국 기준 값인데 그대로 넣을까요"
  • 22:11 운영자 답: "심층 분석해서 진행해" (예산 언급 없음)
  • 22:14 에이전트가 일 예산 칸에 25000 입력, 목표 CPI 칸에는 700원(runbook의 1,400원과도 다른 값)
  • 22:22 운영자가 강한 어조로 다시 지시: 일 2,000원, CPI 없음, 모든 국가
  • 22:23 에이전트가 메모리 파일 작성

에이전트가 틀린 지점은 22시 14분입니다. 예산을 물어 놓고 받은 "진행해"를 문서 값 승인으로 읽었습니다. 2,000원 지시는 그보다 17분 전, 21시 57분에 옆 세션으로 들어갔고, 두 세션은 맥락을 나누지 않습니다. 한 단계 더 올라가면 runbook과 광고 계획 문서가 둘 다 25,000원이었습니다. 같은 날 19시 19분 게임 개발 세션이 쓴 계획 문서도 "하루 25,000원 x 14일"이었습니다. 운영자의 새 결정은 어느 파일에도 없었습니다.

같은 날 밤 게임 개발 세션의 마지막 수동 압축(10월 9일 0시 47분) 요약에는 "광고 계획: KR, 하루 25,000원"이 그대로 들어 있었습니다. 한판블록 세션에서 2,000원으로 정정된 22시 22분보다 2시간 25분 뒤였습니다.

10월 17일 "집행 중"

10월 17일 오전 8시 8분, 마케팅 세션의 에이전트는 광고 콘솔에서 한판블록 KR이 4,000원/일, 화살표 KR이 2,000원/일로 돌고 영어 캠페인 두 개는 일시중지인 것을 읽었습니다.

9시 12분에 에이전트는 바로 그 광고 메모리 파일을 고쳤는데, 계정 연결 메모만 더했습니다. 10월 11일에 적은 "광고그룹 4개 모두 11/02까지 운영" 줄은 그대로 남았습니다. 그 파일에서 맞았던 것은 "runbook 값은 쓰지 않는다"는 결정이고, 예산(각 2,000원)과 운영 상태는 그날 아침 콘솔과 달랐습니다. 10시 7분 압축 3번 요약에는 "게임 캠페인 4개 모두 일시중지(운영자 또는 다른 세션)"가 들어갔고, 17시 49분 압축 4번 요약에는 광고 상태 줄이 아예 없었습니다.

압축 4번 직후 다시 붙은 파일 5개에도 광고 메모리 본문은 없었습니다. 19시 24분, 다음 사용자 턴에 메모리 색인이 다시 실렸고, 거기 광고 줄 두 개는 "영어(동남아)/한국어 캠페인 2개, 각 일 2,000원, tCPI 없음 (runbook보다 우선)"과 "언어별 캠페인 2개(KR/SEA EN), 각 2,000원, tCPI 없음"이었습니다. 이 색인은 세션 시작 때부터 같은 문구였습니다.

14분 뒤인 19시 38분, 에이전트는 게시 기록과 백로그에 화살표 KR을 "집행 중인 캠페인 소재 교체"라고 적었고, 20시 31분 운영자에게 "화살표 KR 광고 소재 v2를 지금 집행 중인 KR 캠페인에 넣을까요"라고 물어 승인을 받았습니다. 집행 중이라는 말이 세 곳에 남았습니다. 소재를 넣으려고 캠페인을 열고 나서야 20시 39분에 "집행 중이라고 한 건 착오였고 원래 일시중지"라고 보고했고, 같은 보고에서 한판블록 KR이 하루 4,000원으로 도는데 자기 메모에는 2,000원으로 적혀 있다고 알렸습니다. 21시 8분 운영자가 지금 도는 것은 한판블록 KR 4,000원 하나뿐이고 화살표는 꺼져 있다고 바로잡았습니다. 에이전트는 "제 메모에 아직 각 2,000원으로 남아 있던 것"을 고쳤다고 답했고, 실제로 세 곳을 고쳤습니다. 한판블록 메모리 파일, 화살표 메모리 파일, 그리고 색인의 광고 줄 두 개입니다.

2026-10-17 현재 운영 상태(사용자 확인): 4개 캠페인 중 한판블록 KR만 4,000원/일로 운영, 나머지는 일시중지. 일시중지된 캠페인은 사용자 결정 없이 재개하지 않는다.

22시 12분 압축 5번 요약에는 운영 상태 표와 "집행 중이라고 잘못 말함"이 들어갔고, 그 뒤 다시 실린 색인에는 "10/17 현재 한판블록 KR만 4,000원 운영, 나머지 3개 일시중지"가 들어 있었습니다.

에이전트가 무엇을 근거로 "집행 중"이라고 했는지는 기록에 직접 남아 있지 않습니다. 그날 아침 8시 8분에 콘솔에서 화살표 KR이 2,000원으로 도는 것을 본 일이 남았을 수도 있습니다. 그 관찰은 3번 요약에 "모두 일시중지"로 적혔고 4번 요약에서는 빠졌습니다. 반면 색인은 착오 14분 전에 다시 실렸고, 문구가 에이전트가 스스로 말한 "각 2,000원"과 같습니다. 그래서 색인 쪽을 유력한 출처로 봅니다.

메모리 14개 중 13개가 Why와 How to apply

이 메모리는 Claude Code가 작업 폴더별로 두는 ~/.claude/projects/<작업 폴더 이름>/memory/ 폴더의 파일들이고, MEMORY.md가 한 줄씩 요약한 색인입니다. 2026-11-02 기준 이 홈 폴더의 메모리는 파일 14개와 색인 14줄입니다. 13개는 본문 끝에 Why:와 How to apply:가 있고, 없는 1개는 플러그인 계정을 안내하는 참조용 메모입니다. 광고 메모리는 10월 8일 22시 23분에 처음 쓰였고, 10월 18일까지 본문을 5번 더 고쳤습니다. 식별값과 감정 표현을 지운 요지는 이렇습니다.

한판블록 앱 설치 캠페인: 언어별 2개, 각 일 2,000원, 목표 CPI 없음
runbook 2절의 "미국, tCPI 1,400원, 일 25,000원"은 쓰지 않는다.
Why: 여러 번 지시했는데 runbook 값을 따랐다.
How to apply: 이 캠페인 설정·수정 때 사용자 지시가 runbook보다 우선.

요약 9개 어디에도 runbook과 다르게 정한 이유가 없었는데, 마케팅 세션은 13일 동안 25,000원이나 tCPI 1,400원을 한 번도 설정하려 하지 않았습니다. 10월 11일 광고 안을 짤 때 이 메모리 파일을 읽었고, 색인 줄의 "(runbook보다 우선)"은 세션 시작과 압축 1~4번 뒤에 다시 실렸습니다. 10월 17일 정정 때 이 줄이 상태 줄로 바뀌면서 그 뒤 다섯 번은 이 문구 없이 실렸습니다.

결정의 이유는 요약에 맡기지 말고 그 자리에서 메모리 파일에 적으십시오. 광고 콘솔처럼 사람이 밖에서 바꾸는 상태는 요약도 메모리도 믿지 마십시오.

이 글과 비슷한 문제를 겪고 있다면 메일로 상황을 알려 주세요. 읽고 답하겠습니다. 메일로 문의하기

runbook, /compact, CLAUDE.md, 색인

runbook 2절의 값은 미국 설치 단가를 재는 실험(누적 100,000원, 4일)의 근거와 함께 정해졌고, 실제 집행은 동남아 영어권과 한국을 언어별로 나눈 다른 실험이었습니다. runbook 2절 값은 고치지 않았고, 고치지 않은 이유는 기록에 없습니다. 메모리에는 "runbook 값은 쓰지 않는다"가 적혔습니다.

압축 시점을 사람이 고르는 수동 /compact로도 다른 세션의 결정은 요약에 들어오지 않았습니다. 비교한 두 세션은 수동 압축 10번을 했는데, 게임 개발 세션의 수동 요약도 25,000원 계획을 들고 갔습니다. 다른 세션에서 내린 결정은 메시지나 파일로 이 세션에 들어오지 않는 한 요약에도 들어올 수 없습니다. 요약의 사용자 메시지 목록에 기대는 것도 같은 이유로 버렸습니다. 2,000원 지시는 옆 세션의 사용자 메시지였고, 운영자가 콘솔에서 캠페인을 끈 것은 메시지가 아닙니다. /compact 뒤에 남길 것을 지시문으로 붙이는 방법은 써 보지 않았습니다. 이 기록의 수동 압축 10번은 모두 지시문 없이 실행됐습니다.

전역 CLAUDE.md도 압축 6~9번 뒤(10월 19일부터) 네 번은 색인과 함께 다시 실렸습니다. 다시 실린다는 점은 색인과 같아서, 거기에 상태를 적으면 같은 방식으로 오래된 값이 남을 것으로 봅니다. 같은 세션 안에서 난 10월 17일 착오를 막을 대안 중 근거가 있는 것은 색인에서 상태를 빼는 것입니다. 착오 직전에 다시 실린 것은 결정과 금액이 한 줄에 함께 들어간 색인 줄이었고, 날짜 붙은 상태 줄은 본문에만 있었습니다. 색인 줄에는 결정과 파일 이름만 두고, 금액과 운영 상태는 날짜를 붙여 본문에 두는 쪽을 권합니다.

작업 폴더별 메모리

Claude Code 메모리는 세션을 연 작업 폴더별로 쌓였습니다. 게임 저장소 폴더에서 연 세션들은 다른 메모리 폴더를 사용했고, 거기 광고 상태 파일에는 "10-17 운영자가 전부 일시중지, 같은 날 한판블록 KR 4,000원으로 재개"가 적혀 있었습니다.

압축 없이 끝나고 옆에서 도는 세션도 없는 작업이면 이 방식까지 갈 일이 적습니다. 상태 줄은 날짜와 "사용자 확인"을 붙여도 다음 변경 전까지만 맞습니다.

문서와 다른 결정이 나온 자리에서

  1. 운영자가 문서와 다른 값을 지시하면 그 자리에서 메모리 파일 하나를 만듭니다. 결정값, 그와 다른 문서와 그 값("쓰지 않는다"), Why:, How to apply: 순서입니다.
  2. 색인 MEMORY.md에는 그 파일의 결정만 한 줄로 넣습니다. 금액이나 켜짐·꺼짐 같은 상태는 넣지 않습니다.
  3. 지금 켜져 있는 것 같은 상태는 본문의 결정과 다른 줄에 날짜와 "사용자 확인"을 붙여 쓰고, 바꾸면 안 되는 것을 같이 적습니다.
  4. How to apply:에 "비용이 걸린 콘솔 작업 전에는 콘솔 현재 값을 읽고, 이 파일 상태 줄과 다르면 먼저 고친다"를 적습니다.

맥락이 끊길 때 디스크에 쓴 파일만 남은 기록은 이 사이트의 다른 노트 서브에이전트 브리프의 절대 규칙 6개와 한도로 끊긴 에이전트 5건에도 있습니다.

색인에 남은 상태 줄

11월 2일에도 runbook 2절과 광고 계획 문서는 25,000원입니다. 같은 날 색인의 한판블록 줄에는 "10/18 현재 한판블록 KR 4,000원·화살표 KR 2,000원 운영"이라는 상태가 아직 들어 있어서, 2번 절차대로라면 이 줄부터 결정만 남기고 고쳐야 합니다. 화살표 KR이 정확히 몇 시에 꺼졌는지는 세션 기록에 없어 재지 못했습니다.
