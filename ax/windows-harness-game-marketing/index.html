Claude Code 하네스 17일 운영과 시작 순서

처음 1주는 보고만 받고, 실패는 날짜별로 적고, ok 대신 판정 줄을 읽고, 로그인 만료일을 달력에 적은 뒤 작업을 하나씩 늘립니다.

작성 SugarMount · 스토어와 수익화 · 읽는 시간 9분 · 최종 업데이트 2026년 11월 12일

Windows 하네스 연재 11/11 · 이전 편 틱톡·릴스·쇼츠 영상 계획

6~10편에서 키트로 작업 네 개를 만들었습니다. 이 편은 SugarMount 하네스를 2026-10-25부터 11-10까지 17일 돌린 기록에서, 키트를 매일 쓰기 시작할 때 지킬 순서와 아침 점검 습관을 뽑았습니다.

  • 준비물: 6~7편의 hello 예약, 8편의 ga4-daily 작업
  • 비용: 추가 비용 없음

1단계: 처음 1주는 보고만 받는다

그림자 운전은 AI가 보고만 하고 실제로 바꾸지는 않는 시험 운전입니다. 키트의 보고 작업 세 개는 지시문이 "파일을 고치거나 새로 만들지 않는다"이고 읽기 도구(Read, Glob)만 허용하므로, 그대로 쓰면 그림자 운전이 됩니다.

  1. PowerShell을 열고 키트 폴더로 갑니다.

    cd $HOME\harness

  2. 이 창에서만 스크립트 실행을 허용합니다(6편). 창을 새로 열 때마다 이 줄을 먼저 넣습니다.

    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

  3. ga4-daily를 매일 09:30에 예약합니다. 8편에서 등록했다면 이 줄은 넣지 않아도 됩니다.

    .\register-job.ps1 -Name ga4-daily -At 09:30

  4. 다음 날부터 1주 동안 아침마다, 예약 시각 전에 GA4 CSV를 오늘 날짜로 시작하는 이름(예: 2026-11-12-events.csv)으로 data\ga4에 넣습니다(8편).

  5. 예약 시각이 지나면 가장 최근 보고서를 엽니다.

    notepad .\reports\latest-ga4-daily.md

  6. 보고서에서 [GA4 CSV] 표시가 붙은 숫자 3개를 골라, data\ga4 폴더의 CSV 원본에서 같은 숫자를 찾습니다.

이렇게 보이면 성공

1주 동안 고른 숫자가 모두 CSV 원본과 맞습니다. 틀린 숫자가 하나라도 있으면 다음 작업으로 넘어가지 않습니다.

SugarMount 기록

SugarMount 하네스는 10-25~10-27 사흘을 그림자 모드로 돌렸고, 그사이에도 보고서 잘못이 적어도 두 번 나왔습니다. 한 번은 실패율 계산에 틀린 분모를 썼고, 정정 줄을 붙여 고쳤습니다. 다른 한 번은 기존 대화 세션 예약이 "돌지 않은 것으로 보인다"고 적었는데, AI가 날짜만 준 조회로 기록을 찾다가 그날 것을 빠뜨린 것이었고 다음 날 보고서가 바로잡았습니다.

2단계: 실패를 날짜별로 본다

날짜별로 적어 두면 실패가 되풀이되는지 보입니다.

  1. 매일 아침 탐색기에서 harness 폴더의 status.cmd를 두 번 클릭해 상태 표를 엽니다(7편). 폴더는 PowerShell에서 아래 줄로도 열립니다.

    explorer $HOME\harness

  2. 마지막결과가 ok가 아닌 작업은 PowerShell 창에서 로그를 엽니다(1단계의 cd 줄 다음에).

    Get-Content .\logs\ga4-daily.log

  3. 날짜, 작업, 마지막결과를 메모장에 한 줄씩 적습니다.

PowerShell 창에서 1단계의 두 줄을 넣은 뒤 .\status.ps1을 넣어도 같은 상태 표가 나옵니다.

이렇게 보이면 성공

마지막결과 칸에 ok, 끝난시각 칸에 오늘 날짜, 다음예약 칸에 내일 예약 시각이 보입니다.

아래 그림의 exit 뒤 숫자는 종료 코드, 곧 프로그램이 끝나며 남기는 숫자입니다. 0이면 오류 없이 끝난 것입니다. 11-06 칸이 초록인 것은 그날 아침 실패한 뒤 다시 돌려 성공했기 때문입니다.

SugarMount 기록

17일 51칸 중 실패는 7칸입니다. 10-30의 세 칸은 요금제의 주간 사용 한도(You've hit your weekly limit)에 걸린 날입니다. 11-04에는 전날 회차가 남긴 파일 변경 때문에 한글 앱만 멈췄고, 이어서 약 38시간 동안 하네스 코드에 확정(commit)하지 않은 편집이 남아 모든 예약 작업이 준비 단계에서 멈췄습니다(7편).

3단계: ok를 성공으로 읽지 않는다

상태 표의 ok는 오류 없이 끝났다는 뜻일 뿐입니다. 일을 해냈는지는 키트 작업 네 개가 모두 보고서 끝에 쓰는 판정: 완료 또는 판정: 일부 실패(이유) 줄로 봅니다.

  1. 그날 보고서를 엽니다.

    notepad .\reports\latest-ga4-daily.md

  2. 아래쪽에서 판정:으로 시작하는 줄을 찾습니다.

  3. 일부 실패라면 괄호 안 이유를 읽습니다. (파일 없음)이면 data\ga4 폴더에 CSV가 없고, (오늘 넣은 파일 없음)이면 오늘 날짜로 시작하는 파일이 없는 것입니다.

이렇게 보이면 성공

판정: 완료 줄이 보입니다.

SugarMount 기록

2026-11-10 유틸 앱의 소셜 작업은 올릴 영상 목록이 비어 게시 0건으로 끝났지만 러너 상태는 ok였고, 그날 밤 하루 상태판도 "실패·빠짐 0건"이었습니다. 11-11부터 모든 작업이 마지막 줄에 판정을 쓰게 했고, 키트 지시문 네 개에도 같은 줄을 넣었습니다.

이 글과 비슷한 문제를 겪고 있다면 메일로 상황을 알려 주세요. 읽고 답하겠습니다. 메일로 문의하기

4단계: 로그인 만료일을 달력에 적는다

Claude Code 로그인에는 끝나는 날이 있고, 로그인이 없으면 실행은 실패합니다. 그 전에 예약 작업용 전용 설정 폴더(.claude-harness)에서 다시 로그인합니다.

  1. 상태 표의 로그인경고 칸에 다시 로그인 필요가 보이면, 그 작업의 로그(보고서가 아님)에서 Warning: this sign-in ends between으로 시작하는 줄의 날짜 두 개를 읽습니다. 로그 끝쪽에는 러너가 남긴 주의: Claude 로그인 만료 예고가 나왔습니다… 줄도 있습니다.

    Get-Content .\logs\hello.log

  2. 앞 날짜보다 이른 날을 골라 "Claude 다시 로그인"이라고 달력에 적습니다.

  3. 그날 새 PowerShell 창에서 전용 설정 폴더를 지정합니다(4편).

    $env:CLAUDE_CONFIG_DIR = "$env:USERPROFILE\.claude-harness"

  4. 같은 창에서 Claude Code를 열고, /login을 입력해 브라우저 안내를 따릅니다.

    claude

이렇게 보이면 성공

터미널에 Login successful이 보입니다. Enter를 눌러 계속합니다.

SugarMount 기록

2026-11-12 실제 하네스의 전용 설정 폴더로 돌린 작업은 답마다 맨 앞에 이 줄을 찍었습니다.

Warning: this sign-in ends between 2026-11-18 and 2026-11-21 (in 7 days at the earliest). Renewing it does not move those dates. Run claude auth login before then, or use claude setup-token for unattended jobs.

경고 문장은 이 로그인이 11-18과 11-21 사이에 끝나며(빠르면 7일 뒤) 갱신해도 날짜가 바뀌지 않는다고 알립니다. 경고가 권하는 claude setup-token은 1년짜리 토큰을 만들지만 저장해 주지 않아(공식 문서) 직접 보관해야 하므로, 이 연재는 다시 로그인하는 쪽을 권합니다.

5단계: 작업을 하나씩 늘린다

그림자 1주가 끝나면 작업을 한 번에 하나씩 켜고, 기준을 채운 뒤 다음 줄로 갑니다. 예약 시각은 표처럼 겹치지 않게 둡니다.

순서켜는 작업다음으로 넘어가는 기준
1hello 예약(6~7편)상태 표에 ok와 다음 예약 시각이 보입니다
2ga4-daily, 09:30(8편)1주 동안 보고서 숫자가 CSV 원본과 맞습니다
3ads-check, 09:40(9편)제안을 사람이 읽고, 무엇을 바꿨는지 기록합니다
4shorts-plan, 10:00(10편)사람이 올리고 posted.csv에 조회수를 적습니다
5승인함(연재 밖)사람이 승인한 요청만 실행합니다
6정해진 범위 안의 자동 변경(연재 밖)상한부터 정합니다. 실제 하네스의 광고 일 예산 상한은 앱당 5,000원, 전체 12,000원입니다

실제 하네스에서는

SugarMount 하네스는 일을 권한에 따라 세 단계로 구분합니다.

  • 바로 실행: 무료 마케팅, 스토어 문구, 문서, 검증을 통과한 배포
  • 확인 받기(승인함): 돈, 새 캠페인과 중지, 광고 설정, 권한, 앱 이름, 가격, 큰 변경
  • 절대 금지(가드 훅이 막음): 코드 기록 강제 덮어쓰기, 비밀값 출력, 패키지 설치, 100% 출시

이 구분을 정한 과정은 AI 에이전트 권한 표: 돈·계정·정책은 사람이 누른다 글에 따로 적었습니다.

자주 묻는 질문

그림자 운전은 며칠 해야 하나요?

SugarMount는 사흘(10-25~10-27) 돌린 뒤 10-27에 실제 변경을 켰고, 광고 일 예산 조정은 그 뒤 10-30에 따로 맡겼습니다(9편). 그 사흘 사이에도 보고서 잘못이 적어도 두 번 나왔기 때문에, 이 연재는 처음 시작할 때 1주를 권합니다.

상태가 ok인데 일이 안 됐을 수도 있나요?

그렇습니다. 2026-11-10 SugarMount 하네스의 게시 작업 하나는 올릴 영상이 없어 0건을 올렸지만 상태는 ok였습니다. 보고서의 판정 줄을 함께 봅니다.

2026-11-12 기준. SugarMount 하네스의 디스패처 상태 파일과 러너 로그(2026-10-25~11-10), 그림자 운전 비교 보고서(2026-10-26·27), 이 PC에서 2026-11-12에 돌린 키트 출력, Claude Code 공식 문서(code.claude.com).

이 글은 SugarMount가 직접 측정한 값으로 쓰고, 초안 작성에 AI 코딩 에이전트를 썼습니다.
