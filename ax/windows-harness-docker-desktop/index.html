Docker가 이 하네스에서 하는 일 두 가지

Docker는 프로그램을 컨테이너라는 격리된 공간에 넣어 실행하는 도구입니다. 컨테이너는 이미지(컨테이너를 만드는 설계도 파일)에서 만들어집니다. 이 하네스는 Docker로 서버 두 종류를 실행합니다.

하나는 데이터 수집 서버입니다. 웹앱과 PostgreSQL 16 데이터베이스를 Docker Compose(컨테이너 여러 개를 설정 파일 하나로 같이 실행하는 기능)로 구성했습니다. 매일 09:00 KST(UTC 00:00)에 전날의 AdMob(앱 광고 플랫폼), GA4(Google 애널리틱스 4), Google Ads 지표를 모아 스냅샷 JSON 파일(그날 지표를 그대로 적어 둔 텍스트 파일)을 만들고, 게임 데일리 작업이 이 파일을 읽어 그날 분석을 시작합니다.

다른 하나는 MCP 서버입니다. MCP는 Claude가 GitHub 같은 외부 서비스를 도구처럼 쓰게 해 주는 연결 방식이고, 이 PC는 GitHub MCP 서버를 ghcr.io/github/github-mcp-server 이미지로 실행합니다. Claude 세션이 열릴 때마다 하나씩 생기기 때문에 11월 11일 아침에는 이 컨테이너가 7개 떠 있었습니다. 메모리 사용량을 볼 때는 이 개수도 함께 계산합니다.

4편의 최소 키트는 러너 스크립트 하나와 작업 파일 두 개라서 Docker 없이 돌아갑니다. Docker는 매일 지표를 모아 둘 서버나 MCP 서버를 컨테이너로 돌릴 때 필요합니다. 하네스를 처음 꾸린다면 Docker는 지금 깔지 마십시오. 키트로 예약 실행이 한 번 돌고 나서, 매일 모아 둘 지표가 생기면 이 편으로 돌아오면 됩니다.

첫날 4번 실패: Docker는 떠 있었고 서버는 일하지 않았습니다

데이터 수집 서버 실행 기록 (10-11~11-10)값
예약 실행32회 (성공 28, 실패 4)
손으로 돌린 실행8회 (모두 성공)
실패 4회모두 10-11 예약 회차, "Google 자격 증명 없음"
40회 전체 걸린 시간중앙값 5.8초, 가장 길게 58초

10월 11일 15시 21분(KST)부터 약 30분 간격으로 돈 예약 실행 4번이 모두 실패했습니다. 컨테이너는 떠 있었습니다. 이 편 뒤쪽의 hello-world가 확인해 주는 것도 거기까지입니다. 그런데 각 실행은 1~64ms 만에 "Google 자격 증명 없음"을 남기고 끝났고, 수집은 시작도 하지 않았습니다.

컨테이너가 떠 있으니 서버도 일한다고 보면 틀립니다. 자격 증명을 넣은 뒤 그날 손으로 돌린 4번은 모두 성공했고, 10월 12일 09:00부터는 예약 실행이 한 번도 실패하지 않았습니다. Docker 위에 서버를 올렸다면 첫 예약 회차의 기록을 열어 성공 줄이 남았는지 따로 확인하십시오.

관리자 PowerShell에서 WSL 설치하고 재시작

WSL(Windows Subsystem for Linux)은 Windows 안에서 Linux를 돌리는 기능입니다. Docker Desktop은 이 WSL 2 위에서 엔진을 돌리도록 설치합니다.

시작 메뉴에서 PowerShell을 검색하고, 검색 결과를 오른쪽 클릭해 "관리자 권한으로 실행"을 선택합니다. 확인 창이 나오면 화면 안내를 따라 진행합니다. PowerShell 창이 열리면 아래 명령을 붙여 넣고 Enter 키로 실행합니다. 명령을 복사해 붙이는 법은 2편에 적었습니다.

wsl --install

기본으로 Ubuntu(Linux 배포판 하나)가 함께 깔립니다. 설치가 끝나면 PC를 다시 시작하고, 재시작 뒤 나오는 창은 화면 안내를 따라 진행합니다. WSL이 이미 깔린 PC라면 이 명령은 설치 대신 안내만 보여 주니, 바로 버전 확인으로 넘어갑니다.

wsl --version

첫 줄의 WSL 버전이 2.1.5 이상이면 됩니다. 한국어 Windows에서는 "WSL 버전: 2.1.5.0"처럼 한국어로 찍힙니다(아래 출력 그림 맨 위). 2.1.5보다 낮을 때만 아래 명령으로 올립니다.

wsl --update

Docker Desktop 설치 화면에서 고르는 것

설치 파일 Docker Desktop Installer.exe는 Docker 공식 문서의 Windows 설치 페이지에서 받습니다. 기본은 사용자 단위 설치라서 관리자 권한이 없어도 됩니다. 나머지 화면은 안내를 따라 진행합니다.

  1. 받은 Docker Desktop Installer.exe를 두 번 클릭해 실행합니다.
  2. 구성(Configuration) 화면에서 "Use WSL 2 instead of Hyper-V"를 선택합니다. Hyper-V는 Windows에 들어 있는 다른 가상화 방식이고, 이 편에서 직접 골라야 하는 항목은 이것 하나입니다.
  3. 마법사가 끝나면 Close를 클릭합니다. 설치 중에 재시작을 요구할 수 있습니다.
  4. Docker Desktop은 설치 뒤 저절로 켜지지 않습니다. 시작 메뉴에서 Docker Desktop을 찾아 직접 실행합니다.
  5. 첫 실행에 Docker 구독 서비스 약관(Docker Subscription Service Agreement)이 나옵니다. 동의해야 Docker Desktop이 실행됩니다.

hello-world로 확인한 11월 11일 출력

Docker Desktop이 켜진 상태에서 일반 PowerShell 창에 아래 두 줄을 넣습니다. 이 두 명령은 공식 설치 문서에는 없고, 이 PC에서 11월 11일에 돌려 결과를 확인했습니다.

docker version
docker run --rm hello-world

docker version을 그대로 치면 Client와 Server 두 묶음이 길게 나옵니다. 두 묶음 모두에 버전이 나오면 Docker 클라이언트와 엔진(컨테이너를 실제로 만들고 돌리는 부분)이 다 켜진 것입니다. 아래 그림은 두 버전만 한 줄로 보려고 --format 옵션을 붙인 출력이고, 이 PC는 둘 다 26.0.0이었습니다.

docker run --rm hello-world는 시험용 이미지 hello-world를 받아 한 번 돌리고, --rm 옵션으로 끝난 컨테이너를 삭제합니다. "Hello from Docker! This message shows that your installation appears to be working correctly."가 나오면 설치는 끝났습니다.

표의 healthy는 컨테이너가 스스로 점검해 정상이라고 알린 상태입니다. 맨 아래 두 줄의 이미지·컨테이너 이름은 개인 서버 이름이 들어 있어 가렸습니다.

.wslconfig로 WSL 메모리 3GB 상한 두기

이 단계는 PC 메모리를 다른 무거운 작업과 나눠 쓸 때만 필요합니다. 이 PC에서 WSL은 Docker Desktop을 돌리는 용도로만 쓰이고, PC는 RAM 28GB, 16코어에서 Android 앱 빌드도 함께 돌립니다. 그래서 10월 22일에 WSL이 쓸 메모리와 CPU에 상한을 두는 설정 파일을 사용자 폴더 바로 아래(%USERPROFILE%\.wslconfig)에 만들었습니다. 파일 탐색기 주소창에 %USERPROFILE%를 입력하면 그 폴더가 열립니다.

아래는 이 PC의 파일입니다. 서버 이름이 든 주석 한 줄을 빼고, 나머지 주석은 뜻을 그대로 옮겼습니다. swap은 메모리가 모자랄 때 디스크를 메모리처럼 쓰는 공간이고, 논리 프로세서는 Windows가 세는 CPU 수입니다.

[wsl2]
# 10-22 기준 컨테이너 실사용 약 220MB + Docker 엔진, 이미지 빌드 여유 포함
memory=3GB
# 서비스 하나라 논리 프로세서 2개면 충분 (10-22 기준, 이 PC는 16개)
processors=2
# 메모리가 모자랄 때 강제 종료를 막는 최소 swap
swap=1GB

[experimental]
# 쉬는 동안 Linux 캐시를 Windows에 바로 반환
autoMemoryReclaim=dropCache

메모장으로 만들 때는 "다른 이름으로 저장"에서 파일 형식을 "모든 파일"로 변경해야 이름 끝에 .txt가 붙지 않습니다. 변경한 값은 WSL이 다시 켜질 때 적용되므로, 저장한 뒤 하네스 작업이 없는 시간에 PC를 다시 시작합니다.

3GB는 10월 22일에 컨테이너 실사용을 약 220MB로 보고 정한 값입니다. 데이터베이스를 여러 개 돌리거나 이미지를 자주 빌드하는 PC라면 이 값을 그대로 가져가지 마십시오. 세션마다 하나씩 늘어나는 MCP 컨테이너도 이 상한 안에서 메모리를 사용합니다.

WSL 전체 종료 명령은 치지 않습니다

wsl --shutdown은 돌고 있는 WSL을 한꺼번에 끄는 명령입니다. Docker Desktop이 WSL 2 위에서 돌기 때문에 이 명령을 치면 Docker까지 같이 내려가고, 그 안의 데이터 수집 서버도 같이 꺼집니다. Docker가 도는 하네스 PC에서는 이 명령을 쓰지 마십시오.

10월 18일부터 22일 낮까지 AI 에이전트가 보고 여섯 번에 "wsl --shutdown을 요청해 주세요" 같은 안내를 적었고, 10월 22일 밤 운영자가 그대로 실행하자 Docker까지 내려갔습니다. 에이전트는 그 뒤 보고 두 개에도 같은 안내를 붙였습니다. Ubuntu만 끄는 명령은 따로 있었고, 경위는 WSL을 접고 Windows 네이티브로: Claude Code 개발 환경 이전 체크리스트에 적었습니다.

지금은 이 하네스의 가드(Claude가 도구를 쓰기 직전에 검사해 위험한 명령을 막는 스크립트)가 wsl --shutdown과 WSL 배포판을 지우는 명령을 막습니다. 예약 작업의 Claude도 PowerShell 명령을 실행하기 때문입니다. 가드가 막는 다른 명령과 사람이 승인하는 일의 구분은 AI 마케터를 하루 4번 예약 실행하며 정한 권한 표: 돈·계정·정책은 사람이 누른다에 있습니다.

Docker Desktop 라이선스: 개인과 소규모 사업은 무료

Docker 문서(11월 11일 확인)에 따르면 Docker Desktop은 개인 사용, 교육, 비상업 오픈소스, 그리고 직원 250명 미만이면서 연 매출 1,000만 달러 미만인 소규모 사업에서 무료입니다. 그보다 큰 기업이 상업적으로 쓰면 유료 구독이 필요합니다. 회사 PC에 깔 계획이라면 설치 전에 이 조건을 회사 기준으로 확인하십시오.

다음 편: 모은 지표를 읽을 작업 걸기

여기까지 오면 Docker는 돌지만, 그 위에서 돌 서버도 결과를 읽을 AI 작업도 아직 없습니다. 데이터 수집 서버 자체를 만드는 법은 이 연재 범위 밖입니다. 4편에서 러너 스크립트와 작업 파일로 첫 예약 실행을 Windows 작업 스케줄러에 걸고, 5편에서 게임 데일리 작업이 스냅샷 지표를 GA4·AdMob API와 다시 대조하는 운영을 다룹니다.

설치 전에 Docker 문서의 최신 지원 목록부터 확인하십시오. 11월 11일에 확인한 요구 사항 목록에는 Pro, Enterprise, Education만 있고 Home은 없었습니다. 이 PC는 Enterprise판이라 Home판은 확인하지 못했습니다.

가상화 관련 오류가 나면 무엇부터 확인하나요?

BIOS/UEFI(Windows보다 먼저 나오는 PC 설정 화면)에서 하드웨어 가상화가 켜져 있는지부터 확인합니다. Docker 문서가 요구 사항으로 적은 항목이고, 켜는 메뉴는 PC 제조사 설명서를 따라 찾습니다.

Docker 계정이 꼭 있어야 하나요?

없어도 됩니다. 첫 실행에 Docker 구독 서비스 약관에는 동의해야 하지만, Docker 계정 로그인은 하지 않아도 된다고 Docker 문서(11월 11일 확인)에 적혀 있습니다.

기준일 2026-11-11. 설치 절차는 Microsoft WSL 설치 문서와 Docker Desktop Windows 설치 문서(11-11 확인), 버전과 출력은 이 PC의 PowerShell 실측(11-11), 수집 기록은 데이터 수집 서버의 실행 기록 파일(10-11~11-10), 메모리 값은 이 PC의 설정 파일(10-22 작성), 10-22 종료 사고는 이전 체크리스트 글의 세션 기록 정리입니다.
