Windows 작업 스케줄러로 Claude Code 매일 실행하기: 파일 3개짜리 키트와 실제 하네스의 안전장치

러너·작업 정의·지시문 파일 3개를 한 폴더에 두고 작업 스케줄러에 등록하면, PC에 로그온해 있는 동안 매일 정한 시각에 Claude가 일하고 로그를 적습니다.

작성 SugarMount · 에이전트와 일하는 법 · 읽는 시간 17분 · 최종 업데이트 2026년 11월 11일

Windows 하네스 연재 4/5 · 앞 편 3편 Docker Desktop 설치 · 다음 편 5편 게임 앱 마케팅 운영

이 글의 키트로 hello 작업을 손으로 돌리자 Claude가 11초 만에 답을 냈고, 러너가 로그와 상태 파일을 남겼습니다(2026-11-11, 이 PC). 시간 한도를 3초로 줄인 작업은 3초에 강제 종료됐습니다. 코드를 짜 본 적이 없어도 파일 3개를 복사해 붙여 넣으면 됩니다.

대화창 안에서 건 예약은 그 세션을 닫으면 돌지 않습니다(1편 하네스 개요). 작업 스케줄러는 세션과 상관없이 정한 시각에 Claude를 새로 띄우고, 클라우드 서버 없이 PC 한 대로 돌아갑니다.

폴더 하나와 파일 세 개

이 키트에서 시계는 Windows의 작업 스케줄러가, 실행은 러너 run-job.ps1이 맡습니다. 러너는 작업 정의 jobs\hello.json을 읽고 지시문 prompts\hello.md를 claude -p에 넣습니다. -p는 대화창 없이 일을 한 번 시키고 끝내는 헤드리스 실행입니다.

2편에서 쓴 PowerShell 창에 아래 두 줄을 붙여 넣으면 폴더가 생기고 그 안으로 들어갑니다. $HOME은 내 사용자 폴더입니다. logs와 state는 러너가 처음 돌 때 만듭니다.

New-Item -ItemType Directory -Force "$HOME\harness\jobs", "$HOME\harness\prompts"
cd $HOME\harness

러너 run-job.ps1

같은 창에서 notepad $HOME\harness\run-job.ps1을 입력하면 메모장이 새 파일을 만들지 묻습니다. '예'를 누르고 아래 코드를 그대로 붙여 넣은 뒤, Ctrl+Shift+S(다른 이름으로 저장)에서 인코딩을 'UTF-8(BOM)'으로 골라 저장합니다. BOM(파일 앞 3바이트 표식)이 없으면 PowerShell 5.1이 파일을 ANSI(옛 지역 문자 코드)로 읽어 한글을 깨뜨립니다.

param([Parameter(Mandatory = $true)][string]$Name)
# 작업 하나를 실행한다: 작업 정의를 읽고, 겹침을 막고, 시간 한도를 걸고, 로그를 남긴다.
$ErrorActionPreference = 'Stop'
$root = $PSScriptRoot
$job  = Get-Content "$root\jobs\$Name.json" -Raw -Encoding UTF8 | ConvertFrom-Json
New-Item -ItemType Directory -Force "$root\logs", "$root\state" | Out-Null
$log  = "$root\logs\$Name.log"
function Write-Log($msg) { Add-Content -Path $log -Value "[$(Get-Date -Format 'yyyy-MM-dd HH:mm:ss')] $msg" -Encoding UTF8 }

# 1) 같은 작업이 아직 돌고 있으면 건너뛴다
$mutex = New-Object System.Threading.Mutex($false, "Global\my-harness-$Name")
if (-not $mutex.WaitOne(0)) { Write-Log '이전 실행이 아직 돌고 있어 건너뜀'; exit 5 }

try {
    # 2) 전용 설정 폴더(로그인 정보가 대화용 Claude와 섞이지 않게)
    if ($job.configDir) { $env:CLAUDE_CONFIG_DIR = $job.configDir.Replace('~', $HOME) }

    # 3) claude -p 인자: 프롬프트는 인자가 아니라 표준 입력으로 넣는다
    $claudeArgs = @('-p', '--model', $job.model)
    if ($job.allowedTools -and $job.allowedTools.Count -gt 0) {
        $claudeArgs += @('--allowedTools', ('"' + ($job.allowedTools -join ',') + '"'))
    }
    $promptFile = "$root\$($job.prompt)"
    $outFile    = "$env:TEMP\my-harness-$Name.out"
    $cmdLine    = 'claude ' + ($claudeArgs -join ' ') + " < `"$promptFile`" > `"$outFile`" 2>&1"

    Write-Log "시작 model=$($job.model) timeout=$($job.timeoutSeconds)s"
    $sw = [Diagnostics.Stopwatch]::StartNew()
    $p  = Start-Process -FilePath 'cmd.exe' -ArgumentList '/c', $cmdLine -WorkingDirectory $root -WindowStyle Hidden -PassThru

    # 4) 시간 한도: 넘으면 claude와 그 자식 프로세스까지 끈다
    if (-not $p.WaitForExit([int]$job.timeoutSeconds * 1000)) {
        & taskkill.exe /PID $p.Id /T /F | Out-Null
        $status = 'timeout'; $code = 1
    } else {
        $code = $p.ExitCode
        $status = if ($code -eq 0) { 'ok' } else { 'error' }
    }
    if (Test-Path $outFile) { Get-Content $outFile -Encoding UTF8 | Add-Content -Path $log -Encoding UTF8; Remove-Item $outFile }
    Write-Log ("종료 status={0} exit={1} ({2:N0}s)" -f $status, $code, $sw.Elapsed.TotalSeconds)

    # 5) 마지막 결과를 상태 파일로 남긴다(감시자가 이 파일만 본다)
    @{ job = $Name; status = $status; exitCode = $code; finishedAt = (Get-Date).ToString('s') } |
        ConvertTo-Json | Set-Content -Path "$root\state\$Name.json" -Encoding UTF8
    exit $code
}
finally {
    $mutex.ReleaseMutex()
}
  • 맨 위와 5): 작업 정의를 읽고, 시각을 붙여 로그를 쓰고, 결과를 state\hello.json에 적습니다.
  • 1) 같은 작업이 돌고 있으면 종료 코드 5로 건너뜁니다(뮤텍스는 Windows의 '사용 중' 표시).
  • 2)·3) configDir 폴더의 설정을 쓰고, 지시문은 <로 표준 입력(키보드 대신 받는 입력 통로)에 넣습니다. 인자로 넘기면 도구 목록으로 읽혀서입니다.
  • 4) 한도를 넘기면 Claude와 자식 프로세스(Claude가 띄운 하위 프로그램)까지 강제 종료합니다.

종료 코드는 0이 성공, 1이 시간 초과, 5가 건너뜀입니다.

작업 정의와 지시문

작업 하나는 JSON 작업 정의와 지시문 한 쌍입니다. 같은 방법으로 notepad $HOME\harness\jobs\hello.json을 열어 아래를 붙여 넣고 UTF-8로 저장합니다.

{
  "description": "동작 확인용 작업",
  "prompt": "prompts/hello.md",
  "model": "haiku",
  "allowedTools": [],
  "timeoutSeconds": 300
}

model은 판단이 적은 동작 확인이라 haiku로 두었습니다. allowedTools가 빈 목록이면 Claude는 파일 읽기나 명령 실행 없이 답만 냅니다. 지시문 prompts\hello.md는 두 줄입니다.

너는 게임 앱 마케팅 하네스의 동작 확인 작업이다. 도구는 쓰지 않는다.
"하네스 동작 확인"이라는 말과 함께, 게임 앱 마케팅 담당자가 아침에 가장 먼저 볼 숫자 세 가지를 한 줄로 적어라.

Get-ChildItem $HOME\harness -Recurse를 입력해 파일 3개가 제자리에 있는지 확인합니다.

손으로 한 번 돌리기

등록 전에 손으로 한 번 돌립니다. 예약 실행은 창이 뜨지 않습니다.

cd $HOME\harness
powershell -NoProfile -ExecutionPolicy Bypass -File .\run-job.ps1 -Name hello
Get-Content .\logs\hello.log

-ExecutionPolicy Bypass는 PC 설정을 바꾸지 않고 이번 실행에만 스크립트를 허용합니다. 로그 마지막 줄이 종료 status=ok exit=0이면 성공입니다.

Claude는 숫자를 지어내지 않았습니다. 지시문이 도구를 쓰지 말라고 했으니 데이터를 가져올 수 없다며, 어제 신규 설치, 설치당 비용(CPI), D7 ROAS 칸을 비워 둔 한 줄 형식만 냈습니다. 상태 파일 state\hello.json에는 작업 이름, status, exitCode, 끝난 시각이 남습니다.

시간 한도 시험은 timeoutSeconds만 3으로 둔 t3 작업으로 했고, 3초 뒤 러너가 Claude를 끄고 status=timeout exit=1을 적었습니다.

처음 생각과 다르게 쓰인 configDir

키트를 처음 만들 때는 configDir를 로그인을 나누는 선택 칸으로만 봤고(러너 주석도 '로그인 정보가 대화용 Claude와 섞이지 않게'), hello는 이 칸 없이 돌렸습니다. 그런데 답 끝에 지시문에 없는 세 줄이 '한 일', '결과', '남은 일'로 시작하며 붙었습니다. 운영자가 대화용 Claude에 넣어 둔 개인 지침 파일(전역 CLAUDE.md)의 요약 규칙이 예약 작업에도 적용된 것입니다.

CLAUDE_CONFIG_DIR를 정하면 Claude Code가 ~/.claude 대신 그 폴더의 설정, 로그인, 지침 파일을 사용합니다. 그래서 configDir를 쓰면 대화용 지침 대신 그 폴더의 지침을 따릅니다. 실제 하네스의 전용 폴더에도 같은 요약 지침이 복사돼 있어서 11-10 실제 작업의 답도 이 요약으로 끝났고, 이 형식을 빼려면 그 폴더의 지침 파일을 고쳐야 합니다. 그 폴더를 지정한 hello2는 덧붙임 없이 5초에 끝났지만 한 번 돌린 결과라 비교 근거로 쓰지 않습니다.

폴더를 나누는 더 큰 이유는 로그인입니다(아래 표 첫 줄). 예약용 hello.json은 이렇게 바꿉니다(JSON 안에서는 역슬래시를 두 번 씀).

{
  "description": "동작 확인용 작업",
  "prompt": "prompts/hello.md",
  "model": "haiku",
  "allowedTools": [],
  "configDir": "~\\.claude-harness",
  "timeoutSeconds": 300
}

전용 폴더에는 한 번 로그인합니다. 새 PowerShell 창에서 아래를 입력하고, Claude가 열리면 /login으로 로그인한 뒤 창을 닫습니다.

$env:CLAUDE_CONFIG_DIR = "$env:USERPROFILE\.claude-harness"; claude

이 글과 비슷한 문제를 겪고 있다면 메일로 상황을 알려 주세요. 읽고 답하겠습니다. 메일로 문의하기

작업 스케줄러에 등록

아래 묶음을 PowerShell 창에 한 번에 붙여 넣으면 매일 9시 5분에 hello 작업이 돕니다. 줄 끝 역따옴표(`)는 다음 줄로 이어진다는 표시입니다. SugarMount 하네스 설치 스크립트의 등록 부분을 줄인 것입니다.

$runner   = "$HOME\harness\run-job.ps1"
$action   = New-ScheduledTaskAction -Execute 'conhost.exe' `
              -Argument "--headless powershell.exe -NoProfile -ExecutionPolicy Bypass -File `"$runner`" -Name hello" `
              -WorkingDirectory "$HOME\harness"
$trigger  = New-ScheduledTaskTrigger -Daily -At 9:05
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries `
              -MultipleInstances IgnoreNew -ExecutionTimeLimit (New-TimeSpan -Hours 1)
$principal = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" -LogonType Interactive -RunLevel Limited
Register-ScheduledTask -TaskPath '\my-harness\' -TaskName 'hello' -Action $action -Trigger $trigger `
  -Settings $settings -Principal $principal -Force
설정하는 일과 이유
conhost.exe --headless창 없이 실행합니다. 빼면 실행마다 검은 창이 나타납니다(Windows 11).
-StartWhenAvailable꺼짐·절전으로 놓친 회차를 깨어난 뒤 한 번 돌립니다.
-AllowStartIfOnBatteries, -DontStopIfGoingOnBatteries배터리에서도 시작하고 전원을 뽑아도 끊지 않습니다. 빼면 기본값대로 배터리에서는 시작하지 않습니다.
-MultipleInstances IgnoreNew앞 실행이 안 끝났으면 새 실행을 무시합니다.
-ExecutionTimeLimit 1시간러너 한도(300초)보다 길어야 러너가 먼저 끝내고 기록을 적습니다.
-LogonType Interactive, -RunLevel Limited로그온한 동안만, 관리자 권한 없이 돕니다. 비밀번호 저장 없이 내 프로필의 Claude 로그인을 씁니다.
-Force다시 실행하면 같은 이름의 작업을 바꿔 등록합니다.

등록 뒤 시험, 확인, 지우기는 이 세 줄입니다.

Start-ScheduledTask -TaskPath '\my-harness\' -TaskName 'hello'
Get-ScheduledTaskInfo -TaskPath '\my-harness\' -TaskName 'hello'
Unregister-ScheduledTask -TaskPath '\my-harness\' -TaskName 'hello' -Confirm:$false

첫 줄은 지금 한 번 돌립니다. 1분쯤 뒤 둘째 줄의 LastTaskResult가 0인지, logs\hello.log에 새 줄이 붙었는지 봅니다. 셋째 줄은 등록을 지웁니다.

게임 마케팅 작업 예시

아래는 어제 GA4 숫자로 게임 앱 아침 보고를 쓰는 작업의 뼈대로, 이 글을 위해 만든 예시이며 실행하지 않았습니다. GA4에서 내보낸 파일을 data 폴더에 둔다고 가정합니다. 작업 정의는 hello.json을 복사해 prompt, model(sonnet), allowedTools(["Read", "Write"])만 바꿉니다. 지시문의 줄거리:

너는 게임 앱 마케팅 하네스의 아침 보고 작업이다.
1. data\ga4-yesterday.csv를 읽는다. 파일이 없으면 보고에 "데이터 없음"만 쓰고 끝낸다.
2. 신규 사용자, 첫 판 시작 사용자, 첫 판 완료 사용자를 표로 정리한다.
3. 숫자는 파일에 있는 값만 쓴다. 비율은 분수를 같이 적는다.
4. reports\ga4-(어제 날짜).md에 쓴다. 광고 예산과 캠페인은 바꾸지 않고 제안으로만 적는다.

등록은 앞의 명령에서 -Name hello와 -TaskName 'hello'를 ga4-daily로, 시각을 원하는 때로 바꿔 한 번 더 실행합니다.

실제 하네스가 더한 장치

SugarMount 하네스에 11-11까지 커밋이 130개 넘게 쌓이는 동안 붙은 장치는 대부분 사고나 리뷰 지적에서 나왔습니다.

장치계기키트에서는
전용 설정 폴더09-10 대화창 /login이 예약 작업 인증을 덮어씀configDir 칸
끝까지 기다리기-p가 서브에이전트를 10분 뒤 멈춤 → 러너가 한도까지 기다림(1ac160a)없음
잠금과 실행 한도오래 기다린 작업이 끊길 수 있다는 리뷰 지적(대기 최대 19분) → 한도에 잠금 대기 3600초 더함(64eaaeb)같은 작업 겹침만 막음
작업 트리 보존git worktree(저장소의 작업용 사본)에서 일하고 죽은 실행의 잔재는 rescue 브랜치로 옮김없음
가드 훅위험 명령을 막고, 설정을 못 읽으면 막는 쪽으로 판단(fail-closed, a69692b)도구를 비워 둠
감시자15분마다 상태 파일로 실패와 빠진 회차를 알림상태 파일만 남김
런타임 분리와 관문개발 중 편집으로 전체 정지(아래 절, 6fdc641)없음

가드 훅은 Claude가 도구를 쓰기 직전에 Claude Code가 부르는 검사 스크립트(PreToolUse 훅)이고, 종료 코드 2를 내면 그 호출이 막힙니다. 막을 일은 AI 마케터를 하루 4번 예약 실행하며 정한 권한 표에서 정했습니다.

커밋 안 한 편집으로 38시간 멈춘 일

처음에는 하네스를 개발하는 폴더(하네스 레포)에서 그대로 운영했습니다. 작업마다 먼저 도는 준비 스크립트 prepare는 하네스 코드에 커밋(git에 변경을 확정해 기록하는 것)하지 않은 변경이 있으면 종료 코드 3을 내고 끝납니다. 커밋하지 않은 하네스 코드 편집이 남은 채로 11-04 19:37부터 11-06 09:38까지 예약 작업 전부가 prepare에서 exit 3으로 끝났습니다. 약 38시간이고, 앱 데일리는 11-05·11-06 아침 회차가 실패했습니다.

하루 앞선 11-04에 한글 앱 데일리만 exit 3이 난 것은 원인이 달랐습니다. 11-03에 -p가 백그라운드 서브에이전트를 마지막 턴 10분 뒤 멈추면서 작업 트리에 변경이 남았고, prepare가 그 잔재를 보고 exit 3을 냈습니다. 표의 '끝까지 기다리기'와 '작업 트리 보존'이 그 후속입니다.

검사는 설계대로 동작했지만, 개발과 운영이 한 폴더를 쓰고 있어서 개발 중인 편집이 운영 전체를 막았습니다. 11-07부터 운영 작업은 런타임 복제본(운영 전용으로 따로 꺼내 둔 하네스 사본)에서 돌고, 15분마다 도는 harness-release가 관문 검사를 통과한 커밋만 거기에 반영합니다.

운영은 개발 폴더에서 돌리지 않습니다. 키트의 러너도 다른 폴더에서 고쳐 손으로 돌려 본 뒤 복사해 넣으십시오. 반쯤 고친 러너가 불리면 로그조차 남지 않습니다.

남은 일

키트를 등록했다면 다음 날 9시 5분이 지나서 logs\hello.log에 새 시작·종료 줄이 붙었는지, state\hello.json의 finishedAt이 오늘인지 봅니다. 줄이 없으면 그 시각에 PC가 로그온 상태였는지부터 확인합니다. 작업 스케줄러 등록·시작·확인·삭제 명령은 이 글을 쓰면서 실행하지 않았습니다. 첫 예약 실행 결과는 다음에 확인합니다.

다음 편은 이 틀 위에 GA4 분석, 광고 예산, 숏폼 게시를 올린 운영 기록입니다: 5편 게임 앱 마케팅 운영.

출처: 2026-11-11 이 PC에서 키트를 실행한 로그와 상태 파일, 하네스 레포의 README·설치 스크립트·git 기록(커밋 해시), 디스패처 상태 파일과 러너 로그(10-25~11-10), 2026-11-11 작업 스케줄러 목록. 작업 스케줄러 명령과 claude -p·훅 동작은 Microsoft Learn과 Claude Code 공식 문서(2026-11-11 확인)를 따랐습니다.
