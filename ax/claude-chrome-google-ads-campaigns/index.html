측정 대상: 세션 기록 두 개의 도구 호출 1,436번

도구는 Claude in Chrome입니다. 사용자의 크롬에 붙는 확장 프로그램으로, 에이전트가 로그인된 탭에서 화면을 캡처하고 클릭하고 글자를 넣습니다. 세션 A는 화살표 매듭풀기, 세션 B는 한판블록 캠페인을 맡았습니다. 두 세션 모두 게시 버튼은 누르지 말고 검토 화면(게시 직전에 설정을 모아 보여 주는 화면)에서 멈추라는 지시를 받았습니다. 이날 구글 광고 API는 쓰지 않았고, 지시문이 처음부터 크롬 작업이었습니다.

세션 기록의 tool_use(에이전트가 도구를 부른 한 번)를 도구 이름별로 집계했습니다.

세션전체화면 동작페이지 스크립트요소 찾기주소 이동파일 올리기
A 화살표 매듭풀기97770313665399
B 한판블록459263119351311

그래프에서 두 선이 평평한 구간(B는 22시 51분, A는 23시 06분부터 0시 40분 무렵까지)에는 운영자 메시지가 없었고, 두 세션의 도구 호출도 멈춰 있었습니다.

703번 가운데 클릭은 201번이었습니다

글감을 고를 때 붙인 제목은 "클릭 703번"이었습니다. 화면 동작 도구의 호출을 종류별로 집계해 보니 그 숫자는 클릭 수가 아니었습니다.

에이전트는 클릭 201번 가운데 140번은 바로 다음 호출이 대기였고, 기다린 시간은 대부분 1~6초였습니다(대기 249번 중 231번). 결과는 화면 캡처로 확인하는 일이 잦았습니다.

페이지 스크립트(javascript_tool, 탭 안에서 자바스크립트를 실행하는 도구) 136번을 코드 문자열 기준으로 분류하면 절반 가까운 67번이 화면 글자를 읽는 호출입니다.

화면 실수도 있었습니다. 다른 앱의 항목을 고르거나, 화면이 밀려 '예'가 눌리거나, 헤드라인 두 줄이 한 칸에 합쳐졌습니다. 보고 문장에 남은 이런 실수는 8번이고, 모두 운영자가 말하기 전에 에이전트가 알아채고 바로잡거나 빠져나왔습니다.

같은 예산 정정을 두 세션에 따로 했습니다

세션 A의 첫 지시는 설정값을 게임 저장소의 광고 문서에서 읽으라고 했고, 문서에는 일 예산 25,000원과 목표 CPI(설치당 목표 비용)가 적혀 있었습니다. A가 값을 넣기 전, 시작 65초 뒤 운영자가 정정했습니다. 일 예산 2,000원, 목표 CPI 없음, 전 세계.

세션 B는 22시 03분에 국가를 전 세계로 하라는 정정만 따로 받았고, 예산과 목표 CPI 정정은 받지 못했습니다. B가 읽은 한판블록 실행서(runbook)에는 미국, 목표 CPI 1,400원, 일 25,000원이 적혀 있었습니다.

운영자가 "심층분석해서 진행해"라고 하자, B는 일 예산은 실행서대로 넣고 목표 CPI만 실행서 값(미국 기준) 대신 자기 계산으로 700원을 넣었습니다.

22시 22분 운영자가 B에게 예산·CPI 정정을 했습니다. A에게 말하고 24분 40초 뒤였고, 말투가 거칠었습니다. 그날 정한 2,000원은 두 지시문이 가리킨 문서 어디에도 없었습니다. 예산·CPI 정정은 세션 A의 대화창에만 있었고, 병렬로 도는 세션은 서로의 대화를 읽지 않습니다.

언어 정정도 두 세션에 따로 했습니다. A의 한국어 소재 캠페인은 위치가 전 세계였고, 운영자가 언어에 영어를 직접 더해 둔 상태였습니다. 운영자가 한국어 소재로 전 세계에 나가도 되느냐고 묻자, A는 이대로면 영어 사용자에게 한국어 광고가 나간다고 답했습니다. 운영자는 그 뒤 2분이 안 되는 사이에 두 세션 모두에게 언어별 캠페인을 따로 만들라고 했고, B 창에는 A에게 보낸 지시를 그대로 붙여 넣기도 했습니다. 결과는 앱마다 한국 한국어 캠페인 하나와 동남아 영어 캠페인 하나, 각 일 2,000원이었습니다.

영상은 채널 권한과 자동 권한 검사에서 막혔습니다

앱 캠페인은 영상을 YouTube 링크로만 받습니다. 세션 A는 광고 소재 창에서 바로 올리려다 오류를 냈고, 운영자가 올려 달라고 하자 YouTube Studio에서 한국어 영상 3개를 '일부 공개'로 올렸습니다. 22시 35분에 시작해 4분 남짓 걸렸습니다.

같은 시각 세션 B는 광고 화면의 업로드 창에서 멈췄습니다. 업로드 버튼이 회색이었고, 안내 문구는 채널에 올릴 권한이 없다는 것이었습니다. 광고에 로그인된 계정과 영상 채널을 가진 계정이 달랐습니다. 운영자는 A의 답("네, 올릴 수 있습니다…")을 B 창에 그대로 붙여 넣고, 저쪽은 된다는데 왜 못 하느냐고 물었습니다.

세션 B는 닫히지 않는 영상 선택 창을 페이지 스크립트로 숨긴 적이 있습니다. 운영자가 광고 화면이 '오류 확인 중'에서 멈췄다고 알리자, B는 새로고침으로 풀고 원인을 자기 스크립트로 지목했습니다. 지금 운영 규칙은 크롬 확장이 사이트 권한을 거부하면 페이지 스크립트로 우회하지 않고 그 단계를 사람에게 넘기는 것입니다.

B가 YouTube Studio로 옮겨 파일을 보내자 이번에는 클로드 코드의 자동 권한 검사가 막았습니다. 자동 모드에서 에이전트의 도구 호출을 실행 전에 걸러 내는 검사입니다. 사유는 "Unrequested Commit in a Connected App"이었고, B는 YouTube에 올리면 외부에 게시되는데 그만큼 분명한 요청이 없었다고 검사기가 판단했다고 설명했습니다.

B는 우회하지 않고 멈췄고, 0시 39분 운영자가 영상을 왜 못 넣었느냐고 묻자 한 줄 지시 문안을 제안했습니다. 채널, 영어·한국어 각 3개, 일부 공개, 아동용 아님. 운영자가 그 문장을 그대로 입력하자 6개가 5분 안에 올라갔습니다. 광고 탭이 응답하지 않아 캠페인에 붙이는 일은 그날 끝내지 못했습니다.

정정 40초 뒤 메모리 파일이 생겼습니다

세션 B는 운영자의 예산 정정 40초 뒤 메모리 파일을 썼습니다. 메모리 파일은 클로드 코드가 세션을 시작할 때 목차(MEMORY.md)부터 읽는 프로젝트 메모입니다. 본문 첫 단락은 운영자가 정한 값을 적고, 실행서의 "미국, tCPI 1,400, 일 25,000"은 쓰지 않는다고 못 박았습니다. tCPI는 목표 CPI를 줄인 말입니다.

언어별로 나누라는 지시 9분 뒤에는 같은 파일을 덮어써 언어별 2개 구조와 영상 업로드 경로를 넣었습니다. 세션 A도 23시 06분 자기 앱 파일에 "소재 언어 = 타겟 언어"를 적었습니다.

사흘 뒤 10월 11일, 게임 마케팅을 맡은 다른 세션은 운영자가 일 2,000원 광고 얘기를 꺼내자 6초 만에 이 두 파일부터 읽었습니다. 운영자가 콘솔에서 기간을 직접 고쳤다고 하자 그 자리에서 파일을 고쳤습니다. 마케팅 세션 기록에서 운영자가 예산·입찰·언어를 다시 정정한 메시지는 찾지 못했습니다.

값을 둔 곳그날 결과고르지 않은 이유
저장소 문서·실행서B가 계획 때 값을 넣음(A는 넣기 전에 정정)계획을 적은 문서라 당일 결정이 없음
대화창 정정그 세션만 바로 고침옆 세션은 24분 40초 뒤 같은 정정
메모리 파일이후 세션이 먼저 읽음채택

메모리 파일에 먼저 쓰지 않은 값은 브라우저 에이전트에게 말하지 마십시오.

설정값은 메모리 파일에 먼저 씁니다

  1. 브라우저를 열기 전에 위치, 언어, 일 예산, 입찰, 소재 언어, 영상 채널과 그 채널을 가진 계정, 아동용 여부를 메모리 파일에 날짜와 함께 적고, 지시문에는 그 파일을 읽되 저장소 문서와 다르면 메모리가 우선이라고 씁니다.

  2. 게시 직전에서 멈추게 하고, 검토 화면 값을 메모리 파일과 줄마다 맞춘 표로 받습니다.

  3. 정정할 때는 메모리 파일을 먼저 고치고, 돌고 있는 세션마다 그 파일을 다시 읽으라고 말합니다.

  4. 영상 업로드처럼 외부에 게시되는 단계는 채널, 공개 범위, 아동용 여부를 한 줄에 다 넣어 지시합니다.

영상 소재를 만든 과정은 구글 앱 캠페인 광고 소재를 플레이 녹화로 만들기에, 이 캠페인들의 예산을 매일 점검하게 한 일은 Google Ads 일 예산 점검 보고서 매일 받기에 적었습니다. 문서에 남은 옛 줄을 에이전트가 지금 사실로 읽은 다른 사례는 클로드 코드 세션 인수인계: 멈춘 세션에 일 넘기기에 있습니다.

메모리 파일도 9일 동안 틀린 번호를 들고 있었습니다

10월 17일 마케팅 세션이 메모리에 적힌 광고 계정 번호로 GA4 연결을 요청하자 "잘못된 Google Ads 계정 ID" 오류가 났습니다. 그 번호는 세션 B가 광고 화면 주소에서 읽은 내부 번호였고, 9일 동안 아무도 몰랐습니다.

A는 22시 29분 B가 쓴 목차 한 줄(모든 국가, 일 2,000원, 목표 CPI 없음)을 실행 도중 자동으로 받았고 23시 06분 자기 파일에 B 파일을 링크했지만, B 파일 본문을 여는 호출은 없었습니다. B 쪽에는 A가 쓴 파일을 받은 기록이 없습니다.

다음에는 두 메모리 파일이 영상 채널의 소유 계정을 서로 다르게 적은 것을 실제 채널 권한 화면에서 확인하고, 광고 설정을 파일 하나로 정리합니다. 한판블록 실행서에 미국·일 25,000원 값이 아직 남아 있는지도 이번에는 열어 보지 않았습니다.

이 기록에서는 맡기지 않았습니다. 두 세션 모두 게시 직전에 멈추게 했고, 게시와 본인 인증은 운영자가 했습니다. 일 예산이 바로 나가는 단계라 검토 화면의 값을 메모리 파일과 대조한 뒤 사람이 누르는 쪽을 권합니다.

구글 광고 화면에서 YouTube 영상 업로드 버튼이 회색이면 무엇을 봐야 하나요?

광고에 로그인된 계정이 그 채널에 업로드 권한을 가졌는지 봅니다. 이 기록에서는 채널을 가진 계정이 달라서, YouTube Studio에서 그 채널로 직접 올렸습니다. 링크를 캠페인에 붙이는 일은 그날 광고 탭이 응답하지 않아 끝내지 못했습니다.
