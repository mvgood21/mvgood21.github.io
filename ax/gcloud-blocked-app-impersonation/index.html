gcloud '차단된 앱', 서비스 계정 가장으로 우회

gcloud 로그인에 analytics 스코프를 더하면 '차단된 앱'이 나옵니다. 서비스 계정을 가장해 토큰을 받으면 키 파일 없이 GA4를 읽습니다.

작성 SugarMount · 에이전트와 일하는 법 · 읽는 시간 6분 · 최종 업데이트 2026년 11월 13일

GA4(Google 애널리틱스 4) 데이터를 스크립트로 읽으려면 analytics 권한 범위(스코프)가 붙은 토큰이 필요합니다. 흔히 gcloud auth application-default login에 그 스코프를 더하는데, 그러면 브라우저에 '차단된 앱' 화면이 나오고 스코프 목록을 바꿔도 풀리지 않습니다. SugarMount는 10월 8~15일에 이 화면을 세 번 봤고, 세 번 다 AI 코딩 에이전트가 낸 로그인 명령에서 시작했습니다.

15일에는 서비스 계정 가장(impersonation)으로 갔습니다. 내 계정이 서비스 계정 대신 짧게 쓰는 토큰을 받아 오는 방식입니다. 차단 뒤 5분이 안 돼 GA4 속성 목록이 나왔고, 키 파일은 만들지 않았습니다.

세 번 본 같은 화면

10월 8일 밤, 에이전트가 낸 로그인 명령은 drive.file과 youtube.upload를 함께 요청해 400을 받았습니다. Drive 스코프를 빼고 YouTube 스코프를 따로 요청하자 '차단된 앱'이 나왔고, 에이전트는 업로드를 접고 Google Ads 화면에서 영상을 올리는 길로 바꿨습니다(구글 앱 캠페인 광고 소재를 플레이 녹화로 만들기). 11일과 15일에는 analytics 스코프로 같은 화면을 만났습니다.

막은 쪽은 gcloud 로그인 앱

15일의 출발점은 403 ACCESS_TOKEN_SCOPE_INSUFFICIENT였고, ADC(스크립트가 빌려 쓰는 기본 자격 증명) 토큰에 analytics 스코프가 없다는 진단은 맞았습니다. 틀린 것은 스코프를 더하는 해결이었습니다. gcloud auth application-default login은 gcloud에 든 OAuth 로그인 앱으로 동의 화면을 엽니다. 직접 만든 데스크톱 클라이언트로 같은 스코프를 요청한 11일 스크립트는 통과했습니다.

8일의 교훈은 에이전트 메모 속 괄호 한 줄, "gcloud 클라이언트는 YouTube 스코프에 막힌다"로만 남았습니다. 15일 세션은 그 메모를 읽고 39초 뒤, 같은 모양의 로그인 명령에 analytics 스코프만 바꿔 넣어 냈습니다. 에이전트가 스코프만 더하면 된다며 gcloud 로그인 명령을 내밀면 실행하지 마십시오.

이 글과 비슷한 문제를 겪고 있다면 메일로 상황을 알려 주세요. 읽고 답하겠습니다. 메일로 문의하기

키 파일 없이 가장 토큰 받기

  1. GA4 연결 프로젝트에서 IAM Credentials API(토큰 발급 API)와 Analytics Data API를 켜고 서비스 계정을 만듭니다. 키는 만들지 않습니다.

  2. 내 계정에 그 서비스 계정의 토큰 생성자 역할(roles/iam.serviceAccountTokenCreator)을 줍니다.

  3. GA4 관리의 계정 액세스 관리에서 서비스 계정 주소를 뷰어로 넣습니다.

  4. 받은 토큰을 GA4 Data API 요청 헤더에 Bearer 토큰으로 붙입니다.

    gcloud auth print-access-token --impersonate-service-account=<서비스 계정 주소> --scopes=https://www.googleapis.com/auth/analytics.readonly

내 로그인은 원래 있던 cloud-platform(Google Cloud용) 스코프로 IAM Credentials API를 부를 뿐이고, analytics 스코프는 서비스 계정 토큰에 붙습니다. Windows PC에서는 ADC 토큰으로 그 API를 부릅니다(10월 22일). 15일에는 1·2번 명령(역할 부여 포함)을 Claude Code 자동 모드의 권한 분류기(위험한 명령을 사람에게 넘기는 자동 검사)가 막아 운영자가 직접 돌렸고, 3번도 운영자가 했습니다.

다른 길은 직접 만든 OAuth 데스크톱 클라이언트입니다. 11일 대시보드 서버는 이 방식으로 AdMob·GA4 읽기와 Gmail 발송 세 스코프만 받습니다. 다만 클라이언트 비밀 파일을 보관해야 해서, 15일에는 유출될 비밀값이 없는 가장을 골랐습니다.

해결법을 적어 둔 곳이 한 폴더뿐이었습니다

15일 저녁 에이전트는 게임 폴더의 프로젝트 메모리에 GA4 접근 메모를 따로 만들었습니다. 첫 줄은 동작하는 명령이고, 왜 그렇게 하는지와 언제 쓰는지가 뒤따릅니다.

Claude Code의 프로젝트 메모리는 그 폴더에서만 읽힙니다. 이틀 뒤 한글뷰어 세션의 서브에이전트는 GA4 Data API 403 앞에서 다시 ADC 로그인 명령을 남겼습니다(GA4에 0이 보일 때 먼저 볼 곳: 표 보고서의 합계 행). 25일에는 다른 프로젝트가 스프레드시트 스코프로 네 번째 '차단된 앱'을 봤습니다. Gmail 발송, AdMob 읽기, YouTube 업로드는 가장으로 시험하지 않았습니다.

여러 프로젝트에서 에이전트를 쓴다면, 동작하는 가장 명령과 "gcloud 로그인에 스코프를 더하지 않는다"는 한 줄을 모든 프로젝트가 읽는 사용자 전역 지침(Claude Code라면 홈 폴더의 ~/.claude/CLAUDE.md)에 두십시오. Claude Code는 이 파일을 모든 세션이 시작될 때 읽어 들입니다.

자주 묻는 질문

"This request contains scopes that cannot be requested together"는 왜 나오나요?

한 로그인 요청에 함께 넣을 수 없는 스코프 조합이 있어서입니다. 10월 8일에는 drive.file과 youtube.upload가 그 조합이었습니다. drive.file을 빼고 YouTube 스코프만 요청하자 이 400은 사라졌지만, gcloud 기본 로그인으로는 YouTube 스코프가 다시 '차단된 앱'에 걸렸습니다.

GA4 Data API를 서비스 계정으로 읽으려면 키 파일이 꼭 있어야 하나요?

없어도 됩니다. 내 계정에 토큰 생성자 역할을 주고, GA4 계정 액세스 관리에서 서비스 계정을 뷰어로 넣은 뒤 --impersonate-service-account로 토큰을 받으면 됩니다. 이 글의 서비스 계정은 키 파일 없이 10월 15일부터 GA4를 읽었습니다.

2026-11-12 확인. Claude Code 세션 기록(10월 8~25일), 프로젝트 메모리, 대시보드 서버와 게임 저장소의 git 기록.
