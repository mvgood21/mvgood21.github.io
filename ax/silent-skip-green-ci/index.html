조용히 skip되는 테스트가 CI를 초록으로 만든다: 암호 대조 3건과 엿새 동안 고장 난 통합 테스트

필수 테스트의 skip은 CI에서 실패로 바꾸십시오. 암호 대조 테스트 3개는 python 모듈이 없으면 skip이었고, CI에는 설치 단계가 없었습니다.

작성 SugarMount · 검증과 출시 · 읽는 시간 10분 · 최종 업데이트 2026년 11월 8일

flutter test의 skip 수는 2026년 9월 11일, 13일, 15일 모두 13개였습니다. 그 13개 안에는 엿새째 고장 난 릴레이 통합 테스트가 있었고, 13개 밖에는 모듈 하나가 없으면 3개가 더 빠지는 암호 대조 테스트가 있었습니다. 9월 15일 밤 CI에 설치와 확인 단계를 넣어, CI에서 모듈이 없어 그 3개가 조용히 빠지는 길을 막았습니다.

출처: Flutter P2P 채팅 앱 저장소의 git 기록(커밋 b559ba0, 32ce058, cab4bed, 7048e46), CI 설정, 테스트 파일, 9월 15일 E2E 보고서. skip 개수는 커밋 7048e46 시점의 트리에서 다시 세었고, 테스트를 다시 실행하지는 않았습니다. 기준일 2026년 11월 3일.

skip 13개 밖에 있던 암호 대조 3개

커밋 7048e46 시점의 skip: 선언을 다시 세면, 환경 변수나 서버가 없을 때 빠지는 테스트는 소크 9개(BOS_SOAK), 시그널링 서버 통합 2개, DB 벤치 1개, 라이브 2-프로세스 E2E 1개로 13개입니다. 9월 13일 기록의 3,160 passed / 13 skipped는 'E2E 100% 통과'의 정체에서 이미 다뤘고, 9월 15일 교차 검증 문서도 3,186 passed / 13 skipped였습니다.

암호 대조 테스트 3개는 python cryptography 모듈을 찾으면 돌고, 못 찾으면 skip합니다. 9월 15일 개발 기계에는 모듈(50.0.1)이 있어 3개가 모두 돌았고, 9월 11일부터 기록된 skip 수 13은 환경 게이트 13개와 수가 같아, 이 3개가 skip됐다는 흔적은 없습니다.

CI flutter 잡은 sqlite만 설치하고 테스트를 돌렸습니다

이 테스트는 X25519, HKDF, AES-256-GCM과 프레임 형식을 python cryptography로 따로 계산해 앱의 결과와 맞춰 봅니다. 파일 머리 주석에 따르면 양쪽이 같은 식으로 틀린 경우를 잡는 테스트는 이 파일뿐인데, 같은 주석이 모듈이 없을 때를 이렇게 정했습니다.

// External-process dependency: this test SKIPS (it does not fail) when
// `python3 -c "import cryptography"` does not succeed, so it is safe on
// machines and CI images without the module.

9월 15일 전까지 CI의 flutter 잡은 sqlite 말고는 아무것도 설치하지 않고 flutter test를 돌렸습니다. 초록까지의 사슬은 이렇게 이어집니다.

  1. CI 잡은 flutter test의 종료 코드만 봅니다.
  2. 종료 코드는 skip을 실패로 세지 않습니다. skip 수는 결과 줄의 ~N에만 나옵니다.
  3. 테스트는 모듈이 없으면 skip하도록 짜여 있었고, CI에는 모듈을 설치하거나 확인하는 단계가 없었습니다.
  4. skip 수를 기준값과 비교하는 장치가 없어서, 13이 16이 되어도 알릴 곳이 없었습니다.

'안전하다'는 주석과 같은 날 세운 브라우저 가드

이 주석과 테스트는 9월 11일 10시 45분 커밋 b559ba0에 들어갔고, 커밋에는 Claude 공동 작성 표기가 있습니다. 14시 32분 커밋 8f5a0a5(역시 Claude 공동 작성)가 고친 결함은 메시지 축출 가드가 CI가 설정하지 않는 환경 변수 뒤에 있던 것으로, 축출을 꺼도 테스트 659개가 초록이었습니다(이 커밋의 경과는 테스트 3,066개가 초록인데 DB를 못 여는 코드가 숨어 있었다에 있습니다). 8f5a0a5는 CI 웹 단계에 "브라우저가 없으면 크게 실패시킨다"는 가드도 넣었습니다. 네 시간 전에 쓴 암호 대조 테스트의 skip에는 그 원칙이 닿지 않았습니다.

9월 15일 운영자가 E2E가 끝났느냐고 물었고, 확인해 보니 UI 리디자인(9월 13~14일) 뒤로는 한 프로세스 안에서 도는 E2E만 돌고 나머지는 환경 게이트 뒤에서 skip 중이었습니다. 그날 밤 게이트를 하나씩 열었고, 22시 12분 커밋 7048e46이 CI에 이 단계를 넣었습니다.

- name: Ensure python cryptography exists (the crypto cross-check must never silently skip)
  run: |
    python3 -m pip install --quiet --upgrade cryptography || true
    python3 -c 'import cryptography; print("cryptography", cryptography.__version__)' || {
      echo "::error::python cryptography 가 없다 ..."
      exit 1
    }

skip되는 동안 두 규칙과 어긋난 릴레이 테스트

13개 안에 있던 릴레이 통합 테스트는 9월 6일 뒤로 수정이 없었고, 그사이 9월 9일 프로덕션에 두 규칙이 들어왔습니다. 승인 콜백이 연결되지 않으면 메시지를 거부하는 지문 게이트(df1dddc·684ff8c)와, 세션의 방이 아닌 roomId를 가진 프레임을 버리는 방 바인딩(684ff8c·6c99027)입니다. 9월 15일 시그널링 서버를 띄우고 처음 실제로 돌리자 둘 다 걸렸습니다. 승인 콜백 없이 부른 sendMessage는 "Peer identity is not verified yet"로 거부됐고, 'room-relay' 리터럴로 보낸 메시지는 오류 없이 버려졌습니다.

21시 13분 커밋 32ce058은 제품이 맞고 테스트가 뒤처졌다고 판정했습니다. 테스트에 승인 콜백을 넘기고, 핸드셰이크가 묶은 방 이름을 debugSessionRoomId로 꺼내 그 방으로 보내게 고쳤습니다. 방 이름 규칙을 테스트에 베껴 적으면 다음 규칙 변경 때 또 어긋나기 때문입니다. 서버를 띄운 상태에서 test/integration 13개가 모두 통과했습니다.

같은 밤 기기 스모크(에뮬레이터 API 35)도 설정 화면에서 멈췄습니다. tester.pageBack()은 영어 툴팁 'Back'으로 뒤로 버튼을 찾는데, 앱을 한국어로 고정한 뒤 그 툴팁은 "뒤로"였습니다. find.byType(BackButton)으로 바꾸자 2/2가 통과했습니다(cab4bed).

skip 수 비교와 '항상 실패'로는 부족한 이유

아래 두 방법이 부족하다는 판단은 이 글을 쓰며 한 분석이고, 저장소에는 이 판단을 적은 기록이 없습니다. skip 수를 기준값 13과 비교해 다르면 실패시키는 방법은 13이 16이 되는 경우는 잡지만, 릴레이 테스트처럼 늘 skip되는 테스트가 고장 나는 것은 못 잡습니다(기록이 남은 세 날 모두 13). 모듈이 없으면 실패하도록 테스트를 바꾸면 모듈 없는 개발 기계에서 전체 스위트가 빨개지는데, 처음 주석은 바로 이 경우를 피하려고 skip을 골랐습니다. 저장소가 넣은 것은 CI 단계 가드였고, 커밋은 웹 잡의 브라우저 가드와 같은 방식이라고 적었습니다.

시그널링 서버를 CI에서 띄워 통합 테스트까지 돌리는 길도 있었지만 택하지 않았고, 그 이유는 기록에 없습니다. 대신 CI가 돌리지 않는 세 종류(라이브 2-프로세스, 시그널링 통합, 기기 스모크)의 명령을 배포 문서 4.1.1절에 올려 릴리스 전에 사람이 한 번 돌리게 했습니다.

GitHub Actions는 모든 실행에 환경 변수 CI=true를 넣으므로, 테스트가 이 값을 보고 CI에서는 skip하지 않으면 전제가 빠진 순간 그 자리에서 빨개지고 개발 기계의 동작은 그대로입니다. 저장소에서 실행해 보지 않은 제안입니다.

final onCi = Platform.environment['CI'] == 'true';

test('python cryptography 와의 양방향 교차 검증', () async {
  // ...
}, skip: onCi ? false : skipReason);

이 분기는 dart:io를 쓰므로 브라우저에서 도는 테스트에는 넣을 수 없습니다. 이 저장소의 웹 단계는 test/web/만 브라우저로 돌려 암호 대조 파일과는 겹치지 않습니다.

CI 가드가 보지 않는 skip 경로와 없는 실행 기록

7048e46의 가드는 python3 실행과 모듈 import만 확인합니다. 테스트의 skip 경로는 셋인데, 그중 스크립트 경로 하나인 "tool/crypto_vectors/cross_check.py를 현재 폴더와 그 위 4단계 안에서 찾지 못함"은 가드 밖에 있습니다. CI는 저장소 루트에서 돌아 지금은 스크립트를 찾지만, 이 경로를 막아 둔 장치는 없습니다.

이 저장소에는 CI flutter 잡의 실행 결과가 남아 있지 않고, 배포 문서도 CI의 웹 단계는 이 환경에서 돌릴 수 없어 "CI가 초록"인지 아직 증명되지 않았다고 적습니다. 그래서 CI에서 이 3개가 실제로 skip된 적이 있는지는 확인하지 못했습니다. 7048e46 뒤로는 설치를 시도한 뒤에도 모듈을 불러오지 못하면 CI 잡이 exit 1로 끝납니다.

필수 skip을 찾아 실패로 바꾸는 4단계

  1. grep -rn "skip:" test/와 grep -rn "markTestSkipped" test/로 모두 찾습니다(skip 수를 결과에 같이 적는 이유는 'E2E 100% 통과'의 정체에 있습니다). 선언 줄 수는 실제 skip 수와 다릅니다. 이 앱의 skip: 17줄은 조건부 암호 대조 3줄, 웹에서만 skip되고 VM에서는 도는 1줄, 헬퍼 매개변수 1줄을 빼고 릴레이 group 1줄을 테스트 2개로 세어야 13이 되고, markTestSkipped 6곳은 실행해야 압니다.
  2. 줄마다 필수인지 적습니다. 필수는 다른 테스트가 대신 잡지 못하는 것이고, 독립 구현과의 대조나 실제 서버 경로가 여기에 듭니다.
  3. 필수 테스트는 CI에서 전제를 설치하고 확인하는 단계를 두거나, 위 코드처럼 CI=true에서는 skip하지 않게 합니다. 이 앱의 가드에서는 설치가 실패하고 모듈도 없으면 확인 명령에서 CI가 빨개집니다.
  4. CI에서 못 도는 테스트는 릴리스 전 수동 목록에 명령과 마지막 실행 날짜를 적어 놓습니다. 오래 skip된 테스트를 다시 돌려 실패가 나오면 테스트 쪽이 뒤처졌는지부터 봅니다. 이 앱에서는 고장 3건이 모두 그랬습니다.

남은 일: 테스트 파일의 skip 조건과 2대 기기 E2E

암호 대조 테스트 파일은 9월 11일 뒤로 바뀌지 않아 지금도 모듈이 없으면 skip합니다. CI=true 분기를 넣은 뒤 GitHub Actions에서 skip 수가 개발 기계와 같은지 보는 일이 남았습니다. 두 대의 기기로 도는 자동 E2E도 아직 없습니다.

자주 묻는 질문

flutter test에서 skip된 테스트가 있으면 CI가 실패하나요?

실패하지 않습니다. skip은 실패로 세지 않아 종료 코드가 0이고, 수는 결과 줄의 ~N으로만 보입니다. 이 앱의 기록도 13 skipped인 실행을 0 failed로 적었습니다.

GitHub Actions에서 python 모듈이 없으면 단계를 실패시키려면 어떻게 하나요?

설치한 뒤 python3 -c 'import 모듈'을 실행하고, 실패하면 ::error::를 출력하고 exit 1로 끝냅니다. 설치 명령에는 || true를 붙여도 되지만 확인 명령에는 붙이지 않습니다.
