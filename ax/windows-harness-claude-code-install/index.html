Claude Code Windows 설치부터 첫 실행까지: PowerShell 한 줄과 예약용 설정 폴더

Claude Code는 PowerShell 명령 한 줄로 관리자 권한 없이 설치되고, 예약 작업에 쓸 로그인은 대화용과 다른 설정 폴더에 따로 둡니다.

작성 SugarMount · 에이전트와 일하는 법 · 읽는 시간 12분 · 최종 업데이트 2026년 11월 11일

Windows 하네스 연재 2/5 · 이전 편 하네스가 무엇이고 무엇을 맡는지 · 다음 편 Docker Desktop 설치

이 편을 따라 하면 PowerShell 창에서 Claude에게 질문을 한 줄로 보내고 답을 받는 데까지 갑니다. 설치에는 관리자 권한이 필요 없고, 2026년 11월 11일 하네스를 돌리는 PC의 새 PowerShell 창에서 버전 확인과 첫 질문을 같은 명령으로 다시 돌려 확인했습니다.

마지막 단계에서는 예약 작업 전용 설정 폴더를 하나 더 만듭니다. 대화용과 같은 설정 폴더를 쓰던 예약 작업이 로그인 덮어쓰기로 멈춘 일이 있어서 설치 편에 넣었습니다.

PowerShell 창을 열고 명령을 붙여 넣는 법

PowerShell은 Windows에 처음부터 들어 있는 명령 창입니다. 작업 표시줄의 시작 버튼을 누르고 PowerShell이라고 치면 검색 결과에 Windows PowerShell이 나옵니다. 이 편의 명령은 모두 관리자 권한 없이 실행하므로 "관리자 권한으로 실행"은 고르지 않습니다(관리자 창은 3편에서 한 번 씁니다).

화면 설명: 창이 열리면 줄 맨 앞에 PS로 시작하는 글자와 지금 폴더 이름이 보이고, 그 끝에서 커서가 깜빡입니다. 줄이 PS로 시작하지 않으면 PowerShell이 아니라 명령 프롬프트(CMD) 창입니다. 두 창은 받는 명령이 달라서, 이 글의 오류 대부분이 여기서 나옵니다.

이 글의 회색 상자에 있는 명령은 상자 안 글자를 드래그해 복사(Ctrl+C)하고, PowerShell 창을 한 번 누른 뒤 Ctrl+V로 붙여 넣고 Enter를 칩니다.

Claude Code 공식 설치 문서가 적은 조건은 Windows 10 1809 이상 또는 Windows 11, 메모리 4GB 이상, x64 또는 ARM64 PC, 인터넷 연결입니다.

Git for Windows는 권장, Python은 5편 준비

Git for Windows는 필수는 아니고 권장입니다. Claude Code는 명령을 실행할 때 창 종류를 하나 골라 쓰는데, 공식 문서에 따르면 Git for Windows가 있으면 Git Bash를 쓰는 Bash 도구를, 없으면 PowerShell 도구를 씁니다. "Git for Windows"로 검색해 공식 배포 페이지의 설치 프로그램을 받고, 화면 안내를 따라 진행합니다.

Python은 이 편과 4편의 최소 하네스에는 필요 없습니다. 실제 하네스의 GA4·AdMob 보조 스크립트가 Python입니다(5편). 4편 키트만 쓴다면 건너뛰어도 됩니다. python.org의 Windows 설치 프로그램을 쓴다면 설치 첫 화면 아래쪽의 "Add python.exe to PATH"에 체크하고 진행합니다.

둘 다 설치한 뒤에는 PowerShell 창을 새로 열고 아래 두 줄로 확인합니다. 11월 11일 이 PC에서는 git version 2.45.2.windows.1과 Python 3.12.3이 나왔습니다. 버전 숫자가 아닌 글이 나오면 설치가 끝나지 않은 것입니다.

git --version
python --version

설치 명령은 PowerShell 판으로 고릅니다

공식 문서는 설치 방법 세 가지를 적고 있습니다. PowerShell 명령은 PowerShell 창에, CMD 명령은 명령 프롬프트 창에 넣고, 셋은 업데이트 방식이 다릅니다.

방법업데이트
PowerShell 설치 명령(문서 권장)백그라운드에서 자동
CMD 설치 명령백그라운드에서 자동
WinGet자동 아님, winget upgrade Anthropic.ClaudeCode로 직접

PowerShell 판으로 설치하십시오. 예약 작업은 사람이 보지 않는 시간에 돌기 때문에 업데이트를 손으로 챙겨야 하는 WinGet보다 자동 업데이트가 맞고, 이 글의 나머지 명령도 모두 PowerShell 창에서 넣습니다.

irm https://claude.ai/install.ps1 | iex

화면 설명: Enter를 치면 설치가 진행됩니다. PS 줄이 다시 나타날 때까지 기다리고, 그 위에 Setup notes:로 시작하는 경고가 있는지 봅니다. 명령 프롬프트 창을 쓰고 있다면 아래 CMD 판을 씁니다. 창을 잘못 골랐을 때 나오는 오류 원문은 글 끝 질문 모음에 있습니다.

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

Setup notes 경고가 나오면 PATH에 폴더 하나를 더합니다

PATH는 Windows가 명령 이름을 듣고 실행 파일을 찾아보는 폴더 목록입니다. 설치 프로그램은 claude.exe를 %USERPROFILE%\.local\bin(내 사용자 폴더 아래 .local\bin)에 두지만 PATH는 바꾸지 않고, 대신 Setup notes: 경고로 알려 줍니다. 이 경고를 보았다면 아래 두 줄을 차례로 넣습니다. 내 사용자 계정의 PATH 끝에 그 폴더를 붙이는 명령입니다.

$currentPath = [Environment]::GetEnvironmentVariable('PATH', 'User')
[Environment]::SetEnvironmentVariable('PATH', "$currentPath;$env:USERPROFILE\.local\bin", 'User')

새 PATH는 이미 열려 있는 창에는 들어가지 않습니다. PowerShell 창을 닫고 새로 연 뒤 확인합니다.

claude --version
claude doctor

첫 줄은 버전을 찍습니다. 이 PC에서는 2.1.322 (Claude Code)였습니다. claude doctor는 대화 세션을 열지 않고 설치와 설정 상태를 진단하는 명령이라, 버전은 나오는데 뭔가 이상할 때 먼저 돌려 봅니다.

이 글과 비슷한 문제를 겪고 있다면 메일로 상황을 알려 주세요. 읽고 답하겠습니다. 메일로 문의하기

첫 로그인은 유료 요금제 계정으로 합니다

Claude Code를 쓰려면 Pro, Max, Ultra, Team, Enterprise 요금제나 Console 계정(개발자용 Console 계정에 미리 충전한 API 이용료)이 있어야 합니다. 무료 claude.ai 요금제에는 Claude Code가 들어 있지 않으니, 무료 계정만 있다면 이 연재는 여기서 더 나갈 수 없습니다.

하네스 파일을 둘 폴더를 먼저 만들고, 그 폴더에서 claude를 실행합니다. $HOME은 내 사용자 폴더를 뜻합니다. 4편의 최소 하네스도 이 harness 폴더를 씁니다. mkdir를 넣으면 새 폴더 정보가 표로 한 번 찍히는데, 정상입니다.

mkdir $HOME\harness
cd $HOME\harness
claude

처음 실행하면 로그인 안내가 나오고, 브라우저에서 계정 인증을 합니다. 그 사이에 나오는 선택 화면은 공식 문서가 하나씩 적고 있지 않아 여기서도 묘사하지 않습니다. 화면 안내를 따라 진행하고, 로그인이 끝나 대화 화면이 열리면 창을 닫아도 됩니다. 로그인 정보는 대화용 설정 폴더에 남습니다.

claude -p로 보낸 첫 질문과 한글 깨짐

헤드리스 실행은 대화 화면을 띄우지 않고 claude -p로 일을 한 번 시키고 끝내는 방식입니다. 하네스에서 Claude가 판단하는 예약 작업은 모두 이 방식으로 돕니다. 질문은 명령 뒤에 따옴표로 붙여도 되지만, 하네스는 질문을 표준 입력(앞 명령의 출력을 |로 넘겨받는 통로)으로 넣습니다. 하네스를 만들 때 질문을 명령 뒤에 붙였더니 --allowedTools(자동으로 허용할 도구 목록) 다음에 놓인 질문이 도구 이름으로 읽혀 들어간 일이 있었기 때문입니다.

$OutputEncoding = [System.Text.Encoding]::UTF8
echo '게임 앱 광고 지표 CPI를 한 문장으로 설명해 줘.' | claude -p --model haiku

첫 줄 $OutputEncoding은 이 창에서 다른 프로그램으로 넘기는 글자를 UTF-8(한글을 포함한 글자를 컴퓨터가 저장하는 방식)로 정합니다. Windows에 들어 있는 Windows PowerShell 5.1은 기본 설정에서 파이프로 넘기는 한글이 물음표가 됩니다. 11월 11일 새로 연 Windows PowerShell 창에서는 '게임'이 ??로 넘어갔고, 이 줄을 먼저 넣자 제대로 넘어갔습니다. 한글 질문을 넣을 창에서는 이 줄을 항상 먼저 넣으십시오. 답 앞뒤의 별표 두 개는 Claude가 굵은 글씨 표시로 붙인 기호가 그대로 찍힌 것입니다.

--model은 모델을 고릅니다. 하네스는 판단이 많은 데일리 작업에 opus, 정해진 화면 조작에 sonnet, 자가 점검에 가장 가벼운 haiku를 쓰고, 기본값이 바뀌어도 흔들리지 않게 작업마다 모델을 적습니다. 끝난 뒤 아래 줄을 넣으면 종료 코드(프로그램이 끝나며 남기는 숫자)가 나옵니다. 0이 찍히면 성공입니다. 4편의 러너(예약 작업을 실제로 돌리는 스크립트)는 이 숫자로 성공과 실패를 가립니다.

$LASTEXITCODE

헤드리스 실행에서는 아무도 승인 버튼을 누르지 않습니다. 파일 수정처럼 승인이 필요한 도구는 --allowedTools에 적지 않으면 거부됩니다.

예약 작업은 전용 설정 폴더에서 따로 로그인

Claude Code는 로그인 정보, 설정, 개인 지침 파일을 사용자 폴더의 .claude 폴더와 .claude.json에 둡니다. 환경 변수 CLAUDE_CONFIG_DIR에 다른 폴더의 절대 경로를 넣으면 이것들이 모두 그 폴더로 갑니다. 하네스는 예약 작업에 이 폴더를 따로 줍니다.

2026년 9월 10일, 하네스를 지금 Windows 구성으로 옮기기 전의 일입니다(옮긴 과정은 WSL을 접고 Windows 네이티브로: Claude Code 개발 환경 이전 체크리스트에 있습니다). 대화 창에서 /login으로 계정을 바꾸자 같은 설정 폴더를 쓰던 예약 작업의 인증이 덮어써졌고, 예약 작업은 다시 인증할 수 없어 멈췄습니다.

11월 11일 이 연재를 준비하며 4편 키트의 hello 작업을 선택 칸인 configDir를 비워 둔 채 돌리자, 답 끝에 지시문에 없는 "한 일 / 결과 / 남은 일(사용자 몫)" 형식이 붙었습니다. 같은 설정 폴더의 대화용 개인 지침 파일(전역 CLAUDE.md)이 작업을 마치면 그 형식으로 요약하라고 적고 있었습니다. 폴더를 나눠 둔 실제 하네스도 이 덧붙임을 피하지 못했습니다. 전용 폴더의 지침 파일에 같은 줄이 복사돼 있었고, 11월 10일 게임 소셜 작업의 답도 이 요약으로 끝났습니다. 예약 작업은 전용 폴더에 둔 지침을 따르므로, 그 지침은 예약 작업에 맞게 따로 관리해야 합니다(4편).

예약 작업은 처음부터 전용 설정 폴더로 돌리고, 대화용 지침 파일은 그 폴더에 복사하지 마십시오. 폴더를 나누는 주된 이유는 9월 10일 같은 로그인 덮어쓰기입니다. 만드는 법은 환경 변수를 그 창에만 정하고 claude를 실행하는 것입니다. 앞의 첫 로그인과 같은 안내가 나오면 그대로 따르고, 대화 화면이 바로 열리면 /login을 넣습니다.

$env:CLAUDE_CONFIG_DIR = "$env:USERPROFILE\.claude-harness"
claude

$env:로 정한 값은 이 창을 닫으면 사라집니다. 그래서 대화용 Claude는 원래 폴더를 계속 쓰고, 예약 작업은 4편 작업 정의 파일의 configDir 칸에 이 폴더를 적어서 씁니다. 전용 폴더에는 대화용에서 연결해 둔 기능이 일부 따라오지 않습니다(5편에서 다룹니다).

다음 편 전에 확인할 것

새 PowerShell 창에서 claude --version이 버전을 찍고, 첫 헤드리스 질문이 답과 종료 코드 0을 돌려주고, 전용 폴더 로그인까지 끝났다면 이 편은 끝입니다. WinGet으로 설치했다면 업데이트 명령을 언제 돌릴지 정해 두십시오. 4편 방식으로 등록한 예약 작업은 Windows에 로그온해 있는 동안만 돌기 때문에, PC를 켜 두고 로그온 상태로 둘 수 없다면 이 구성은 맞지 않습니다.

다음 편 Docker Desktop 설치는 데이터를 매일 모아 두는 서버를 돌릴 때 필요한 준비입니다. 최소 하네스만 먼저 돌려 보려면 3편을 건너뛰고 4편 작업 스케줄러 등록으로 가도 됩니다.

자주 묻는 질문

'irm' is not recognized 오류가 납니다.

PowerShell용 설치 명령을 명령 프롬프트(CMD) 창에 넣은 경우입니다. 시작 메뉴에서 PowerShell을 열어 다시 넣거나, 그 창에서는 CMD용 curl 명령을 씁니다.

The token '&&' is not a valid statement separator 오류는 무엇인가요?

반대로 CMD용 설치 명령을 PowerShell 창에 넣은 경우입니다. PowerShell 창에서는 irm https://claude.ai/install.ps1 | iex를 씁니다.

설치는 끝났는데 claude 명령을 찾지 못합니다.

PATH에 %USERPROFILE%\.local\bin이 없어서입니다. 위 PATH 절의 두 줄을 넣고, 창을 새로 연 뒤 claude --version을 다시 칩니다.
