AX 노트 · 연재

디버그에서는 멀쩡한 R8 릴리스 빌드 결함 4가지

디버그에서 멀쩡하던 앱이 2026년 9월 23일 R8을 거친 릴리스 빌드에서 실행 직후 죽은 뒤, 같은 종류의 결함 넷을 찾아 막은 기록입니다.

4편

이 연재에서 알게 된 것

  • 2026년 9월 23일, R8이 생성자 하나를 지우는 바람에 사진 용량 줄이기의 모든 릴리스 빌드가 시작 직후 죽었습니다. 그때까지 출시용 빌드를 기기에서 실행해 본 적이 없었고, 지금은 업로드 전마다 세 단계 점검을 거칩니다. (1편: 출시 전 점검)
  • @SerializedName이 없는 Gson 필드 output과 etype이 a와 b로 바뀌어, 예외 없이 빈 값이 나올 결함이 생겼습니다. 단위 테스트 203개는 R8을 거치지 않은 클래스로 돌아 이를 보지 못했습니다. (2편: Gson 필드 이름)
  • 실제 광고 ID로 만든 한판블록 AAB의 dex에 Google 테스트 광고 문자열 5개가 남았습니다. listOf(...).any로 묶은 조건을 R8이 빌드 때 계산하지 못했고, 상수끼리 ||로 쓰자 0개가 됐습니다. (3편: 테스트 광고 ID)
  • -dontoptimize를 지운 뒤에도 Play Console 지표는 최적화 36%, 난독화·축소 39%였습니다(2026-09-25). 앱이 쓰지 않는 Kakao SDK keep 규칙을 지우자 r8.json 기준 85%가 됐고 AAB는 11.6MB가 됐습니다. (4편: keep 규칙)

Android 앱을 R8(출시 빌드의 코드 축소 도구)과 함께 내는 개발자, 특히 AI 코딩 에이전트가 쓴 코드를 출시하는 경우에 맞는 연재입니다. 1편의 세 단계 점검을 먼저 읽고, Gson처럼 리플렉션을 쓰는 라이브러리가 있다면 2편, 광고를 넣었다면 3편, Play Console의 DEX 최적화 수치가 낮다면 4편으로 가십시오. 네 편의 결함은 모두 디버그 빌드나 단위 테스트에서는 드러나지 않았고, 릴리스 산출물을 기기에서 실행하거나 dex를 직접 열어 봐야 보였습니다.

연재 목차

  1. 1편바이브코딩 앱 출시 전 점검: 안드로이드 릴리스 빌드와 R8 크래시

    2026년 10월 18일

    AI로 만든 안드로이드 앱이 디버그에서는 멀쩡하다가 R8 때문에 출시용 빌드에서 실행 직후 죽었습니다.

  2. 2편단위 테스트 203개가 놓친 릴리스 전용 빈 값: R8과 Gson 필드 이름

    2026년 11월 7일

    R8이 Gson 필드 output과 etype을 a와 b로 바꿔 릴리스에서만 빈 값이 나올 결함이 생겼습니다.

  3. 3편R8이 지우지 못한 테스트 광고 ID 5개: listOf().any 한 줄과 dex 건수 검사

    2026년 10월 29일

    실제 광고 ID로 만든 한판블록 AAB의 dex에 테스트 광고 문자열 5개가 남았습니다.

  4. 4편Play Console 'DEX 최적화 39%'의 범인: 쓰지도 않는 Kakao SDK keep 규칙

    2026년 10월 20일

    -dontoptimize를 빼도 Play Console DEX 지표는 36~39%였습니다.
