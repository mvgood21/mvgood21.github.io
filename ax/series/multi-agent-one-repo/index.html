에이전트 여럿을 한 저장소에서: 병렬 작업이 부딪힌 자리

2026년 10월 3일, 에이전트 수백 개를 허락받고도 클로드 코드에서 코드를 쓰는 에이전트는 동시에 3개만 돌았습니다. 그 한도와 충돌을 6편에 적었습니다.

6편

이 연재에서 알게 된 것

  • 2026년 10월 3일 커밋은 59개였지만 코드를 쓰는 에이전트는 동시에 최대 3개였습니다. 상한을 정한 것은 에이전트 수가 아니라 여유 메모리 4GB와 공용 테스트폰 2대였습니다. (1편: 동시 실행은 3개)
  • 사용 한도로 끊긴 서브에이전트 5건(9월 7~10일)이 먼저 만들어 둔 보고서는 대부분 빈 절이었습니다. 이어받기를 살린 것은 작업 중에 저절로 남은 로그, 스크린샷, 고친 파일이었습니다. (2편: 서브에이전트 브리프)
  • 같은 작업 트리에서 출시 수정 커밋 하나가 다른 세션이 만들던 파일 50개를 담아 갔습니다(9월 23일). 공유 파일마다 주인을 적는 표를 쓴 뒤에도 머지 13개 중 7개는 손으로 합쳤지만, 어디서 날지는 미리 알 수 있었습니다. (3편: 파일 주인 표)
  • 리뷰와 CI를 통과한 브랜치 13개를 합친 뒤 통합본만 다시 읽자 확정 결함 12건이 나왔고, 그중 10건은 두 패키지 사이의 약속이 어긋난 것이었습니다. (5편: 통합 리뷰)
  • 배포 전 검토에서 에이전트 84개를 돌리고 발견마다 다른 에이전트 3명이 반박하게 해, 버틴 20건만 고쳤습니다. 그중 1건은 앱이 죽는 결함이었고, 고친 뒤 교차 리뷰의 새 확정은 0건이었습니다. (6편: 반박 리뷰)

클로드 코드(Claude Code)로 서브에이전트나 세션 여러 개를 한 저장소에서 돌리는 개발자에게 맞는 연재입니다. 몇 개를 띄울지 정하는 중이면 1편, 서브에이전트에게 줄 지시문을 쓰는 중이면 2편, 이미 세션끼리 파일이 섞였다면 3편부터 읽으십시오. 4편은 여러 세션이 고치는 정적 사이트에서 커밋 전 --check 하나로 합친 결과를 지킨 기록이고, 5편과 6편은 병렬로 만든 코드를 리뷰하는 두 방식이라 이어 읽으면 좋습니다.

연재 목차

  1. 1편클로드 코드 병렬 에이전트: 작업 10개, 동시 실행은 3개였다

    2026년 10월 21일

    클로드 코드 에이전트를 수백 개 써도 된다고 했지만 코드를 쓰는 에이전트는 동시에 3개만 돌았습니다.

  2. 2편클로드 코드 서브에이전트 프롬프트 규칙: 한도로 끊긴 5건

    2026년 11월 2일

    클로드 코드 서브에이전트가 사용 한도로 끊기면 먼저 만들어 둔 보고서는 거의 비어 있습니다.

  3. 3편클로드 코드 여러 세션 동시 작업: 공유 파일마다 주인을 정한 표

    2026년 10월 29일

    같은 작업 트리의 커밋 하나가 다른 클로드 코드 세션 파일 50개를 담아 간 뒤 공유 파일 주인 표를 만들었습니다.

  4. 4편여러 AI 에이전트가 함께 고치는 정적 사이트: 커밋 전 --check 하나로 지키기

    2026년 10월 25일

    여러 AI 에이전트 세션이 고치는 정적 사이트에서 커밋 전 --check로 재빌드 변경 0개와 검사 오류 0건을 확인합니다.

  5. 5편브랜치마다 AI 리뷰를 통과해도 합친 코드에는 결함이 남습니다: 통합 리뷰가 찾은 12건

    2026년 11월 1일

    리뷰와 CI를 통과한 브랜치 13개를 합친 뒤 통합본만 다시 리뷰하자 확정 결함 12건이 나왔습니다.

  6. 6편AI 코드 리뷰 지적, 반박을 버틴 20건만 고쳤다

    2026년 10월 22일

    AI 에이전트 리뷰는 반박을 버틴 발견만 셉니다.
