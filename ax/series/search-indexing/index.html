이 사이트를 검색에 올리기: 사이트맵, 서치콘솔, 구조화 데이터

서치콘솔 사이트맵이 열흘 동안 '가져올 수 없음'이던 때도 Googlebot은 파일을 정상으로 가져갔고, 새 도메인 속성에서는 제출 7초 안에 처리됐습니다.

3편

이 연재에서 알게 된 것

  • 2026년 10월 18일 커밋 하나 뒤로 sitemap.xml의 URL 51개가 모두 같은 lastmod를 가졌습니다. 수정일을 커밋 날짜 대신 본문 해시가 달라진 날로 계산하자, 다음 날 HTML 99개를 고친 커밋에서도 수정일이 바뀐 기존 페이지는 6개였습니다. (1편: 본문 해시 lastmod)
  • 화면의 '가져올 수 없음'은 API에서 isPending=True, lastDownloaded 없음이었습니다. 10월 25일 URL 검사의 실제 테스트에서 Googlebot은 그 파일을 정상으로 가져갔고, 같은 날 Bing도 sitemap.xml을 처리했습니다. (2편: '가져올 수 없음' 열흘)
  • 10월 31일 맞춤 도메인으로 옮겨 새 도메인 속성에 같은 사이트맵 4개를 내자 제출 7초 안에 모두 처리됐습니다. 기다린 열흘 동안 색인은 직접 요청한 URL로 늘었고, 이전 뒤 요청 7건 중 5건은 4시간 안에 색인됐습니다. (2편)
  • Google은 2026년 5월 7일, 네이버는 7월 9일에 FAQ 리치 결과를 끝냈습니다. 이 사이트 HTML 173개 중 106개에 FAQPage JSON-LD가 있지만(10월 27일 집계) 리치 결과는 0이고, 지우지도 늘리지도 않기로 했습니다. (3편: FAQ 종료 뒤 구조화 데이터)

프레임워크 없이 정적 사이트를 운영하며 검색 노출을 처음 챙기는 개발자에게 맞는 연재입니다. 서치콘솔에 '가져올 수 없음'이 떠 있다면 2편부터, 사이트맵을 직접 생성한다면 1편, FAQ 마크업이나 AI 검색(GEO)용 마크업을 고민한다면 3편을 읽으십시오. 세 편 모두 노출이 거의 없던 시기의 기록이라, 순위가 얼마나 올랐는지가 아니라 검색엔진이 무엇을 읽고 무엇을 무시했는지를 다룹니다.

연재 목차

  1. 1편사이트맵 lastmod가 전부 같은 날짜였다: 본문 해시로 수정일 정하기

    2026년 10월 20일

    사이트맵 URL 51개의 lastmod가 모두 같은 날이었습니다.

  2. 2편서치콘솔 사이트맵 '가져올 수 없음' 열흘: 새 도메인 속성에서는 몇 초 만에 처리

    2026년 11월 2일

    서치콘솔 사이트맵이 '가져올 수 없음'이던 열흘, API는 isPending=True였고 Googlebot은 파일을 정상으로 가져갔습니다.

  3. 3편FAQ 리치 결과가 끝난 뒤의 구조화 데이터: GEO용으로 무엇을 남겼나

    2026년 10월 28일

    Google은 2026-05-07, 네이버는 07-09에 FAQ 노출을 끝냈습니다.
