클로드 코드로 안드로이드 앱 개발: Play 출시까지 지킨 규칙과 숫자

클로드 코드로 20일에 앱 4개를 Play에 냈지만, 결과를 가른 것은 코드 속도가 아니라 출시용 빌드를 기기에서 확인하는 규칙이었습니다.

  • 게임 개발

클로드 코드(Claude Code)로 안드로이드 앱을 만들면 혼자서도 Google Play 출시까지 갑니다. SugarMount는 2026년 9월 20일부터 20일 동안 앱 4개를 공개했고, 그 기간 커밋 59개 중 52개(88%)를 클로드 코드와 함께 썼습니다.

속도는 다음 앱을 스크립트로 찍어 내고, 출시 전 검사와 Play Console 작업을 스크립트로 바꾼 데서 나왔습니다. 발목은 늘 같은 자리에서 잡혔습니다. 디버그 빌드와 단위 테스트는 통과했는데, 코드를 줄인 출시용 빌드나 처음 설치한 기기에서 앱이 죽었습니다. 아래 규칙은 모두 그런 사고 뒤에 생겼습니다.

출시까지 지킨 규칙 6가지

  1. 출시용 빌드를 기기에서 두 번 띄운 뒤에만 올립니다. 2026년 9월 23일, 코드 축소 도구 R8이 생성자 하나를 지워 첫 앱의 릴리스 빌드가 모두 시작 직후 죽었고, 디버그에서는 재현되지 않았습니다. 지금은 릴리스 게이트, 축소된 빌드 콜드 스타트 두 번, 실기기 E2E를 거쳐야 올립니다(AI가 만든 앱 출시 전 점검과 R8 크래시).
  2. R8 결과는 리뷰가 아니라 산출물로 셉니다. 맞춤법 앱은 단위 테스트 203개가 모두 통과한 채 릴리스 빌드에서만 교정문이 빈 값이 될 상태였습니다(R8 Gson SerializedName 릴리스 빈 값). 퍼즐 게임은 조건 한 줄의 모양 때문에 출시 AAB에 테스트 광고 문자열 5개가 남았고, 리뷰 에이전트가 낸 19건에는 이 문제가 없었습니다(R8이 남긴 테스트 광고 ID 5개).
  3. 앱 데이터를 지운 상태에서 몽키를 돌립니다. 에이전트가 "실행 시간 857ms, 크래시 없음"이라고 보고하고 4분 뒤, 운영자가 튜토리얼 첫 탭에서 게임이 꺼진다고 알려 왔습니다. 진동 권한이 빠져 있었고, 데이터를 지운 뒤 돌린 몽키가 800회 중 15번째 이벤트에서 잡았습니다(VIBRATE 권한 크래시와 신규 설치 몽키 테스트).
  4. Gradle 빌드는 작업 공간 하나에서 한 번에 하나만 돌립니다. 에이전트 수백 개를 써도 된다고 한 날에도 코드를 고치는 에이전트는 동시에 3개가 최대였습니다. 메모리 13GB 중 여유가 4GB였고 테스트폰은 2대였습니다(AI 에이전트 병렬 개발: 동시 실행은 3개였다).
  5. 실기기 E2E는 심사 제출 전에 합니다. 세 사진 앱을 심사에 넣은 뒤 Galaxy S21·S20에서 E2E를 돌리자 에뮬레이터와 단위 테스트가 놓친 major 결함 9건이 나왔습니다(AI 에이전트로 20일에 Android 앱 4개 출시).
  6. minSdk 기기에서 릴리스 빌드를 띄우기 전에는 검증을 마쳤다고 쓰지 않습니다. 공용 모듈의 java.time 한 줄이 게임 두 개를 Android 7에서 2주 동안 죽였습니다. 커밋에 남은 "몽키 3x1500, 치명 오류 0"은 Android 15 기기의 결과였습니다(Android 7 실행 즉시 크래시와 java.time).

여섯 규칙 모두 에이전트의 "완료"를 받기 전에, 어느 기기에서 어떤 빌드로 무엇을 확인했는지 묻는 일입니다. R8 사고 네 편은 릴리스 빌드에서만 나는 결함(R8) 연재로 묶었습니다.

어디서 막혔나

  • Play 단계적 출시: 20%로 내보내려던 맞춤법 앱 1.6.029가 스크립트의 인자 개수 조건 하나 때문에 전체 사용자 대상으로 커밋됐고, 35초 뒤 되돌리려는 요청은 HTTP 403으로 거부됐습니다(Play 단계적 출시 20%가 100%로 나갔다).
  • 16KB 페이지 요건: NDK를 27·29로 올린 사진 영상 앱 빌드가 사진 전환에 파란 색조를 냈습니다. 다시 재 보니 NDK 25에서도 링커 플래그 한 줄이면 됐습니다.
  • 광고 SDK: 단위 테스트 243개가 통과하고 4분 뒤, 백그라운드 스레드에서 온 전면 광고 콜백이 화면을 옮기다 사진 앱을 죽였습니다(GMA Next-Gen 전면 광고 콜백 스레드 크래시).
  • 검사 도구: 화면을 기다리는 스크립트가 시간 초과에도 성공으로 끝나, 뒤의 검사가 엉뚱한 화면에서 돌았습니다. AdMob 앱 생성 API는 403을 돌려줘서 광고 단위는 콘솔에서 사람이 만듭니다.

클로드 코드에 무엇을 맡기고 무엇을 남겼나요?

에이전트는 Kotlin 코드와 단위 테스트, 빌드·출시·QA 스크립트, 스토어 설명 초안과 스크린샷, 기기 테스트 보고서를 맡았습니다. 사람은 광고 배치·가격 같은 결정, Play Console에서만 되는 작업, 실기기 연결과 최종 확인, 출시 결정을 맡았습니다. 틀리기 쉬운 규칙은 지침 파일의 문장으로 두지 않고 빌드를 막는 테스트로 만들었습니다.

시작하기 전에: 스택 고르기

  • 플러터 vs 네이티브 1인 개발 선택 기준: 플랫폼 기능에 몰린 유틸리티는 Kotlin으로, 같은 화면을 세 번 쓰는 가족 앱은 실패 조건을 붙인 2주 Flutter 스파이크로 정한 근거.

출시용 빌드에서만 나는 문제

  • R8 Gson 릴리스 빈 값: 예외 없이 값만 비는 결함을 mapping.txt와 dexdump로 찾는 순서.
  • 테스트 광고 ID와 dex 건수 검사: 값을 출력하지 않고 출시물의 광고 ID를 세는 명령.
  • 광고 없는 앱의 릴리스 게이트: 의존성 그래프만 보던 게이트가 Firebase가 병합 매니페스트에 다시 넣은 AD_ID를 놓쳐 두 검사를 한 작업에 건 기록.
  • DEX 최적화와 keep 규칙: 쓰지 않는 keep 규칙 하나를 지우자 축소율이 39%에서 85%로 오른 기록.
  • Android 7 크래시와 java.time: 공용 모듈까지 보는 lint 게이트와 API 24 에뮬레이터.
  • 16KB 페이지 NDK 대응과 파란 색조: NDK를 올리기 전에 링커 플래그부터 재 보는 이유.
  • assets .gz가 안 열리는 이유: 빌드가 이름 끝의 .gz를 떼어 기기에서 파일을 못 찾은 일.

수명 주기와 저장

  • 스플래시 멈춤과 리스너: onStop에서 지워지는 리스너로 생긴 멈춤.
  • androidx.pdf 격리 프로세스의 함정: 격리 프로세스에서도 도는 Application.onCreate와 첫 줄 가드.
  • PDF 저장 취소와 SAF 빈 파일: 저장 중 BACK을 일곱 시점에 눌러 빈 파일이 남는지 확인한 방법.

화면과 글자

  • Compose 한글 줄바꿈: 음절 사이에서 끊기는 한글을 공용 TextStyle 한 곳에서 고친 방법.
  • 한글 빈칸과 cmap 8,693자: 폰트가 없는 글자를 가진 척할 때 생기는 빈칸.
  • 테마 색이 다이얼로그로 새는 자리 3곳: 버튼 글자가 안 보일 때 테마를 덮을 자리.

파일, 문서, 외부 연결

  • 한글 뷰어 만들기: rhwp 실측: 문서 222개 중 221개를 연 엔진을 고른 측정.
  • HWPX MIME과 intent-filter: 종류를 모르는 파일(octet-stream)로 오는 hwpx를 받는 법.
  • JPEG 용량 맞추기: 500 KB 같은 상한에 맞추는 품질 이분 탐색.
  • market:// 스토어 선택 창 없애기: 통신사 판매 폰에서 Play 패키지를 먼저 지정하는 법.

출시 뒤에 드러난 문제

  • 버전 문자열 비교 버그: "6.7"을 "6.11"보다 크게 본 비교로 원격 설정이 일부 기기에 가지 않은 일.
  • 다음 맞춤법 전부 실패: 실패를 세는 이벤트가 없어 아무도 몰랐던 기록.
  • 네이버 맞춤법 하이라이트 누락: 요청에 붙인 꼬리표와 부등호 하나가 문장 끝 오류의 색을 지운 기록.
  • 앱에 Gemini 붙이기: 59건 평가로 모델을 고르고 하루 3,000회에서 끊는 설계.
  • 퀴즈 도달 2.6%에서 17.7%: 입구를 늘리기보다 아침 알림이 도달을 바꾼 측정.
  • 실기기 E2E 중 실광고 클릭: 테스트 기기 목록이 디버그 빌드에만 걸려 있던 앱에서 에이전트의 탭이 앱 안에서 열린 광고 화면에 떨어진 기록.

글 목록

  • 클로드 코드 애드몹 테스트 기기: 실광고 클릭 사고

    클로드 코드가 실기기 E2E 중 전면 광고를 한 번 눌렀습니다. 테스트 기기 목록은 디버그 빌드에만 걸려 있었고, 탭 가드는 패키지 이름만 봤습니다. 두 구멍을 고친 순서와 아직 남은 곳입니다.

  • 네이버 맞춤법 하이라이트 안 됨: 문장 끝 오류 누락

    맞춤법 앱에서 네이버가 찾은 오류 31개 중 17개만 색이 칠해졌습니다. 요청 끝에 붙인 꼬리표와 부등호 하나가 원인이었고, 클로드 코드와 고친 뒤 31개가 모두 칠해졌습니다.

  • 다음 맞춤법 전부 실패: OkHttp와 JS 리다이렉트

    맞춤법 앱의 다음(Daum) 검사가 HTTP 200에 빈 본문만 받으며 전부 실패했습니다. OkHttp가 못 따라간 259바이트 JS 리다이렉트와, 실패를 드러내지 않은 폴백과 계측을 정리했습니다.

  • XML 어디에도 흰색이 없는데 다이얼로그 글자가 사라졌다: 테마 색이 새는 자리 3곳

    앱바 색 colorPrimary가 다이얼로그와 시트 버튼 글자로 새어 흰 바탕 위 1.02:1이 됐습니다. 새는 자리 3곳과 띄운 화면에서 재는 테스트, 명도만 바꾼 하이라이트 색을 적었습니다.

  • 퀴즈 도달 2.6%에서 17.7%로: 진입 건수의 63%는 아침 알림이었다

    맞춤법 퀴즈를 연 사용자가 2.6%에서 17.7%로 늘었고 진입 건수의 63%가 아침 로컬 알림이었습니다. 말풍선 전환 8.1%와 알림 22.7%, 표본의 한계까지 GA4 수치로 적었습니다.

  • 단위 테스트 203개가 놓친 릴리스 전용 빈 값: R8과 Gson 필드 이름

    R8이 Gson 필드 output과 etype을 a와 b로 바꿔 릴리스에서만 빈 값이 나올 결함이 생겼습니다. 단위 테스트 203개가 놓친 이유와 불변식 테스트, dexdump 검사를 적었습니다.

  • 'PDF로 저장' 하나를 내려고 BACK을 7가지 시점에 눌렀다

    SAF로 PDF를 바로 저장하는 기능을 릴리스 빌드에서 BACK 7시점으로 확인했습니다. S20은 0.9~1.0초, S21은 0.75~0.9초에서 취소와 완료가 갈렸고 남은 빈 파일은 0개였습니다.

  • 맞춤법 앱에 처음 LLM을 붙였다: '왜 틀렸나요?'의 비용, 모델 평가, 한도 설계

    맞춤법 앱의 '왜 틀렸나요?'에 Gemini를 붙이며 59건 평가로 1,000건당 $0.93 모델을 골랐습니다. 비용은 하루 3,000회 차단으로 막고, 402는 Vertex AI로 풀었습니다.

  • JPEG를 용량 상한에 맞추는 법: 품질 이분 탐색, 긴 변 예측, 마지막에 원본과 비교

    JPEG를 500KB 같은 상한에 맞추는 탐색을 품질 이분 탐색과 긴 변 예측, 인코딩 20회 한도로 만들었습니다. 이미 작은 107KB 이미지가 150KB로 커진 결함과 수정도 적었습니다.

  • 안드로이드에서 HWPX는 octet-stream으로도 온다: 보낸 앱별 인텐트 18행과 intent-filter 설계

    같은 hwpx가 삼성 내 파일에서는 한컴 MIME, Chrome과 Files에서는 octet-stream으로 와서 문서 MIME만 받는 앱은 연결 목록에서 빠졌습니다. 인텐트 18행 실측.

  • Android assets를 미리 gzip한 실측: APK 이득은 0, .pack.gz는 .pack이 되어 FileNotFoundException

    Android assets에 미리 gzip해 넣은 팩 5개는 APK의 deflate보다 18바이트씩 컸고, 이름의 .gz가 빠져 FileNotFoundException까지 났습니다.

  • SKT 판매 삼성 폰에서 market://을 열면 스토어 선택 창이 뜬다: Play 패키지부터 지정하기

    SKT 판매 삼성 폰 두 대에서 market:// 링크를 스토어 앱 3개가 받아 선택 창이 나왔습니다. Play 패키지를 먼저 지정하고 실패할 때만 다음 주소로 넘기자 Play가 바로 열렸습니다.

  • addOnCompleteListener(this)가 onStop에서 지운 리스너 때문에 스플래시에 멈춘 버그
