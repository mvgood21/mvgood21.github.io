에이전트와 일하는 법

AI 코딩 에이전트에게 일을 나누고 규칙을 전하는 방법, 여러 세션을 한 저장소에서 함께 돌리며 겪은 충돌과 그 뒤에 정한 작업 방식입니다.

글 22개

  • 검증과 출시
  • Android 개발
  • 게임 개발
  • 스토어와 수익화
  • 웹사이트와 검색
  • 회고와 숫자

글 목록

  • gcloud '차단된 앱', 서비스 계정 가장으로 우회

    gcloud 로그인에 YouTube·analytics 스코프를 더하자 '차단된 앱'이 세 번 나왔습니다. 키 파일 없이 서비스 계정 가장으로 GA4 토큰을 받은 절차와 메모리에 남긴 방식입니다.

  • Claude Code 로그인과 첫 자동 질문 보내기

    3편에서 설치한 Claude Code에 브라우저로 로그인하고 claude -p로 첫 자동 질문을 보냅니다. 예약 작업용 로그인 폴더를 따로 만들고, 로그인이 끝나는 날을 확인합니다.

  • Claude Code 하네스 키트로 첫 작업 돌리기

    연습용 하네스 키트를 내려받아 풀고, 이 PowerShell 창에서만 스크립트 실행을 허용한 뒤 hello 작업을 돌려 로그와 보고서를 읽습니다.

  • PowerShell 처음 열기: 명령 붙여넣기와 경로

    명령 창을 처음 여는 분을 위한 준비 편입니다. Windows 판 확인, PowerShell 열기, 명령 붙여넣기, 내 사용자 폴더 경로 읽기, 관리자 창이 필요한 때를 화면 그대로 따라 합니다.

  • Vertex AI 테스트 비용 하드캡: 2,500원 중단선이 결제 2,956원을 놓친 뒤 바꾼 기본값

    2,500원에서 멈추는 평가 러너가 있었는데 결제 실측은 2,956원이었습니다. 장부가 받은 응답만 더했기 때문입니다. 그 뒤 배포는 DRY-RUN, 상한 값이 없으면 0을 기본값으로 정했습니다.

  • Windows에 Git과 Claude Code 설치하기

    Git for Windows를 공식 페이지에서 받아 설치하고, PowerShell 명령 한 줄로 Claude Code를 설치한 뒤 claude doctor로 확인합니다.

  • Windows에 Docker Desktop 설치하기

    Windows Pro·Enterprise·Education PC에 WSL과 Docker Desktop을 설치하고 hello-world로 확인합니다. 6편 키트에는 필요 없어 건너뛰어도 됩니다.

  • Claude Code를 매일 자동으로 돌리는 하네스란

    Windows PC 한 대에서 Claude Code가 매일 아침 GA4 보고, 광고 예산 점검, 영상 계획을 써 두게 하는 하네스가 무엇인지, 대화형 AI와 다른 점, 준비물과 요금을 정리했습니다.

  • 작업 스케줄러로 Claude Code 매일 돌리기

    하네스 키트의 register-job.ps1로 hello 작업을 Windows 작업 스케줄러에 매일 9시 5분으로 등록하고, 바로 한 번 돌린 뒤 상태 표로 결과를 확인합니다.

  • CLAUDE.md에 적은 규칙을 Claude가 어길 때: 사고 6건과 재발 기록

    CLAUDE.md 규칙 6개를 사고와 짝짓고, 그중 둘의 재발을 세션 기록으로 세었습니다. 한국어 규칙은 적은 뒤 다섯 날짜에 깨졌고, exit 144는 메모 없는 프로젝트에서 7건 더 났습니다.

  • GA4에 0이 보일 때 먼저 볼 곳: 표 보고서의 합계 행

    GA4 개요의 '데이터 없음'을 AI 에이전트가 28일 0건으로 보고했지만, 표 보고서 합계 행에는 43명과 10,522건이 있었습니다. 화면별 0의 뜻과 코드 전에 볼 순서입니다.

  • WSL을 접고 Windows 네이티브로: Claude Code 개발 환경 이전 체크리스트

    Claude Code 작업 환경을 WSL에서 Windows 네이티브로 옮긴 점검표입니다. 저장소는 하루, 세션 기록과 Docker는 닷새 걸렸고 R8 릴리스 빌드와 몽키 1,500회로 확인했습니다.

  • Claude Code 자동 압축 뒤에 남는 것: 요약, 최근 파일, 메모리 색인

    13일 이어진 Claude Code 세션의 자동 압축 요약 9개에 예산을 정한 이유는 0번 나왔습니다. 압축마다 다시 실린 메모리 색인의 오래된 한 줄이 착오의 유력한 출처였습니다.

  • 서브에이전트가 한도로 끊기면 무엇이 남나: 보고서보다 디스크의 원본 파일

    서브에이전트가 사용 한도로 끊기면 먼저 만들어 둔 보고서는 거의 비어 있습니다. 끊긴 5건을 이어받은 방법과, 원본 파일 경로를 먼저 적는 브리프 틀을 정리했습니다.

  • 브랜치마다 AI 리뷰를 통과해도 합친 코드에는 결함이 남습니다: 통합 리뷰가 찾은 12건

    리뷰와 CI를 통과한 브랜치 13개를 합친 뒤 통합본만 다시 리뷰하자 확정 결함 12건이 나왔습니다. 10건은 두 패키지 사이의 약속이 어긋난 것이었고, 찾는 순서를 정리했습니다.

  • AI 에이전트 여러 개가 한 저장소를 고칠 때: 공유 파일마다 주인을 정하는 표

    같은 작업 트리의 커밋 하나가 다른 세션 파일 50개를 담아 간 뒤 공유 파일 주인 표를 만들었습니다. 그 표로 나눈 머지 13개에서 손 머지가 어디서 났는지 git으로 셌습니다.

  • 설계 3안을 심사자 3명이 채점했다: 시장 심사자 혼자였다면 카톡 열기마다 죽는 안이 1위였다

    문서 뷰어를 코딩하기 전에 에이전트 설계 3안을 심사자 3명이 채점했습니다. 카톡 열기 크래시와 최종안 결함 23건이 코드 전에 나왔습니다. 단계, 프롬프트 모양, 비용을 적었습니다.

  • Co-Authored-By 트레일러 없는 커밋, 확인한 29개 중 26개는 에이전트가 만들었다

    Co-Authored-By 트레일러가 없는 커밋 중 세션 기록과 대조할 수 있던 29개를 봤더니 26개는 에이전트가 낸 병합과 revert였습니다. 세는 명령과 한계를 적었습니다.

  • 예약 실행하는 AI 에이전트의 권한 표: 혼자 할 일과 사람이 누를 클릭

    하루 4번 예약 실행되는 AI 마케팅 에이전트에게 위임 범위를 권한 표 파일 한 장으로 줬습니다. 운영자가 승인한 광고 재개 클릭도 도구 권한 검사가 막아, 마지막 클릭은 사람이 했습니다.

  • AI 에이전트 코드 리뷰를 믿는 법: 다른 에이전트가 반박해도 버틴 발견만 고친다

    AI 에이전트 리뷰는 반박을 버틴 발견만 셉니다. 한글 띄어쓰기 1.6.025 검토는 에이전트 84개를 돌려 발견마다 3명이 반박했고, 20건을 확정한 뒤 2차 리뷰는 0건이었습니다.

  • AI 코딩 에이전트는 몇 개까지 동시에 돌릴 수 있나: 상한은 메모리와 테스트폰이 정했다

    AI 코딩 에이전트를 수백 개 써도 된다고 했지만 코드를 쓰는 에이전트는 동시에 3개만 돌았습니다. 상한을 정한 것은 여유 메모리 4GB와 공용 테스트폰 2대였습니다.

  • AGENTS.md 작성법: AI 코딩 에이전트가 틀리기 쉬운 규칙만 적는다

    AGENTS.md는 AI 코딩 에이전트가 작업 전에 읽는 지침 파일입니다. 앱 4개를 낸 96줄짜리 실제 파일은 틀리기 쉬운 규칙만 이유와 함께 적고, 중요한 규칙은 테스트로 막습니다.
