Claude Code 예약 실행 하네스: Windows PC 한 대로 게임 앱 마케팅을 돌리는 구조

하네스는 Claude Code를 사람 없이 정해진 시각에 돌리고, 결과를 남기고, 위험한 일을 막는 틀입니다. PC가 켜져 있고 로그온한 동안만 돕니다.

작성 SugarMount · 에이전트와 일하는 법 · 읽는 시간 11분 · 최종 업데이트 2026년 11월 11일

Windows 하네스 연재 1/5 · 전체 그림과 준비물

게임 앱 두 개(화살표 매듭풀기, 한판블록)의 광고 숫자를 읽고, 예산이 상한 안에 있는지 보고, 틱톡에 영상을 올리는 일을 SugarMount에서는 예약 작업이 맡습니다. 2026년 11월 10일에는 게임 데일리 작업이 오전에 13.8분 동안 돌았고, 저녁에는 게임 소셜 작업이 화살표 퍼즐 영상 한 편을 틱톡, 인스타그램, 유튜브 세 곳에 올렸습니다.

이 연재는 개발 경험이 없는 1인 앱 운영자를 기준으로 다섯 편으로 나눴습니다. 1편은 설치 전에 보는 지도입니다.

11월 10일 하루, 하네스가 실제로 돈 시간

아래 그림은 11월 10일 러너 로그로 그렸습니다. 러너는 작업 하나를 실행하고 시작·종료 시각을 로그에 적는 PowerShell 스크립트입니다.

아침의 파란 막대 두 개와 주황 막대 하나가 앱 데일리 세 개를 나타냅니다. 한글 앱이 09:11에 시작해 29분, 유틸 앱이 27분을 쓴 뒤 게임이 이어받았습니다. 셋을 동시에 돌리면 Chrome과 에뮬레이터(PC 안의 가상 Android 폰)를 서로 쓰려고 다투기 때문에, 디스패처라는 관리 작업이 하나가 끝나야 다음 것을 부릅니다.

맨 아래 세로줄은 15분마다 깨어나는 관리 작업 세 종류(디스패처, 감시자, 하네스 코드 반영)로, 이날 284회 돌았고 셋 다 AI 모델을 부르지 않는 스크립트입니다.

이날 러너 기록은 모두 정상 종료(status ok)였지만, 그 뜻은 오류 없이 끝났다는 것까지입니다. 18:07 유틸 소셜은 올릴 영상 큐가 비어 게시 0건이었는데도 ok였습니다. 11월 11일부터는 작업마다 마지막 줄에 '판정: 완료' 또는 '판정: 일부 실패'를 쓰게 했고, 하루 상태판은 이 줄로 빠진 일을 셉니다.

모델은 Claude의 등급 중 판단할 것이 많은 데일리에 가장 강한 opus, 정해진 화면을 누르는 게시에 중간급 sonnet, 자가 점검에 가장 가벼운 haiku를 배정했습니다. 게임 데일리 한 회차는 시간 한도 5,400초 안에서 아래 일곱 단계를 거칩니다.

내부 테스트 트랙은 테스터에게만 먼저 배포하는 Play의 통로이고, 20% 단계 출시는 새 버전을 사용자 20%에게만 먼저 내는 방식입니다.

대화창 예약은 세션이 닫히면 돌지 않습니다

하네스를 만들기 전 앱 데일리는 Claude Code 대화 세션 안에 걸어 둔 예약(세션 크론)이 맡았습니다. 이 예약은 세션이 열려 있어야 돌고, 하네스 README의 전환 체크리스트도 기존 예약을 끄는 방법으로 세션 종료를 적었습니다. 하네스는 시계를 Windows 작업 스케줄러에 맡기고, 판단은 대화창 없이 claude -p로 한 번 일을 시키고 끝내는 방식(헤드리스 실행)으로 합니다.

예약 작업의 로그인과 지침은 전용 설정 폴더에 따로 있습니다. 11월 11일 시험에서 전용 폴더 없이 돌린 작업의 답 끝에는 대화용 개인 지침의 "한 일 / 결과 / 남은 일" 형식이 붙었습니다. 전용 폴더를 두면 예약 작업에 줄 지침과 로그인을 따로 관리할 수 있습니다. 다만 실제 하네스의 전용 폴더에도 같은 요약 지시가 복사돼 있어, 11월 10일 게임 소셜의 답도 이 형식으로 끝났습니다. 대화용 지침을 그대로 복사하면 형식도 따라옵니다(2편).

두 방식을 처음 비교한 10월 26일 밤에는 AI의 확인이 틀렸습니다. 비교 보고서는 기존 쪽 산출물이 없어 "돌지 않은 것으로 보인다"고 적었는데, 2분 뒤 게임 레포(코드와 기록을 담는 git 저장소)에 그날 기록이 커밋됐습니다. 다음 날 보고서가 찾은 원인은 두 가지입니다. 확인한 시각이 커밋보다 2분 일렀고, 날짜만 준 git log --since는 현재 시각 기준으로 해석돼 그날 커밋을 빠뜨렸습니다. 그 기록에는 '사용자 지시로 모든 스케줄러를 멈췄다'고 적혀 있었습니다. 날짜로 기록을 찾을 때는 시각까지 붙이십시오.

WSL(Windows 안에서 도는 Linux)에 bash와 crontab으로 만든 예전 하네스는 10월 25일에 동결했고, 코드 대신 교훈만 옮겨 Windows용을 새로 썼습니다(첫 커밋 0114edc). 작업 스케줄러는 비밀번호를 저장하지 않고 사용자 프로필의 Claude 로그인을 그대로 쓰도록, 로그온한 동안만 도는 방식을 골랐습니다.

10월 27일 실제 운영으로 바꿀 때(305934e) 체크리스트 첫 줄은 사람이 할 일이었습니다. 기존 세션 예약을 끄는 일입니다. 둘이 같이 돌면 같은 날 두 번 배포하고 두 번 게시합니다. 두 방식을 함께 켜 두지 마십시오.

무엇을 바로 하고 무엇을 사람에게 올릴지 가르는 권한 표는 세 칸입니다. 무료 마케팅과 스토어 문구는 바로 하고, 돈·새 캠페인·권한 변경은 승인함에 올리고, 강제 push나 비밀값 출력, 100% 출시는 가드 훅이 막습니다. 이 표를 만든 과정은 AI 마케터를 하루 4번 예약 실행하며 정한 권한 표에 적었습니다.

처음 만드는 하네스에 이 부품이 다 필요한 것도 아닙니다. 4편의 최소 키트는 러너, 작업 정의, 지시문 세 파일과 작업 스케줄러로만 돕니다. Docker는 데이터를 매일 모아 둘 서버나 MCP 서버(Claude에 GitHub 같은 외부 도구를 붙이는 연결 서버)를 컨테이너로 돌릴 때 필요합니다.

다른 숫자에 첫 판 해결률이라는 이름을 붙였습니다

10월 26일 그림자 실행에서 게임 데일리는 한판블록 1.1.6의 안내 판 세 개를 끝낸 사람 5명과 앱을 처음 연 사람 8명을 보고 본문에 맞게 적었습니다. 틀린 곳은 승인 요청입니다. 이 5/8에 첫 판 해결률이라는 이름을 붙였고, 레포에 있던 6/8 기록을 읽고도 두 값을 맞춰 보지 않았습니다.

다음 날 GA4를 다시 조회한 검증 문서가 차이를 정리했습니다. 판을 구분하는 값(pid) 없이 버전별 이벤트만 조회했으니, 처음부터 첫 판 숫자가 나올 수 없었습니다.

승인 요청에 쓴 5/8첫 판 해결률
분자tutorial_complete 사용자(안내 판 세 개를 다 푼 사람)첫 판 level_up 사용자
분모first_open 사용자첫 판 level_start 사용자
결과5/86/8(75%)

승인함 요청 GAM-1026-1이 바로 이 숫자를 조건으로 삼았습니다. 새 버전의 첫 판 해결률이 1.1.6보다 낫지 않으면 일 예산을 4,000원에서 2,000원으로 줄이자는 요청입니다. 검증 문서에 따르면 잘못된 기준으로는 새 버전이 확실히 나아 보여 감액을 거두게 되고, 맞는 기준으로는 차이가 1명 이하라 감액 조건에 해당합니다.

그래도 돈은 움직이지 않았습니다. 그림자 모드였고, 실제 운영이었더라도 승인함 요청은 사람이 승인해야 실행됩니다. 지금 게임 데일리 지시문에는 첫 판 해결률의 정의가 적혀 있고, 표본이 20명보다 적으면 비율 옆에 분수를 같이 적습니다(5편).

시작 전에 갖출 것

요구 사항은 11월 11일에 각 공식 문서에서 확인했습니다.

  • Windows PC: Claude Code는 Windows 10 1809 이상 또는 Windows 11, RAM 4GB 이상이면 돌고 관리자 권한도 필요 없습니다. Docker Desktop은 문서 목록 기준 Windows 11 64비트 Pro·Enterprise·Education 23H2 이상과 RAM 8GB를 요구하고, Home판은 그 목록에 없습니다(3편). 내 PC의 판은 Win+R을 누르고 winver를 입력하면 나옵니다.
  • Claude 유료 요금제: Pro, Max, Ultra, Team, Enterprise 중 하나나 Console(API 선불) 계정. 무료 claude.ai 요금제에는 Claude Code가 없습니다.
  • Google 계정과 GA4, Google Ads, AdMob(Google의 앱 광고 수익 서비스) 접근 권한: 사용자, 광고비, 광고 수익 숫자를 읽습니다.
  • Notion(메모와 표를 쓰는 웹 앱): 승인함과 일일 보고가 여기에 있습니다.
  • 틱톡, 인스타그램, 유튜브 계정: 소셜 작업이 Chrome으로 게시합니다.
  • 켜 두고 로그온해 둘 PC: 꺼져 있거나 절전이라 놓친 회차는 깨어난 뒤 한 번 실행되게 설정합니다(4편).

프로그램은 2편에서 설치합니다. Git for Windows는 권장이고, Python은 GA4·AdMob 보조 스크립트에 필요하며, 마지막이 Claude Code입니다.

이 구성이 맞지 않는 경우

PC를 매일 켜 두지 못한다면 이 구성은 맞지 않습니다. 작업 스케줄러는 로그온한 동안만 작업을 깨우고, 놓친 회차는 깨어난 뒤 한 번만 돌립니다.

광고 예산 결정을 AI에 통째로 맡기고 싶을 때도 맞지 않습니다. 이 하네스가 혼자 바꿀 수 있는 것은 운영자가 10월 30일에 위임한 범위뿐이고, 일 예산 상한은 앱당 5,000원, 전체 12,000원입니다. 상한은 승인으로도 넘지 못하고, 새 캠페인·중지·입찰·타겟 변경은 승인함으로 갑니다.

예약 작업도 Claude 요금제의 사용량 한도 안에서 돕니다. 10월 30일에는 주간 사용 한도에 걸려 세 앱 데일리와 게임 소셜 세 회차가 모두 2~5초 만에 끝났습니다.
