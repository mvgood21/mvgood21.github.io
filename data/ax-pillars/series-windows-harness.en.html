Called as claude -p, Claude Code answers one prompt and exits without opening a chat window, so Windows Task Scheduler can run it at a fixed time every day on a single PC. SugarMount's harness ran this way for 17 days, from 25 October to 10 November 2026. Its three morning app jobs (one per app) ran 51 times in that period, and 7 of those runs failed.

As of 11 November, 14 tasks were registered in Task Scheduler, and on 10 November the housekeeping jobs alone, which run every 15 minutes, ran 284 times. A harness here means the frame around the AI: it starts the model on schedule, writes results and failures to files, and hands anything involving money or accounts to a person. The 11-part series below builds a cut-down practice kit of that harness, written for someone opening PowerShell for the first time.

What do claude -p and Task Scheduler give you?

claude -p leaves an exit code: 0 on success. Failures such as a missing login are printed where the answer would be, so the exit code is what you judge by. An unattended run can only use the tools listed in advance (--allowedTools) on the job card. A schedule set inside a chat session stops when the window closes; Task Scheduler runs the job at its time whether or not any window is open.

The kit turns on three Task Scheduler settings. If the PC was off at the scheduled time, the job runs once after it comes back (StartWhenAvailable). If the previous run is still going, the new one is dropped (IgnoreNew). And jobs run only while you are logged on, so no password is stored. That means the PC has to be on and logged in at job time. Claude Code is not included in the free Claude plan, so you need Pro or above.

Where it actually stopped, and the fixes

  • Weekly usage limit. On 30 October all three morning jobs hit the plan's weekly limit ("You've hit your weekly limit"). In that state jobs finish in seconds; rerun them by hand once the limit resets.
  • Uncommitted code. From the evening of 4 November to the morning of 6 November, about 38 hours, every job stopped at its pre-start check because harness code under development had been left uncommitted. Since 7 November production runs from a separate copy, and only changes that pass the checks are moved across.
  • "ok" is not success. On 10 November one app's posting job had no video to post, published nothing, and still reported ok; that night's summary said "0 failed, 0 missed". Since 11 November every job ends with a verdict line.
  • Logins that expire or get overwritten. The scheduled login printed a warning on every answer that it would end between 18 and 21 November. On 10 September, switching accounts with /login in a chat window overwrote the scheduled jobs' login and they stopped, so scheduled runs now use their own config folder (CLAUDE_CONFIG_DIR).
  • How the prompt is passed. A prompt given as a command-line argument was once read as part of the tool list after --allowedTools, so prompts now go in on standard input. If ANTHROPIC_API_KEY is set on the PC, -p runs use that key and bill to the API.

The first three days (25 to 27 October) were a shadow run that only reported. Even then the reports went wrong at least twice, once with the wrong denominator and once by missing a record, which is why the series suggests a full week of report-only runs to start.

The 11 parts, in order

  1. What a harness is: one real day of the harness and the kit's four parts, so you can decide whether your PC fits.
  2. Open PowerShell: pasting commands and reading paths. Do not skip it if the command line is new to you.
  3. Install Git and Claude Code: Git from its official page, Claude Code with one command and no admin window.
  4. Login and a first unattended question: separate chat and scheduled logins, and a claude -p run that exits 0.
  5. Install Docker Desktop: the kit runs without Docker, so read this only if you run a data server alongside.
  6. A first job with the kit: run it once by hand and check that a log, a report and a state file appear.
  7. Run it every day with Task Scheduler: one registration line and a morning status table. This is the core of unattended runs.
  8. A morning report from a GA4 CSV: the job reads only files you drop in, so the harness never gets GA4 access.
  9. A daily Google Ads budget check: it never touches the account and only writes raise, cut or hold suggestions plus a list for you to decide.
  10. TikTok, Reels and Shorts plans: the AI writes the plan; filming, posting and logging views stay with you.
  11. 17 days of running it: reading failures by date and the bar for adding the next job.
