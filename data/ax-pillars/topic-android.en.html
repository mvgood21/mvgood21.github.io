One developer with Claude Code can take an Android app all the way to Google Play. SugarMount published four apps in the 20 days from 20 September 2026, and 52 of the 59 commits in that window (88%) were co-written with Claude Code.

The speed came from stamping out each new app from the first one with a script, and from scripting the pre-release checks and the Play Console work. The failures kept landing in the same place. Debug builds and unit tests passed, then the app died in the minified release build or on a phone that had never run it before. Every rule below came out of one of those failures.

Six rules that held

  1. Launch the release build on a device twice before uploading. On 23 September 2026 R8, the code shrinker, removed one constructor and every release build of our first app crashed on start. Debug builds never showed it. An upload now waits for a release gate, two cold starts of the minified build and an on-device E2E run (Pre-release checks for an AI-built Android app).
  2. Judge R8 by counting the artifact, not by reading the code. Our spell checker had 203 passing unit tests while its release build was set to return blank corrections (R8 renamed Gson fields: empty release results). A puzzle game's release AAB kept 5 test ad strings because of how one condition was written, and none of the 19 findings from the review agent mentioned it (Why R8 kept 5 AdMob test IDs in a release AAB).
  3. Run the monkey on a fresh install. The agent reported "launch 857 ms, no crash" for a game; four minutes later the operator reported that it crashed on the first tutorial tap. The vibrate permission was missing, and a monkey run on cleared app data hit the crash at event 15 of 800 (VIBRATE crash and the fresh-install monkey test).
  4. One Gradle build at a time per workspace. Even on the day the operator said hundreds of agents were fine, no more than 3 code-writing agents ran at once. The machine had 4 GB free out of 13 GB, and there were 2 test phones (Parallel AI agents: 10 workstreams, 3 at a time).
  5. Do the on-device E2E before you submit for review. We submitted three photo apps first and then tested on a Galaxy S21 and S20. That turned up 9 major defects the emulator and unit tests had missed (Four Android apps in 20 days with an AI agent).
  6. Do not call it verified until the release build runs at your minSdk. One java.time call in a shared module crashed two games on Android 7 for two weeks. The commit said "monkey 3x1500, 0 fatals", but that phone ran Android 15 (java.time on Android 7: Call requires API level 26).

All six come down to one question you ask before accepting an agent's "done": which device, which build, and what exactly was checked. The four R8 notes are collected in the series Release-only bugs from R8.

Where it went wrong

  • Staged rollout: version 1.6.029 of the spell checker was meant for 20% of users. An off-by-one argument check in a script committed it to everyone, and the rollback request 35 seconds later came back HTTP 403 (Play staged rollout API: 20% went out as 100%).
  • 16 KB pages: builds of our photo-to-video app made with NDK 27 and 29 put a blue tint on photo transitions. Re-measured later, NDK 25 with one linker flag was enough.
  • Ad SDK: four minutes after 243 unit tests passed, an interstitial callback arriving on a background thread tried to change screens and crashed a photo app (GMA Next-Gen ad callbacks run off the main thread).
  • The test tools: a script that waited for a screen exited with success on timeout, so the next checks ran against the wrong screen. The AdMob app-creation API returned 403, so ad units are created by hand in the console.

What did Claude Code do, and what stayed with a person?

The agent wrote the Kotlin code and unit tests, the build, release and QA scripts, store listing drafts and screenshots, and the device test reports. A person decided ad placement and pricing, did the work only Play Console allows, plugged in the phones, did the final check and made the release call. Rules the agent tended to break were turned into tests that fail the build, not left as sentences in an instructions file.

Reading order

If you are new here, start with the 20-day note and the pre-release checks, then pick the group below that matches your problem.

Bugs that only exist in release builds

  • R8 and Gson field names: finding fields that silently come back empty, with mapping.txt and dexdump.
  • Test ad IDs and dex counts: a command that counts ad IDs in the artifact without printing them.
  • A release gate for an app with no ads: a gate that read only the dependency graph missed the AD_ID Firebase merges back into the manifest, so both checks now run in one task.
  • DEX optimization and a keep rule: deleting one unused keep file took shrinking from 39% to 85%.
  • java.time on Android 7: a lint gate that also covers library modules, and an API 24 emulator check.
  • 16 KB pages and a blue tint: why to try the linker flag before upgrading the NDK.
  • .gz assets that would not open: the build dropped the .gz suffix and the app could not find its files.

Lifecycle and saving

  • Splash hang and a listener: a listener removed in onStop left the splash stuck.
  • androidx.pdf's isolated process: Application.onCreate runs there too, so guard the first line.
  • Cancelling a SAF PDF save: pressing BACK at seven points during a save to prove no empty file is left.

Screens and text

  • Korean line breaks in Compose: Korean words split mid-syllable, fixed in one shared TextStyle.
  • Blank Hangul and 8,693 empty glyphs: a font that claims glyphs it cannot draw.
  • Theme colour leaking into dialogs: the three places to override when button text disappears.

Files, documents and other apps

  • An Android HWP viewer with rhwp: the engine opened 221 of 222 test documents.
  • HWPX MIME and intent filters: accepting files that arrive as octet-stream.
  • Fitting a JPEG under a size limit: a quality binary search for caps such as 500 KB.
  • market:// and the store chooser: naming the Play package first on carrier-sold phones.

Problems that surfaced after release

  • A version string bug: "6.7" compared greater than "6.11", so remote config missed some devices.
  • Daum spell check failing everywhere: no event counted the failures, so nobody noticed.
  • Naver spelling highlights missing: a tag appended to the request and one comparison erased the colour on end-of-sentence errors.
  • Gemini in an Android app: a 59-case eval to pick the model and a 3,000-calls-a-day cap.
  • Quiz reach from 2.6% to 17.7%: a morning notification did more than extra entry points.
  • A real ad tapped during device E2E: a test-device list wired to debug builds only, and an agent tap that landed on an ad screen opened inside the app.
