클로드 코드(Claude Code)는 claude -p로 부르면 대화 창 없이 질문 하나에 답하고 끝나기 때문에, 윈도우 작업 스케줄러에 걸어 두면 PC 한 대에서 매일 정한 시각에 사람 없이 실행됩니다. SugarMount 하네스는 2026년 10월 25일부터 11월 10일까지 17일 동안 이렇게 돌았고, 앱 세 개의 아침 작업(데일리) 51회 가운데 실패는 7회였습니다.

11월 11일 기준으로 작업 스케줄러에 등록한 작업은 14개이고, 11월 10일 하루에는 15분마다 도는 관리 작업만 284회 돌았습니다. 하네스는 AI를 정한 시각에 돌리고, 결과와 실패를 파일로 남기고, 돈·계정이 걸린 일은 사람에게 넘기는 틀입니다. 아래 연재 11편은 이 하네스를 줄인 연습용 키트를 PowerShell을 처음 여는 사람 기준으로 따라 만듭니다.

claude -p와 작업 스케줄러로 무엇이 되나요?

claude -p는 답을 낸 뒤 종료 코드를 남깁니다. 성공하면 0이고, 로그인이 없을 때 같은 실패도 답 자리에 문장으로 찍히므로 판정은 이 숫자로 합니다. 무인 실행에서는 작업 카드에 미리 적은 도구(--allowedTools)만 쓸 수 있습니다. 대화 창 안에 걸어 둔 예약은 창을 닫으면 멈추지만, 작업 스케줄러는 창과 상관없이 Windows가 정한 시각에 실행합니다.

키트는 작업 스케줄러에 세 가지를 설정합니다. 예약 시각에 PC가 꺼져 있었으면 켜진 뒤 한 번 돌리고(StartWhenAvailable), 이전 회차가 돌고 있으면 새 회차를 버리고(IgnoreNew), 비밀번호를 저장하지 않도록 내가 로그온해 있는 동안만 실행됩니다. 그래서 작업 시각에 PC가 켜져 있고 로그온해 있어야 합니다. Claude Code는 무료 요금제에 없으니 Pro 이상 요금제가 필요합니다.

실제로 멈춘 곳과 대처

  • 주간 사용 한도. 10월 30일에는 아침 작업 세 개가 모두 요금제의 주간 사용 한도(You've hit your weekly limit)에 걸렸습니다. 이때는 작업이 몇 초 만에 끝나니, 한도가 풀린 뒤 손으로 다시 돌립니다.
  • 확정하지 않은 코드. 11월 4일 저녁부터 6일 아침까지 약 38시간 동안 모든 작업이 시작 전 검사에서 멈췄습니다. 개발하던 하네스 코드가 확정(commit)되지 않은 채 남아 있었기 때문입니다. 11월 7일부터 운영은 별도 복사본에서 돌고, 검사를 통과한 변경만 옮겨 갑니다.
  • ok는 성공이 아닙니다. 11월 10일 한 앱의 게시 작업은 올릴 영상이 없어 0건을 올렸는데 상태는 ok였고, 그날 밤 요약도 "실패·빠짐 0건"이었습니다. 11월 11일부터 모든 작업이 마지막 줄에 "판정:"을 씁니다.
  • 로그인 만료와 덮어쓰기. 예약용 로그인은 "이 로그인은 11-18과 11-21 사이에 끝난다"는 경고를 답마다 찍었습니다. 9월 10일에는 대화 창에서 /login으로 계정을 바꾸자 예약 작업의 로그인이 덮어써져 멈췄고, 그 뒤 예약용 설정 폴더(CLAUDE_CONFIG_DIR)를 따로 둡니다.
  • 지시문 전달. 지시문을 명령 인자로 넘겼다가 --allowedTools 뒤에서 도구 목록으로 읽힌 일이 있어, 지금은 표준 입력으로 보냅니다. PC에 ANTHROPIC_API_KEY가 있으면 -p 실행은 그 키를 쓰고 요금도 API로 나갑니다.

처음 사흘(10월 25~27일)은 보고만 하는 그림자 운전이었는데, 그사이에도 보고서가 틀린 분모를 쓰거나 기록을 빠뜨린 일이 적어도 두 번 있었습니다. 그래서 연재는 처음 1주는 보고만 받으라고 권합니다.

연재 11편, 읽는 순서

  1. 하네스란: 실제 하네스의 하루와 키트의 부품 4개를 보고, 내 PC로 시작할 수 있는지 판단합니다.
  2. PowerShell 처음 열기: 명령을 붙여 넣고 경로를 읽는 법. 명령 창이 처음이면 건너뛰지 않습니다.
  3. Git과 Claude Code 설치: Git은 공식 페이지에서 받고, Claude Code는 관리자 창 없이 명령 한 줄로 설치합니다.
  4. 로그인과 첫 자동 질문: 대화용과 예약용 로그인을 나누고, claude -p가 종료 코드 0을 남기는지 봅니다.
  5. Docker Desktop 설치: 키트는 Docker 없이 도니, 수집 서버를 따로 돌릴 때만 읽습니다.
  6. 키트로 첫 작업 돌리기: 손으로 한 번 돌려 로그, 보고서, 상태 파일이 남는지 봅니다.
  7. 작업 스케줄러로 매일 돌리기: 등록 한 줄과 아침 상태 표. 무인 실행의 핵심 편입니다.
  8. GA4 CSV로 아침 보고서: 사람이 넣은 파일만 읽어서, 하네스에 GA4 권한을 주지 않습니다.
  9. Google Ads 일 예산 점검: 계정을 건드리지 않고 증액·감액 제안과 사람이 결정할 목록만 씁니다.
  10. 틱톡·릴스·쇼츠 영상 계획: AI는 계획만 쓰고, 찍고 올리고 조회수를 적는 일은 사람이 합니다.
  11. 17일 운영과 시작 순서: 실패를 날짜별로 보는 법과 작업을 하나씩 늘리는 기준.

함께 읽을 글

  • Claude Code WSL에서 Windows로 이전: 이 하네스는 WSL에서 돌던 것을 멈추고 코드 없이 교훈만 옮겨 새로 썼습니다. 10월 18일 하루에 옮겼지만 세션 기록과 Docker까지 정리된 것은 22일이었습니다.
  • AI 에이전트 권한 표: 돈·계정·정책은 사람이 누른다: 혼자 할 일, 승인 뒤에 할 일, 승인해도 사람이 누를 클릭을 나눈 표. 하네스의 광고 일 예산 상한은 앱당 5,000원, 전체 12,000원입니다.
  • AI 코딩 에이전트 비밀값 관리: 채팅, 로그, 토큰 권한 세 곳에서 비밀값이 새지 않게 막는 방법.
  • gcloud '차단된 앱', 서비스 계정 가장으로 우회: 키 파일 없이 GA4를 읽는 방법.
  • 클로드 코드 예약 실행 멈춤: 회차가 남긴 상태: exit 0으로 끝난 회차가 남긴 파일 두 개로 한 앱이 사흘, 다른 브라우저만 연결돼 소셜 게시가 이틀 멈춘 기록. 다음 회차 시작에서 작업 트리와 브라우저 기기 ID를 검사하는 절차가 있습니다.
