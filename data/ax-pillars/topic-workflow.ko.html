짧은 답: 상한은 에이전트 수가 아니라 빌드와 기기입니다

클로드 코드(Claude Code)의 메인 세션은 서브에이전트를 여러 개 동시에 띄울 수 있지만, SugarMount에서 코드를 고치는 에이전트가 동시에 돈 것은 최대 3개였습니다. 2026년 10월 3일 운영자는 "에이전트를 수백 개 써도 된다"고 했고, 상한을 정한 것은 빈 메모리 4 GB(전체 13 GB)와 다섯 세션이 나눠 쓰는 테스트폰 두 대였습니다. 빌드를 하지 않는 조사·설계 단계는 11~14개가 동시에 돌았습니다.

그날 저장소에는 커밋 59개가 쌓였고, 작업 10개는 단계마다 한 통합 에이전트가 합쳤습니다. 구현 에이전트 41개는 "모두 완료, 실패 없음"을 보고했지만 앱은 실기기에서 첫 실행에 죽었습니다. 다른 앱에서는 브랜치 13개가 각자 리뷰와 CI를 통과했는데도, 합친 코드만 읽은 리뷰가 결함 12건(같은 결함 하나가 두 번 잡혀 서로 다른 결함은 11개)을 확인했습니다.

몇 개를 동시에 돌리고, 어떻게 나누나?

  1. 동시 실행 수는 빌드 하나가 쓰는 메모리와 기기 수로 정합니다. 코드를 바꾸는 에이전트는 커밋마다 단위 테스트와 디버그 빌드를 돌려야 해서 3개가 상한이었습니다. 이틀 동안 다른 세션에서 온 메시지 148개 가운데 114개가 폰 두 대의 순서 이야기였습니다. 근거: 동시 실행은 3개였다
  2. "완료"를 실기기에서 실행한 빌드로 정의합니다. 에이전트 41개의 완료 보고는 JVM 테스트와 컴파일만 뜻했습니다. 빌드 도구가 자산 이름 끝의 .gz를 떼어 레벨 파일을 찾지 못한 크래시는 완료 보고 1분 뒤 S21에 설치하고서야 보였습니다. 근거: 완료 41개 뒤의 첫 실행 크래시
  3. 공유 파일마다 주인을 한 명 정합니다. 2026년 9월 23일, 같은 작업 트리의 다른 세션이 쓰던 파일 50개가 출시 수정 커밋에 함께 들어갔습니다. 주인 표를 먼저 쓴 다른 앱은 브랜치 13개를 2분 11초에 합쳤지만, 그래도 7개 병합은 손이 필요했고 8개 브랜치가 남의 파일을 고쳤습니다. 근거: 공유 파일 주인 표
  4. 같은 작업 트리에서는 commit, stash, reset, gradlew --stop을 요청 없이 하지 않습니다. 한 세션의 출시 점검 스크립트가 gradlew --stop을 돌려, 같은 PC에서 다른 세션이 하던 클린 빌드 두 번이 멈췄습니다. 근거: 세션 둘이 한 작업 트리를 쓸 때
  5. 합친 뒤에는 합친 코드만 읽는 리뷰를 따로 돌립니다. 테스트 2,115개가 모두 통과한 통합 브랜치에서 리뷰 에이전트 6개가 지적 32건을 냈고, 반박을 거쳐 확인된 블로커·메이저 12건 중 10건은 서로 다른 패키지 사이의 어긋난 약속이었습니다. 근거: 통합 리뷰가 찾은 12건

에이전트에게 어떻게 맡기고 무엇을 남기게 하나?

  1. 지시서에는 원자료를 어디에, 언제 쓰는지 적습니다. 2026년 9월 7~10일 사용 한도에 걸려 끊긴 서브에이전트 5개의 보고서는 거의 비어 있었고, 이어받은 에이전트는 디스크에 남은 로그, 스크린샷, 고친 파일로 일을 끝냈습니다. 33줄 공통 지시서의 금지 조항은 지켜져, 보고서 13개가 설치 대신 "승인 필요"라고 적었습니다. 근거: 서브에이전트 지시서 규칙
  2. 결정의 이유는 결정할 때 메모리 파일에 씁니다. 13일짜리 세션에서 자동 압축이 9번 일어났고, 압축 뒤 남은 토큰은 이전의 2.6~8.2%였습니다. 요약 9개 어디에도 광고 예산을 운영 문서 값과 다르게 정한 이유는 없었습니다. 근거: 자동 압축 뒤에 남는 것
  3. CLAUDE.md는 맥락이지 강제 설정이 아닙니다. 에이전트가 틀리기 쉬운 규칙만 이유와 함께 적고(앱 4개 저장소의 AGENTS.md는 96줄), 꼭 지킬 규칙은 테스트나 설정으로 옮깁니다. 전역 지침의 "한국어로 답하기"는 그 뒤에도 5일에 걸쳐 깨졌습니다. 근거: CLAUDE.md 규칙 사고 6건
  4. 무인 실행의 규칙은 실행이 읽는 파일 하나에 둡니다. 하루 4번 도는 예약 작업은 혼자 할 일, 승인 뒤 할 일, 사람이 누를 클릭을 나눈 표를 먼저 읽습니다. 승인한 광고 재개도 도구의 권한 검사가 막아 사람이 켰습니다. 근거: 예약 에이전트의 권한 표
  5. 돈이 드는 경로는 값이 없으면 쓰지 않게 둡니다. 코드에 둔 2,500원 중단선은 응답 없이 끝난 호출 62번을 적게 세어 결제 2,956원을 놓쳤습니다. 근거: 2,500원 중단선과 2,956원

결과물 하나하나를 확인하는 방법은 AI 코딩 에이전트 '테스트 통과' 검증에 따로 모았습니다.

읽는 순서

병렬 운영은 연재 에이전트 여럿을 한 저장소에서, 규칙과 메모리는 연재 에이전트에게 규칙과 선 전하기로도 이어집니다.

  1. 에이전트는 몇 개까지 동시에: 상한을 정한 메모리와 폰 계산입니다.
  2. 한도로 끊긴 서브에이전트 5개: 이어받기를 살린 것은 보고서가 아닌 원본 파일이었습니다.
  3. 공유 파일마다 주인 정하기: 파일 50개가 섞인 사고와 병합 13번의 결과입니다.
  4. 커밋 전 --check 하나: 따로 고친 작업을 합친 뒤에만 나는 문제를 막습니다.
  5. 합친 코드의 결함 12건: 브랜치 리뷰가 못 보는 곳을 읽는 리뷰입니다.
  6. 반박을 버틴 발견만 고치기: 리뷰 지적을 거르는 절차입니다.
  7. 설계 3안과 심사자 3명: 에이전트 45개가 59분 동안 코드 없이 설계를 고른 기록입니다.
  8. AGENTS.md 작성법: 에이전트가 틀리는 규칙만 적는 법입니다.
  9. CLAUDE.md 규칙과 재발 기록: 적은 규칙이 얼마나 다시 깨졌는지 세어 봤습니다.
  10. 자동 압축 9번과 메모리 색인: 압축 뒤 남는 것과 빠지는 것입니다.
  11. 혼자 할 일과 사람이 누를 클릭: 무인 실행의 권한을 세 칸으로 나눈 표입니다.
  12. 비밀값을 채팅, 로그, 토큰에서 지키기: 값 대신 위치와 종류만 말하게 합니다.
  13. 트레일러 없는 커밋 29개: 그중 26개를 에이전트가 만들었습니다.
  14. GA4의 0과 합계 행: 에이전트가 10분 26초 만에 거둔 잘못된 보고입니다.
  15. gcloud 차단된 앱 우회: 같은 차단을 세 번 겪고 키 파일 없이 푼 방법입니다.
  16. Vertex AI 비용 하드캡: 에이전트가 쓰는 돈의 기본값입니다.
  17. WSL에서 Windows 네이티브로: 옮기는 나흘 동안 에이전트가 틀린 5가지입니다.
  18. 하네스란 무엇인가: Windows 하네스 연재 1편, 맞는 사람인지 판단합니다.
  19. PowerShell 처음 열기: 연재 2편, 명령 붙여넣기입니다.
  20. Git과 Claude Code 설치: 연재 3편입니다.
  21. 로그인과 첫 무인 질문: 연재 4편, claude -p로 한 번 묻고 끝냅니다.
  22. Docker Desktop 설치: 연재 5편, 건너뛰어도 됩니다.
  23. 키트로 첫 작업 돌리기: 연재 6편, 예약 전에 손으로 한 번 돌립니다.
  24. 작업 스케줄러로 매일 돌리기: 연재 7편, 매일 같은 시각 실행입니다.
