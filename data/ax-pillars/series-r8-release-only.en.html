What this series found

  • On September 23, 2026, R8 removed a constructor and every release build of Compress Image, our first app, crashed at launch. We had never run a release build on a device before; now every upload passes three checks first. (Part 1: pre-release checks)
  • R8 renamed the Gson fields output and etype to a and b. Without @SerializedName, results would have come back empty with no exception, while 203 unit tests passed because they ran on unshrunk classes. (Part 2: renamed Gson fields)
  • A Block Turn AAB built with real ad IDs still held 5 Google test ad strings in its dex. R8 could not fold a listOf(...).any condition at build time; a plain || between constants took the count to 0. (Part 3: leftover test ad IDs)
  • With -dontoptimize removed, Play Console still showed 36% optimized and 39% obfuscated and shrunk (September 25, 2026). Deleting an unused Kakao SDK keep rule took r8.json to 85% and the AAB to 11.6 MB. (Part 4: one keep rule)

This series is for anyone shipping Android apps through R8, the code shrinker in release builds, and especially for code written by an AI coding agent. Read the three checks in Part 1 first. If you use a reflection-based library such as Gson, go to Part 2; if the app shows ads, Part 3; if Play Console reports low DEX optimization, Part 4. None of the four defects showed up in a debug build or a unit test. Each one needed the release artifact run on a device or its dex opened directly.
