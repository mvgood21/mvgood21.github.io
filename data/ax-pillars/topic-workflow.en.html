The short answer: builds and devices set the limit, not the agent count

A Claude Code main session can start many subagents at once, but at SugarMount, a solo app studio, no more than three code-writing agents ever ran at the same time. On October 3, 2026 the operator said "use hundreds of agents if you like." The ceiling came from 4 GB of free RAM (out of 13 GB) and two test phones shared by five sessions. Research and design agents, which never build, reached 11 to 14 at once.

The repository logged 59 commits that day, and a single integration agent merged ten workstreams stage by stage. The 41 implementation agents reported "all complete, no failures," and the app crashed on its first launch on a real phone. In a second app, 13 branches each passed their own review and CI, yet a review that read only the merged code confirmed 12 blocker or major defects (11 distinct, since one was found from two sides). The rules below come from these measurements.

How many agents should run at once, and how do you split the work?

  1. Set concurrency by the memory one build needs and the devices you have. Every code-writing agent had to pass unit tests and a debug build before each commit, so three was the cap. Over two days, 114 of the 148 messages between sessions were about taking turns on the two phones. Evidence: memory and test phones set the limit
  2. Define "done" as a build running on a real device. The 41 "done" reports covered only JVM tests and compilation. The crash appeared when the app was installed a minute after the report: the build tools had stripped a trailing .gz from asset names, so the level file was missing. Evidence: 41 "done" reports and a first-launch crash
  3. Give every shared file exactly one owner. On September 23, 2026, a release-fix commit swept in 50 files another session in the same working tree was still writing. A later app wrote an owner table first and merged 13 branches in 2 minutes 11 seconds; even so, 7 merges needed a hand and 8 branches edited a file someone else owned. Evidence: the file owner table
  4. In a shared working tree, no unrequested commit, stash, reset or gradlew --stop. One session's launch-check script ran gradlew --stop, and two clean builds in another session on the same PC died. Evidence: two sessions in one working tree
  5. After merging, run a separate review that reads only the merged code. On an integration branch where all 2,115 tests passed, six review agents raised 32 findings; of the 12 blockers and majors confirmed by refutation, 10 were broken agreements between code from two different packages. Evidence: 12 defects after every branch passed review

How do you brief agents, and what should they leave behind?

  1. Tell subagents where and when to write raw evidence. Between September 7 and 10, 2026, five subagents stopped at a usage limit with nearly empty reports. The agents that took over finished from the logs, screenshots and edited files left on disk. The bans in the 33-line shared brief held: 13 reports wrote "approval needed" instead of installing anything. Evidence: what survives a subagent cut-off
  2. Write the reason for a decision into a memory file when you make it. One 13-day session was auto-compacted nine times, keeping 2.6% to 8.2% of its tokens each time. None of the nine summaries kept why the ad budget differed from the runbook. Evidence: what survives auto-compaction
  3. Treat CLAUDE.md as context, not enforcement. Write only the rules an agent gets wrong, with the reason (our four-app repository's AGENTS.md is 96 lines), and turn the rules that must hold into tests or settings. A global "reply in Korean" rule still broke on five later dates. Evidence: six CLAUDE.md rule incidents
  4. Put the rules for unattended runs in the one file every run reads. Our scheduled agent runs four times a day and reads a table first: what it does alone, what it does after approval, and the clicks a person makes. Even an ad restart the operator had approved was blocked by the tool's permission check, and a person switched it on. Evidence: a permission table for a scheduled agent
  5. Where an agent can spend money, a missing value should mean no spending. A 2,500 KRW stop line in code undercounted 62 calls that ended without a response and missed a 2,956 KRW bill. Evidence: a cost cap that missed the bill

How to check each result an agent hands back is covered in what to check when an AI coding agent says tests pass.
