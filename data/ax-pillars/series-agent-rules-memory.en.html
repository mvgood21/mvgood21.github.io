What this series found

  • The AGENTS.md in the repository that shipped four Android apps is 96 lines long. It lists only the rules the agent tends to get wrong, each with a reason, and the rules that must never break are also enforced by tests. (Part 1: writing AGENTS.md)
  • CLAUDE.md is context, not enforcement. Recounting session logs, the "answer in Korean" rule broke on five dates after it was written, and a pkill rule saved in one project's memory broke 7 more times in other projects. (Part 2: rules and repeat incidents)
  • One session ran 13 days through 9 auto-compactions, and no summary kept why the ad budget was set to 2,000 won instead of the documented figure. A reason survives only if it goes into a memory file at the moment it is decided. (Part 3: nine compactions)
  • A marketing agent scheduled four times a day reads one permission table at the start of every run, because rules given in chat never reached scheduled runs. Even an ad restart the operator approved was refused by a tool permission check, so a person made the final click. (Part 4: the permission table)
  • Secrets leaked three ways: chat logs, app logs and deploy tokens. The first secrets rule appeared 47 seconds after a key showed up in a session log, and a log-masking regex had been copied into four files while two exception paths never masked at all. (Part 5: secrets in three places)

This series is for developers who write instruction files for an AI coding agent such as Claude Code. If you are writing your first one, read Part 1; if the same mistake keeps coming back, Part 2; if earlier decisions fade during long sessions, Part 3. If your agent runs unattended on a schedule, read Parts 4 and 5 first. Across all five parts, files read on every run and checks that run every time held longer than rules said once in chat.
