Commits without a Co-Authored-By trailer: the agent made 26 of the 29 we could check

Do not report a Co-Authored-By count as the share of AI-written code. Of 29 commits without the trailer that we could check against session logs, the agent made 26.

By SugarMount · Working with agents · 8 min read · Last updated November 13, 2026

AI coding agents such as Claude Code add a Co-Authored-By: Claude line (a trailer) to the end of their commit messages, so it is tempting to count trailer commits and call that the AI's share. We checked the trailer-less commits in the repository of our Korean spell-checker app against the agent's own command history: 26 of 29 were merges (25) and a revert (1) that the agent ran.

When an agent runs git merge or git revert with git's default message, the trailer is simply not there. A trailer count is a lower bound on the agent's work, and it only becomes accurate once the agent's instructions say to add the trailer to merges and reverts too.

Matched against session logs, 26 of 29 were agent commands

A missing trailer says nothing about who made the commit. So we went through the Claude Code session logs (JSONL files) and collected every command the agent ran that contained git commit, merge, revert, stash, tag and the like and pointed at this repository. A commit counted as "agent command found" when such a command ran between ten minutes before and 30 seconds after the commit time.

The logs cover the evening of September 13, 2026 to October 24, a window with 282 commits. All 253 commits with a trailer matched an agent command, so the method finds the agent's commits without missing any.

In this window 89.7% of commits carry the trailer, but 279 commits, 98.9%, match a git command the agent ran. The gaps came in three shapes:

  • git revert --no-edit: it reverted a trailer commit made 28 minutes earlier, and the revert itself has no trailer.
  • git merge --no-edit main: git's default merge message has no trailer.
  • git merge -m "…": the agent wrote the message itself and still left the trailer line out.

The three merges in the same period that do carry a trailer are all cases where the agent put the trailer into its -m message. The remaining three (a version commit and two release merges) have no matching command in the logs, so we left them undecided.

Matching on time alone could produce coincidences, so we shifted every commit time by three hours in each direction and ran the same match. Only 17 and 15 of the 253 trailer commits matched (6 to 7%), and 0 and 1 of the 29 without a trailer.

Over a longer window, most of the 89 gaps are merges and stash

Without session logs, all you can sort by is subject line and date. Since August 1, 2025, 345 of the spell checker's 434 commits (79.5%) carry the trailer. The 89 without it break down as below. We matched Co-Authored-By: Claude at the start of a message line, and git's own trailer parser gave the same count.

The two stash entries are not commits anyone meant to count. git log --all follows refs/stash as well, so the newest stash and its index commit show up. Put --exclude=refs/stash before --all and the share becomes 345 of 432 (79.9%). Drop merges and start the window at the first trailer, and it rises to 342 of 372 single-parent commits (91.9%).

The five data or config commits were image and PSD files, two-line version bumps, a .gitignore cleanup and quiz data. All 24 code commits fall between August 9 and September 13, 2025; one of them is the operator reverting source the AI had changed wrongly (the story is in our note on 701 commit messages).

Repositories built with the agent from day one look the same. All 10 trailer-less commits in the puzzle game are merges, and all 10 line up with an agent git command in the session logs. In the utilities app, 5 of the 6 merges are the agent running git merge --no-edit on branches from the worktree folders Claude Code created for its subagents. The one single-parent commit there is the agent's own git commit -m without the trailer line. The single gap in the P2P chat app is its root commit, "first commit".

We looked for other signals and found none we could use. Every commit had the same author account. Two pull requests labeled codex were closed without merging, so their commits never appear in git log --all. Branch names survive a merge only in the merge commit's subject.

Counting your own repository

These run as-is in Git Bash or a macOS or Linux shell. Change the cutoff and the trailer text to match your repository.

U=2026-10-25T00:00:00; S=2025-08-01T00:00:00
P='^Co-Authored-By: Claude'
# 1. total and trailer commits (stash excluded)
git log --exclude=refs/stash --all --since=$S --until=$U --format=%h | wc -l
git log --exclude=refs/stash --all --since=$S --until=$U -i -E --grep="$P" --format=%h | wc -l
# 2. commits without the trailer, merges among them
git log --exclude=refs/stash --all --since=$S --until=$U -i -E --grep="$P" --invert-grep --format=%h | wc -l
git log --exclude=refs/stash --all --merges --since=$S --until=$U -i -E --grep="$P" --invert-grep --format='%h %s'
# 3. cross-check with git's trailer parser
git log --exclude=refs/stash --all --until=$U --format='%(trailers:key=Co-authored-by,valueonly)' | grep -ci claude
# 4. single-parent commits without the trailer, with size
git log --exclude=refs/stash --all --no-merges --since=$S --until=$U -i -E --grep="$P" --invert-grep --stat --format='%h %ad %s' --date=short
  1. Fix the cutoff with --until. In a repository that gets commits every day, the totals change within hours; this one got five new commits on the morning of October 25 alone.
  2. Find the date of the first trailer (first line with --reverse) and start the window there.
  3. Sort the commits without a trailer into merges, stash entries, data or config, and code.
  4. If you have session logs, match commit times against the times of the agent's git commands, and shift the times by a few hours to measure how often they match by chance.

To close the gaps going forward, tell the agent in its instruction file (CLAUDE.md for Claude Code) to add the trailer to merges and reverts as well. For a merge, put it on the last line of git merge --no-ff -m "message"; for a revert, run git revert --no-commit <commit> and then git commit -m with the trailer. After resolving a merge conflict, add the same line to the git commit -m that concludes it.

Periods without session logs and squash merges cannot be settled

In the spell checker, the 51 trailer-less commits made after the first trailer but before the session logs start (23 merges, 28 single-parent commits) stay undecided. The 24 code commits among them added 5,749 lines of Kotlin and Java, while the 39 trailer commits of the same weeks added 14,762. Why a trailer count is not a share of code lines is covered in the 701-commit note.

With squash merges, one pull request becomes one commit, and the trailer depends on the tool of whoever presses the merge button. In repositories with many contributors, each person's commit habits make the ratio harder to read. Tools that keep no session logs, or setups that delete them, rule out the cross-check entirely. In a GitLab survey of 1,528 developers and technology buyers in six countries, released on June 23, 2026, 43% said they cannot reliably tell AI-generated code from human-written code (GitLab press release).

What we will check next

When we checked on October 25, the spell checker's instruction file said nothing about trailers. Once a rule for merges and reverts is written down, the trailer-less merges have to be counted again to see whether it worked.

Frequently asked questions

Does a commit without a Co-Authored-By trailer mean a person wrote it?

No. When the agent runs git merge or git revert --no-edit with git's default message, or passes -m without the trailer line, the commit it makes has no trailer.

What extra commits does git log --all count?

Besides every branch and tag, it follows refs/stash, so the newest stash and its index commit count as two commits. git log --exclude=refs/stash --all leaves them out.

Can a merge commit carry a Co-Authored-By trailer?

It can if you pass the message yourself with git merge --no-ff -m "message" and put the trailer on its last line. After a merge conflict, add the same line to the git commit -m that concludes the merge.
