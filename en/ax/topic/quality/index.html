Testing and release

Unit tests, release gates and on-device checks that AI-written code goes through before each release, with the real defects those checks caught along the way.

4 notes

  • Working with agents
  • Android development
  • Game development
  • Play Store and monetization
  • Website and search
  • Retrospectives and numbers

Notes

  • Our contrast checker passed while skipping 40% of the text: make it print how much it measured

    A contrast check that passed in three themes had silently dropped 3,762 of 9,318 text fragments (40%). Now it prints what it measured and fails on a shortfall.

  • 3,066 green tests hid a line that breaks opening the database: checking tests by deleting the guard

    A P2P chat app passed 3,066 tests while one SQLite pragma, traced through plugin source, kept its database from opening. Now we judge tests by deleting guards.

  • The agent said it was tested. The game crashed on the first tutorial tap: a missing VIBRATE permission and the fresh-install monkey test

    Our AI agent called a puzzle game crash-free, then it died on the first tutorial tap: a missing VIBRATE permission. adb monkey on clean data hit it at event 15.

  • What to check before shipping an AI-built Android app: the release gate and an R8 crash

    Our Android app ran fine in debug but crashed at launch in release after R8 removed a constructor. Now every upload passes three pre-release checks.
