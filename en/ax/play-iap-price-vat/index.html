Play Console in-app price VAT: 7,500 became 8,000

The Korea price field in Play Console takes the amount before VAT, so typing KRW 7,500 for our one-time in-app product made the buyer price 8,000 won.

By Stephen · Play Store and monetization · 4 min read · Last updated November 19, 2026

We typed 7,500 won into Play Console, and the next day the Pro price on the app's settings screen read 8,000. This was October 2026, while setting up the one-time Pro purchase for SugarDoc, our viewer for Korean HWP documents. The AI coding agent had guessed the field was tax-inclusive, while the owner's first take, that Play adds 10% to the console price, was the right one.

We sent 6,900 and Play stored 7,500

On October 5 a Claude Code agent created the product through the Play Developer API (Google's API for doing Play Console work from code) and sent the owner's chosen price of 6,900 won. Reading the product back, the Korea price was 7,500. The agent took that for a conversion bug and tried to overwrite it with 6,900; the auto-mode permission classifier blocked the edit because it changes what real buyers pay.

The owner answered on the spot that 6,750 in the console would come to 7,500 for buyers once Play added 10%. The agent replied that 6,750 plus 10% is 7,425, so the numbers did not match, and labeled as a guess that the stored 7,500 was probably already the tax-inclusive buyer price. In the same reply it explained 7,500 as 6,900 plus 10% (7,590) rounded down to a price point, yet left rounding out when it checked the owner's 6,750. The owner typed 7,500 into the console, and the agent updated the docs from the owner's message without reading the stored price again.

On October 6 the on-device end-to-end (E2E) report caught 8,000 won on the settings screen. The app never hard-codes a price; it shows whatever Play returns, so the console value went straight to the screen.

On October 8 the agent put the two input and stored pairs side by side and wrote that its tax-inclusive guess had been wrong. The owner typed 5,000, the Korea price the API returned was 5,500, and the agent fixed the docs within the same minute.

The conversion API takes a pre-tax price and returns a taxed one

Google Play's help page on tax rates lists South Korea among the countries where the price shown to buyers must include tax. The API reference for convertRegionPrices describes its input price as "Tax exclusive" and each converted region price as "tax inclusive."

Write down the price you read back

Since the classifier block on October 5, the owner changes prices in the console and the agent only reads them.

  1. Take the Korea price you want buyers to pay and divide by 1.1; that goes in the console (5,000 for 5,500). If the result is not a round number, the stored price may be moved to a nearby price point.

  2. After saving, read the buyer price from the product GET's regionCode KR entry or from the store listing.

  3. Record both numbers, for example "buyer 5,500 won (console 5,000)."

  4. If you create products through the conversion API, note in a code comment that its input is pre-tax.

Update a documented price only from the value you read back after saving. A different Play API result we failed to check before acting is in Play staged rollout API: 20% went out as 100%.

These records cover one one-time product in October 2026; we have not checked subscriptions or accounts that file Korean VAT themselves as a local business. The console path, where 7,500 typed in became 8,000, is something we observed; we could not confirm from the help pages that the same rounding rule applies there. The product script overwrites only the Korea price with the buyer price, while converting every other region from that same number as if it were pre-tax, so other regions may be priced higher than intended. We have not rerun it to check.

As of 2026-11-18. Sources: app repository git history (commit 2cc25d1, PRD and implementation plan), agent session logs (2026-10-05 to 10-08), a read-only Play Developer API query, Google Play Console Help and the Android Publisher API reference.
