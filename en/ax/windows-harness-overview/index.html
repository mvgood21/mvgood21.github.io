A Windows harness for scheduled Claude Code: how one PC runs a game app's marketing

A harness runs Claude Code at set times with nobody watching, keeps a record of what happened, and blocks risky actions. It only runs while the PC is on and you are signed in.

By SugarMount · Working with agents · 10 min read · Last updated November 11, 2026

Windows harness series, part 1 of 5 · The big picture and what you need

At SugarMount, scheduled jobs read the ad numbers for two puzzle games (Arrow Knots and Block Turn), check that ad budgets stay under their caps, and post short videos to TikTok. On November 10, 2026, the game daily job ran for 13.8 minutes in the morning, and in the evening the game social job posted one Arrow Knots video to TikTok, Instagram and YouTube.

This five-part series is written for solo app makers who have never set up developer tools. Part 1 is the map you read before installing anything.

What the harness ran on November 10

The chart below comes from the runner logs for that day. The runner is a PowerShell script that executes one job and logs its start and end times.

Read the three morning bars as one queue. The Korean spelling app's daily started at 09:11 and took 29 minutes, the utility apps took 27, and then the game daily began. They never overlap, because they would fight over Chrome and the Android emulator, so a job called the dispatcher starts each one only after the previous one ends.

The comb along the bottom is three upkeep jobs that wake every 15 minutes (the dispatcher, a watcher, and a job that promotes new harness code). They ran 284 times that day, and none of them calls an AI model.

Every run that day ended with status ok, but ok only means the job ended without an error. The 18:07 utility social run posted nothing because its video queue was empty, and it was still ok. Since November 11, every job ends with a verdict line, either complete or partly failed, and the daily status board counts those lines.

Each job names its model from Claude's three tiers. Dailies, which make the most judgment calls, get the strongest, Opus; posting, which clicks through known screens, gets the middle tier, Sonnet; self-checks get the lightest, Haiku. One game daily run walks through seven steps within a 5,400-second limit.

In step 5, the internal test track is Play's channel for shipping to testers first, and a 20% staged rollout sends the new version to only 20% of users at first.

A schedule inside a chat session stops when the session closes

Before the harness, the app dailies were scheduled inside Claude Code chat sessions (session cron). Those schedules only run while the session is open, and the harness README's switch-over checklist lists ending the session as a way to turn them off. The harness hands the clock to Windows Task Scheduler and does the thinking with claude -p, which runs one task without a chat window and exits (headless mode).

The scheduled jobs' login and instructions live in a separate config folder. In a November 11 test, a job run without one ended its answer in the "done / result / what's left" format from the personal instruction file we keep for chat. A separate folder lets you manage the instructions and login for scheduled jobs on their own. It does not strip that format by itself: our real folder has the same summary rule copied in, and the November 10 game social answer ended the same way. Copy your chat instructions over as they are and the format comes along (part 2).

The first night we compared the two systems, October 26, the AI's check was wrong. The comparison report found no output from the old schedules and said the run appeared not to have happened; two minutes later, that day's record was committed to the game repository (the git store for its code and notes). The next day's report traced it to two things: the check ran two minutes before the commit, and git log --since given only a date reads it relative to the current time and skipped that day's commits. That record itself noted that all schedulers had been stopped on the operator's instruction. When you search history by date, add a time.

An older harness built with bash and crontab inside WSL (the Linux environment that runs inside Windows) was frozen on October 25; we carried over its lessons, not its code, and started the Windows one from scratch (first commit 0114edc). For Task Scheduler we chose "run only while signed in" over storing a password, so jobs use the Claude login already in the user profile.

When we switched to live runs on October 27 (305934e), the first checklist item was a person's job: turn off the old session schedules. If both run, the same day gets two releases and two rounds of posts. Never leave both on.

The parts, from job file to data server

Task Scheduler calls the runner at the set time. The runner reads the job file and feeds the prompt to claude -p; a guard hook checks every tool Claude tries to use, and results land in log and state files.

Notion is a note and database app; here it holds the approval inbox and the daily reports. What the AI may do alone is split three ways: free marketing and store text it just does, money, new campaigns and permission changes go to the inbox, and force pushes, printing secrets or a 100% rollout are blocked by the guard hook. How we arrived at that table is in A permission table for a scheduled AI agent.

You don't need every part on day one. The minimal kit in part 4 is three files (runner, job file, prompt) plus Task Scheduler. Docker only comes in when you want a server that collects data every day or MCP servers (connectors that give Claude outside tools such as GitHub) running in containers.

A different number got labeled the level-one solve rate

On October 26, the shadow game daily correctly reported two numbers for Block Turn 1.1.6: 5 players had finished all three tutorial levels, and 8 had opened the app. The mistake came in the approval request. It called that 5/8 the level-one solve rate, and although the run had read the 6/8 figure in the repository, it never compared the two.

A check the next day, querying GA4 again, laid out the difference. The run had pulled events by app version only, without the value that identifies the level (pid), so no level-one number could have come out of it.

The 5/8 in the requestLevel-one solve rate
Numeratortutorial_complete users (cleared all three tutorial levels)Level-one level_up users
Denominatorfirst_open usersLevel-one level_start users
Result5/86/8 (75%)

An ad budget hung on that number. Approval request GAM-1026-1 proposed cutting the daily budget from KRW 4,000 to KRW 2,000 if the new version's level-one solve rate was no better than 1.1.6's. The check found that the wrong baseline would make the new version look clearly better and cancel the cut, while the right one put the gap at one player or less, which meets the condition for the cut.

No money moved. The run was in shadow mode, and even a live run cannot act on an approval request until a person approves it. The game daily's prompt now defines the level-one solve rate and, below 20 players, writes the fraction next to the percentage (more in part 5).

What to have ready

We checked these requirements against the Claude Code, Microsoft and Docker documentation on November 11, 2026.

  • A Windows PC. Claude Code runs on Windows 10 1809 or later or Windows 11 with 4 GB of RAM, and does not need administrator rights. Docker Desktop's documented list asks for 64-bit Windows 11 Pro, Enterprise or Education 23H2 or later and 8 GB of RAM; Home edition is not on that list (part 3). To see your edition, press Win+R and type winver.
  • A paid Claude plan: Pro, Max, Ultra, Team or Enterprise, or a Console (prepaid API) account. The free claude.ai plan does not include Claude Code.
  • A Google account with access to GA4, Google Ads and AdMob (Google's in-app ad revenue service), for user, ad spend and ad revenue numbers.
  • A Notion workspace for the approval inbox and daily reports.
  • TikTok, Instagram and YouTube accounts; the social job posts through Chrome.
  • A PC that stays on and signed in. Runs missed while it was off or asleep can be set to run once when it wakes (part 4).

Part 2 installs the software: Git for Windows (recommended), Python (for the GA4 and AdMob helper scripts), then Claude Code.

When this setup is the wrong choice

If the PC can't stay on every day, look elsewhere. Task Scheduler only wakes jobs while you are signed in, and a missed run happens once after the PC wakes.

If you want the AI to own ad budget decisions outright, this setup will not do it. The harness can change budgets only inside the range the operator delegated on October 30: at most KRW 5,000 a day per app and KRW 12,000 in total, a cap that even an approval cannot lift. New campaigns, pausing, bids and targeting all go through the approval inbox.

Scheduled jobs also draw on your Claude plan's usage limits. On October 30 the weekly usage limit was hit, and all three app dailies and three game social runs ended within 2 to 5 seconds.
