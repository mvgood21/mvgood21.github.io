Run Claude Code every day with Task Scheduler

One line with register-job.ps1 schedules hello for the same time every day. Each morning, the status table shows the last result, the next run and whether you need to log in again.

By SugarMount · Working with agents · 9 min read · Last updated November 13, 2026

Windows harness series, part 7 of 11 · Previous Download the kit and run a first job · Next A morning GA4 report job

This part puts the hello job from part 6 into Windows Task Scheduler, the scheduling tool built into Windows. Once it is registered, hello runs by itself at the same time every day, as long as the PC is on and you are logged on.

You keep using the $HOME\harness folder from part 6. You do not need an administrator window. The kit's console lines and the status table are in Korean, and this page translates them; to get English answers from Claude, point a job card at the English prompts in prompts/en as shown in part 6, step 3.

When you finish this part

  • Result: hello runs by itself at 09:05 every day (while the PC is on and you are logged on).
  • You need: a PC that has finished part 6 (hello ran by hand).
  • Cost: none. Scheduled runs use the Claude plan you logged in with in part 4.

Step 1: Register hello for 09:05 every day

  1. Open a new PowerShell window and go to the kit folder.

    cd $HOME\harness

  2. Paste the execution policy line from part 6, step 4. register-job.ps1 is a script too, so this window has to allow it.

    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

  3. Register hello. After -At, give the time as hours:minutes.

    .\register-job.ps1 -Name hello -At 09:05

You are done when

You see TaskName : hello and a NextRunTime line with the next run time. On our Korean-language PC it read 2026-11-12 오전 9:05:00 (오전 means AM); your date and format will differ.

register-job.ps1 registers the job with these settings. The values below were read back from Task Scheduler after registering.

SettingKit valueIn plain words
TimeDaily at 09:05Starts at the same time every day.
Missed runs (StartWhenAvailable)OnIf the PC was off or asleep at that time, the job runs once after it is back on.
BatteryStarts on battery, keeps runningBy Windows default, a task does not start on battery and stops if the PC switches to battery. The kit lets it run on a laptop battery.
Overlap (MultipleInstances)IgnoreNewIf the previous run is still going, the new one is dropped.
Run limit (ExecutionTimeLimit)Job card limit + 10 minutes, at least 1 hourThe job card (the job definition file in the jobs folder) sets a time limit; the kit adds 10 minutes. Past this, Task Scheduler stops the job. The Windows default is 72 hours. In our test a 300-second job got 1 hour and a 5,400-second job got 1 hour 40 minutes.
Logon (LogonType)InteractiveRuns only while you are logged on. No password is stored.
Rights (RunLevel)LimitedRuns with normal rights, not as administrator.

At run time, Task Scheduler starts PowerShell with a hidden window (-WindowStyle Hidden) and with the same Bypass execution policy as part 6 (-ExecutionPolicy Bypass), then runs run-job.ps1. That is why scheduled runs do not need the line from part 6. Even with the window hidden, a window may flash briefly as the run starts.

Registering the same name again replaces the earlier schedule, so to change the time, run the same command with the new time. The schedule goes into a folder named \my-harness\ inside Task Scheduler.

Step 2: Start it once now

Instead of waiting for 09:05, start the scheduled job right away.

  1. Start the job now. This command only starts it and returns at once.

    Start-ScheduledTask -TaskPath '\my-harness\' -TaskName hello

  2. Wait about 15 seconds, then look at the last-run information. In our test it started at 2:22:05 AM, and the status table's finished-at time was 02:22:13.

    Get-ScheduledTaskInfo -TaskPath '\my-harness\' -TaskName hello

  3. Check that new start and end lines were added to the log.

    Get-Content .\logs\hello.log

You are done when

LastRunTime shows the time you just started it, and the last log line shows status=ok exit=0.

LastTaskResult is the result the last run returned. It was 0 in our test, and the state file said ok at the same time. Microsoft's docs do not list what each number means, so judge a run by the log and the state file.

Step 3: Check the status table each morning

The status table is what status.ps1 shows: one row per job with its last result, finish time, next run and a sign-in warning. There are two ways to open it.

Way 1: double-click status.cmd in File Explorer

  1. In File Explorer, open the harness folder inside your user folder. If a PowerShell window is open, this line opens it too.

    explorer $HOME\harness

  2. Double-click status.cmd. A black window shows the status table, and the last line reads Press any key to continue . . ..

  3. Read the table, then press any key to close the window.

status.cmd calls status.ps1 with the Bypass execution policy, so it needs no execution policy line. We ran it through cmd on our PC and saw the table and that last line.

Way 2: in a PowerShell window

  1. Open a window, enter cd $HOME\harness and the execution policy line, then show the table.

    .\status.ps1

The table headings are in Korean. Read them left to right:

  • 작업 (job): the job card name from the jobs folder.
  • 마지막결과 (last result): the result from the state file (ok, error or timeout). A job that has never run shows -.
  • 끝난시각 (finished at): when the last run ended.
  • 다음예약 (next run): when Task Scheduler will run it next. A job that is not scheduled shows 등록 안 됨 (not registered).
  • 로그인경고 (login warning): 다시 로그인 필요 (log in again) appears if the last run printed the login expiry warning. Log in again as in part 4, step 5.

A last result of ok only tells you the run ended without an error. Every kit prompt ends its report with a verdict line, 판정: 완료 (done) or 판정: 일부 실패(reason) (partly failed), or Verdict: done / Verdict: partial failure (reason) with the English prompts, so read that line too. Open the most recent report with this line:

notepad .\reports\latest-hello.md

Step 4: Schedule other jobs, and remove one

You register ga4-daily, ads-check and shorts-plan one at a time in parts 8 to 10. In each part you add your data and run the job once by hand, then register it with the same register-job.ps1 command, spacing the times apart (for example 09:30, 09:40 and 10:00). On the practice data, all three jobs finished within 20 seconds.

To remove a schedule, use the line below. It prints a Korean line saying the hello schedule was removed, and the kit files stay where they are. Afterwards the next-run column in the status table reads 등록 안 됨 again. Removing a schedule that does not exist ends with an error, and that line is not printed.

.\remove-job.ps1 -Name hello

In the real harness

As of Nov 11, 2026, the SugarMount harness had 14 jobs registered in one Task Scheduler folder, and that morning every LastResult in the list was 0.

The kit is a cut-down version of this harness. The real one has extra safeguards added after something went wrong; two of them came from these events.

SafeguardWhat happenedIn the kit
Separate production copyFrom the evening of Nov 4 to the morning of Nov 6, about 38 hours, every job stopped at a pre-run check. Harness code that was being edited had not been committed (recorded as final) in the repository. Since Nov 7, production runs from a separate copy, and only changes that pass checks reach it.None
Verdict lineOn Nov 10 one app's social job posted nothing because there was no video queued, yet its status was ok, and that night's daily summary said zero failures or misses. Since Nov 11 every job ends with a verdict line.Yes, in all four prompts

The way the window is hidden also differs. The real harness starts PowerShell through conhost.exe --headless, but we found no official documentation for that option, and security tools sometimes treat it as a warning sign, so the kit does not use it.

FAQ

What happens to a scheduled job if the PC is off?

It does not run at that time. The kit registers missed runs to fire once after the PC is back on, and even then you need to be logged on.

Do scheduled jobs run on a laptop battery?

With the kit, they do. By Windows default a task does not start on battery, but register-job.ps1 sets it to start on battery and keep running.
