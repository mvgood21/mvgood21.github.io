Claude in Chrome set up 4 Google Ads campaigns

Two Claude in Chrome sessions built four Google Ads app campaigns with 966 screen actions, and the operator's corrections were all settings: budget, bid, country and language.

By Stephen · Working with agents · 9 min read · Last updated November 18, 2026

While two browser agents built four Google Ads app campaigns, the operator had to give the same budget correction twice, 24 minutes 40 seconds apart, once to each session. The operator never once pointed out a wrong click. There was one report of a frozen screen, which the agent itself put down to a dialog it had hidden with a page script.

The two Claude Code sessions, one per puzzle game, started 24 seconds apart on the night of October 8, 2026, in the same Chrome and on the same ads account.

What we counted: 1,436 tool calls in two session logs

The tool was Claude in Chrome, a browser extension that lets the agent take screenshots, click and type in the user's signed-in tabs. Session A handled Arrow Knots, session B handled Block Turn. Both were told to stop on the review screen, the summary page shown right before Publish, and never press Publish. We didn't use the Google Ads API that night; the prompt asked for Chrome from the start.

We counted each tool_use entry (one call the agent made to a tool) by tool name.

The flat stretch (from 22:51 for B and 23:06 for A until about 00:40) has no operator messages, and neither session made a tool call in it.

Only 201 of the 703 screen actions were clicks

When we picked this topic, the working title was "703 clicks." Splitting the screen action calls by kind showed that number was never a click count.

140 of the 201 clicks were followed by a wait as the very next call, mostly 1 to 6 seconds (231 of the 249 waits), and the agent often took a screenshot to check the result.

Of its 136 page script calls (javascript_tool, which runs JavaScript inside the tab), just under half, 67 by a rough split on the code text, only read text off the page.

There were screen mistakes. The agent picked another app's item, hit "Yes" when the layout shifted, and merged two headlines into one field. The agents' own status messages mention 8 such slips, and the agent noticed and fixed or backed out of each before the operator said anything.

The same budget fix, given to each session separately

Session A's prompt told it to take settings from an ads doc in the game repo, which said a daily budget of 25,000 won and a target cost per install (target CPI). Before A entered anything, 65 seconds in, the operator overrode that. The new values were 2,000 won a day, no target CPI, all countries.

Session B got only the country part, told separately at 22:03; the budget and target CPI never reached it. The Block Turn runbook that B read said United States, a 1,400 won target CPI and 25,000 won a day.

After the operator told it to "analyze in depth and proceed," B entered the runbook's daily budget and, by its own calculation, a 700 won target CPI instead of the runbook's US-based figure.

At 22:22 the operator gave B the budget and CPI correction, 24 minutes and 40 seconds after giving it to A, less politely. The 2,000 won decided that evening was in neither document the prompts pointed to. The budget and CPI correction lived only in session A's chat, and parallel sessions don't read each other's conversations.

The language fix also went to each session separately. A's Korean-copy campaign targeted all countries, and the operator had added English to its languages directly. When the operator asked whether Korean-only assets could run worldwide, A answered that this would show Korean ads to English speakers. Within the next two minutes the operator told both sessions to split campaigns by language, pasting the instruction sent to A into B's window as well. Each game ended with a Korean campaign for Korea and an English one for Southeast Asia, each at 2,000 won a day.

Videos hit a channel permission, then the auto permission check

App campaigns take video only as YouTube links. Session A tried uploading from the asset picker, got an error, and when the operator asked it to upload them, put three Korean videos up as unlisted through YouTube Studio, starting at 22:35 and taking a little over four minutes.

At the same moment session B was stuck in the ads console's upload dialog. The Upload button was grey with a note saying the account lacked permission to upload to the channel. The account signed in to Google Ads was not the one that owned the video channel. The operator pasted A's reply ("Yes, I can upload them…") into B's window and asked why the other one could and B couldn't.

Session B once hid a video picker that wouldn't close by running a page script. When the operator reported the console frozen on "checking for errors" (22:37), B reloaded it and then named its own script as the cause. Under our current rule, if the Chrome extension is refused a site permission, the agent does not fall back to page scripts and hands that step to a person.

When B moved to YouTube Studio and sent the file, Claude Code's auto permission check stopped it. That check screens the agent's tool calls before they run when Claude Code is in auto mode. The reason given was "Unrequested Commit in a Connected App," which B read as the checker seeing an external publish nobody had clearly asked for.

B stopped there instead of working around it. When the operator asked at 00:39 why the videos weren't in, B proposed a one-line instruction naming the channel, three English and three Korean files, unlisted, not made for kids. The operator typed it as written, and all six were up within five minutes. Attaching them to the campaigns didn't finish that night because the ads tab stopped responding.

A memory file appeared 40 seconds after the fix

Forty seconds after the budget correction, session B wrote a memory file. Memory files are the project notes Claude Code reads, starting from their index (MEMORY.md), when a session begins. Its opening lines set the values the operator had chosen and said not to use the runbook's "US, tCPI 1,400, 25,000 a day." tCPI is short for target CPI.

Nine minutes after the language split it rewrote the file with the two-campaigns-per-language structure and the video upload route. Session A wrote its own file for Arrow Knots at 23:06, saying ad copy language matches target language.

Three days later, on October 11, the marketing session read both files six seconds after the operator mentioned the 2,000 won campaigns. When the operator said the dates had been changed in the console by hand, it updated the file on the spot. We found no later operator message in the marketing session log correcting budget, bid or language again.

Don't tell a browser agent a setting that isn't already in a memory file.

Settings go into the memory file first

  1. Before opening the browser, write location, language, daily budget, bid, copy language, video channel, the account that owns it, and the made-for-kids answer into a dated memory file, and point the prompt at that file, saying it wins over the docs if they disagree.

  2. Have the agent stop before Publish and return the review screen values in a table matched line by line against the memory file.

  3. To correct something, edit the memory file first, then tell every running session to reread it.

  4. For steps that publish outside the console, such as video upload, put channel, visibility and made-for-kids in one instruction.

The video assets came from app campaign ad assets from gameplay recordings, and the daily budget check on these campaigns is in a daily Google Ads budget check that only suggests. Another case of an agent reading a stale doc line as current is in the stale-doc session handoff note.

The memory file held a wrong number for nine days

On October 17 the marketing session asked to link GA4 using the ads account number from memory and got "invalid Google Ads account ID." Session B had copied an internal number out of the console's URL, and nobody noticed for nine days.

At 22:29 session A was handed, mid-run, the one-line index entry B had just written (all countries, 2,000 won a day, no target CPI) and later linked B's file from its own, but it never opened that file. Session B shows no sign of receiving A's file at all.

Next we'll confirm in the channel's permission settings which account really owns the video channel, since the two memory files disagree, and keep the ad settings in one file. We also haven't reopened the Block Turn runbook to see whether the US and 25,000 won values are still there.

FAQ

Should Claude in Chrome press Publish on a Google Ads campaign?

We didn't let it. Both sessions stopped on the review screen, and the operator handled Publish and identity verification. Publishing starts spending the daily budget, so compare the review screen against the memory file and let a person press it.

Why is the YouTube upload button grey in Google Ads?

Check whether the account signed in to Google Ads can upload to that channel. In our case the channel belonged to a different account, so the videos went up through YouTube Studio on that channel; attaching the links to the campaign didn't finish that night because the ads tab stopped responding.
