Claude Code handoff to a session that had stopped

Our Claude Code session handed work to the "dev session" its own docs named, but that session had stopped 25 hours before. We now write the owner, with a date, as one line in memory.

By Stephen · Working with agents · 4 min read · Last updated November 17, 2026

Six lines in three documents assigned work to "the other session" or "the dev session". On the afternoon of October 18, 2026, the Claude Code session running marketing for two of our Android games followed the rule line, said it would pass its day-one drop-off analysis to the dev session, and wrote four more dev-session lines into its drop-off report. The dev session's last record was a commit at 15:30 the day before.

At 16:52 the operator corrected it: there is no other dev session right now, and you own both games. Within three minutes the marketing session itself had built the test-device filter it had meant to ask the dev session for.

The plan line was written while the dev session ran

At 08:48 on October 17 the operator told the marketing session that another session was fixing the games from GA4 (Google Analytics 4) data, so it should stay on marketing. A dev session opened in the game repository had been working since 07:52 and committing fixes since 08:55. The plan document's third line, saying game fixes were being done by the other session, was written that morning. The operating rules that every scheduled run reads first also said "app code or build changes: the other session handles these."

At 15:29 the operator told the dev session, roughly, "commit, and another session will pick it up." It made commit 64267f2 and went quiet until October 22. Nothing the marketing session reads recorded that ending.

Not knowing that, the marketing session pointed at another session in 9 replies, 5 of them after the dev session had stopped. The last three came on October 18 between 16:27 and 16:41.

A present-tense rule outlived its session

The marketing session kept following the rule line its 09:17 scheduled run on October 18 had read, "the other session handles these", 25 hours after that session stopped. The day-one drop-off report it wrote at 16:38 mentioned the dev session four times; one line asked the dev session to filter two test phones out of GA4. Those phones were the ones this same work used.

Ten seconds after the correction the agent said the earlier "dev session" was just an earlier part of this same work, then grepped the three documents and found the six lines.

Once the GA4 report tool dropped test and review devices by default, organic installs in Korea (installs not from ads) for Block Turn since October 11 went from 7 to 2; the rest were test devices. The session deleted the rule line and rewrote the four report lines as past facts, but it left the plan alone, and its third line is still there on November 17.

Ownership as one dated memory line

Don't hand work to a session by name. Find the lines in your plan and rule documents that point at a session, then check the last message time in that session's log (a per-project jsonl file).

grep -n "다른 세션\|개발 세션" *.md

If the session has stopped, rewrite the line as a past fact and write the owner into project memory, the notes file Claude Code reads when a session starts. Fixing document lines alone means hunting down every document already written, and it does nothing for the next one. This project's memory now says the "dev session" in older documents was "Claude's own work in an earlier conversation" and must not be handed anything, and the memory index (MEMORY.md) carries one line: no other session (10/18).

That line is false when sessions really do run in parallel. At 16:34 the same day the operator told a session in another app repository that search work (SEO and GEO) would be handled in a different session. For that case we write an owner for each file, as in Multiple Claude Code sessions: one owner per file.

The same misreading also ran the other way. When the operator reopened the October 17 dev conversation on October 22, it listed the marketing session's GA4 analysis and test-device filter from the 18th and said other sessions had carried the work on in the meantime. Next to check: whether two sessions worked in the game repository at the same time after that, and how the "no other session" line was read that day.

Checked 2026-11-17. Two Claude Code session logs (marketing Oct 9 to 21, dev Oct 15 to 30, 2026, times in KST), game repository git history (commits d1f6de1, 64267f2, 44c6acd), current copies of the three operating documents and the grep output from 2026-10-18, project memory (2026-10-18).
