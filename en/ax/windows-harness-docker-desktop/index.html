Docker Desktop on Windows 11: from WSL 2 to hello-world (Windows harness, part 3 of 5)

Install WSL from an administrator PowerShell and restart, pick WSL 2 in the Docker Desktop installer, then confirm the whole setup works with one hello-world command.

By SugarMount · Working with agents · 10 min read · Last updated November 11, 2026

Windows harness series, part 3 of 5 · Previous: installing Claude Code · Next: scheduled runs with Task Scheduler

Every morning at 09:00 KST, a small server on this PC gathers the previous day's ad and analytics numbers for our game apps into one file, and an AI job reads that file to start the day's analysis. The server runs inside Docker. The install steps below follow the official docs; alongside them are two records from this PC: the first day, when Docker was up and the server still did nothing, and the night one WSL command took Docker down.

Two jobs Docker does in this harness

Docker runs programs inside containers, which keep each program apart from the rest of the PC. A container is created from an image, the blueprint file that holds the program and what it needs. This harness uses Docker for two kinds of server.

The first is a data collector: a web app plus a PostgreSQL 16 database, started together with Docker Compose (one file that describes several containers). At 09:00 KST, which is 00:00 UTC, it pulls yesterday's numbers from AdMob (Google's in-app ad network), GA4 (Google Analytics 4) and Google Ads into a JSON snapshot, a plain text file holding that day's figures. The game app's daily job reads that snapshot before it analyzes anything.

The second is an MCP server. MCP is the protocol that lets Claude use outside services such as GitHub as tools, and this PC runs the GitHub MCP server from the ghcr.io/github/github-mcp-server image. Each Claude session starts its own copy, so on the morning of November 11 seven of these containers were running. When we look at memory use, we count them too.

The part 4 kit is one runner script and two job files, and none of it needs Docker. You need Docker once you want a server that stores numbers every day, or an MCP server in a container. If you are building your first harness, don't install Docker yet. Get one scheduled run working with the kit, and come back here when you have numbers worth collecting daily.

Starting at 15:21 KST on October 11, four scheduled runs about 30 minutes apart all failed. The container was up, which is as far as the hello-world check later in this guide can tell you. Each run then ended within 1 to 64 milliseconds with "no Google credentials" (the log line is in Korean), before any collecting began.

A running container told us nothing about whether the collector could log in. After the credentials were added, four manual runs that same day succeeded, and from 09:00 KST on October 12 every scheduled run did too. If you put a server on Docker, open the log of its first scheduled run and look for a success line.

Install WSL from an administrator PowerShell

WSL, the Windows Subsystem for Linux, runs Linux inside Windows. Docker Desktop will run its engine on WSL 2.

Open the Start menu, search for PowerShell, right-click the result and choose Run as administrator. If a confirmation prompt appears, follow it. When the PowerShell window opens, paste the command below and press Enter (part 2 covers copying and pasting commands).

wsl --install

This also installs Ubuntu, a Linux distribution, by default. Restart the PC when it finishes, and follow whatever the screen asks after the restart. If WSL is already on the PC, the command prints guidance instead of installing; go straight to the version check.

wsl --version

The first line should show 2.1.5 or later. On Korean Windows it comes out in Korean, as in the screenshot further down. Only if it is older than 2.1.5, update it:

wsl --update

The one choice in the Docker Desktop installer

Download Docker Desktop Installer.exe from Docker's Windows install page. By default it installs for your user only, so you don't need administrator rights for this part. For any screen not listed below, follow the prompts.

  1. Double-click Docker Desktop Installer.exe.
  2. On the Configuration screen, select "Use WSL 2 instead of Hyper-V". Hyper-V is another virtualization feature built into Windows; this is the only option this guide asks you to set.
  3. When the wizard finishes, click Close. The installer may ask you to restart along the way.
  4. Docker Desktop doesn't start by itself after installing. Find it in the Start menu and launch it.
  5. On first launch you have to accept the Docker Subscription Service Agreement before Docker Desktop will run.

The hello-world check, as run on November 11

With Docker Desktop running, type these two lines into an ordinary PowerShell window. The official install page doesn't include them; we ran both on this PC on November 11.

docker version
docker run --rm hello-world

Plain docker version prints two long blocks, Client and Server. If both blocks show a version, the Docker client and the engine (the part that actually creates and runs containers) are both up. The screenshot uses a --format option to squeeze the two versions onto one line; both were 26.0.0 here.

docker run --rm hello-world downloads a tiny test image, runs it once, and the --rm flag deletes the finished container. When you see "Hello from Docker! This message shows that your installation appears to be working correctly.", the install is done.

"Healthy" in the table means the container's own check reports it as working. The last two rows' image and container names include a personal server name, so we covered them; the seven rows above are the per-session MCP servers.

Capping WSL memory at 3 GB with .wslconfig

You only need this step if WSL shares the PC's memory with other heavy work. On this PC, WSL exists only to run Docker Desktop, and the machine (28 GB of RAM, 16 cores) also builds Android apps. So on October 22 we added a settings file that caps WSL's memory and CPU, directly in the user folder at %USERPROFILE%\.wslconfig. Typing %USERPROFILE% into File Explorer's address bar opens that folder.

Here is this PC's file, minus one comment line that names our server; the other comments keep their original meaning. Swap is disk space used as memory when RAM runs short, and logical processors are the CPU count Windows reports.

[wsl2]
# as of Oct 22: containers use about 220 MB, plus the Docker engine and room for image builds
memory=3GB
# one simple service, so 2 logical processors are enough (as of Oct 22; this PC has 16)
processors=2
# minimum swap, so running out of memory doesn't force a kill
swap=1GB

[experimental]
# hand Linux cache back to Windows while idle
autoMemoryReclaim=dropCache

If you create it in Notepad, set "Save as type" to "All files" so the name doesn't end in .txt. WSL reads the file when it starts, so save it and restart the PC at a time when no harness job is due.

We picked 3 GB on October 22, when the containers were using about 220 MB. If you run several databases or build images often, don't copy the number. The MCP containers that appear one per session also draw from this cap.

Don't shut WSL down on a harness PC

wsl --shutdown stops everything running in WSL at once. Docker Desktop runs on WSL 2, so the command takes Docker down with it, and the data collector inside stops too. On a PC where Docker serves the harness, don't run it.

This happened here. From October 18 to the afternoon of October 22, an AI agent's reports told the operator six times to ask for wsl --shutdown. On the night of October 22 the operator ran it, and Docker went down. Two later reports still carried the same advice. A separate command stops only Ubuntu; the full story is in Leaving WSL for native Windows: a checklist for moving a Claude Code dev environment.

Today the harness guard (a script that checks each tool call just before Claude makes it and blocks dangerous commands) refuses wsl --shutdown and the command that deletes a WSL distribution, because scheduled Claude jobs can run PowerShell commands too. The other commands it blocks, and the actions a person has to approve, are in Running an AI marketer on a schedule four times a day: the permission table that leaves money, accounts and policy to a person.

Docker Desktop licensing: free for individuals and small businesses

According to Docker's docs (checked November 11), Docker Desktop is free for personal use, education, non-commercial open source, and small businesses with fewer than 250 employees and less than US$10 million in annual revenue. Commercial use in larger companies needs a paid subscription. If you plan to install it on a work PC, check those terms against your company first.

FAQ

Can I install Docker Desktop on Windows 11 Home?

Check Docker's current list of supported editions before you download the installer. The requirements we read on November 11 listed Pro, Enterprise and Education, not Home. This PC runs Enterprise, so we couldn't check Home.

What should I check first after a virtualization error?

Check that hardware virtualization is enabled in BIOS/UEFI. Docker lists it as a requirement; your PC maker's manual shows where the setting lives.

Do I need a Docker account?

No. You must accept the Docker Subscription Service Agreement on first launch, but Docker's docs (checked November 11) say signing in to a Docker account is optional.
